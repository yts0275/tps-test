## LangGraph 워크플로우 노드 흐름 상세 설명

---

### 전체 구조 개요

이 그래프는 **SoftwareEngineer**를 중앙 오케스트레이터로 두고, 코드 분석(CodeAnalyzer)과 코드 편집(Editor)을 전담 서브 에이전트에 위임하는 멀티 에이전트 구조다.

---

### 노드 목록

| 노드 | 종류 | 역할 |
|---|---|---|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 에이전트 | 작업 판단 및 라우팅 |
| `CodeAnalyzer` | 서브 에이전트 | 코드 정적 분석 |
| `Editor` | 서브 에이전트 | 코드 수정 및 테스트 |
| `swe_tool` | 도구 노드 | SoftwareEngineer 직접 사용 도구 |
| `code_analysis_tool` | 도구 노드 | CodeAnalyzer 사용 도구 |
| `code_edit_tool` | 도구 노드 | Editor 사용 편집 도구 |
| `test_tool` | 도구 노드 | Editor 사용 테스트 도구 |
| `end` | 종료점 | 워크플로우 완료 |

---

### 엣지 흐름 상세

#### 1. `start → SoftwareEngineer` (solid arrow)
- 워크플로우 진입 시 무조건 SoftwareEngineer로 이동
- 초기 태스크(요구사항, 이슈 등)를 수신하는 단계

---

#### 2. `SoftwareEngineer` — 중앙 라우터 (4방향 분기)

SoftwareEngineer는 현재 상태를 평가하고 다음 행동을 결정한다. 모든 분기는 **점선(conditional edge)** 으로 표현:

```
SoftwareEngineer
    ├── analyze_code  ──→  CodeAnalyzer   (코드 분석이 필요할 때)
    ├── edit_file     ──→  Editor         (코드 수정이 필요할 때)
    ├── (tool call)   ──→  swe_tool       (직접 도구를 쓸 때)
    └── (완료)        ──→  end            (모든 작업이 끝났을 때)
```

---

#### 3. `SoftwareEngineer →(analyze_code)→ CodeAnalyzer`

- SoftwareEngineer가 코드 이해 또는 분석이 필요하다고 판단할 때 발동
- CodeAnalyzer에게 분석 태스크 위임

**CodeAnalyzer 내부 루프:**
```
CodeAnalyzer
    ↕ continue ↕
code_analysis_tool
```
- `code_analysis_tool`을 반복 호출하며 분석 수행 (`continue` 루프)
- 분석 결과가 충분히 모이면 루프 탈출

**CodeAnalyzer 탈출 경로 (2가지):**
```
CodeAnalyzer ──(done)──→ SoftwareEngineer  (분석 결과 보고 후 복귀)
CodeAnalyzer ──(continue)──→ Editor        (분석 중 바로 편집 필요 시)
```

---

#### 4. `SoftwareEngineer →(edit_file)→ Editor`

- 코드 수정이 필요하다고 판단할 때 발동
- Editor에게 편집 태스크 위임

**Editor 내부 루프:**
```
Editor
    ↕ continue ↕
code_edit_tool   (실제 파일 편집)
test_tool        (편집 후 테스트 실행)
```
- `code_edit_tool`로 코드를 수정하고, `test_tool`로 결과 검증
- 테스트 실패 시 `continue`로 재수정 루프 반복

**Editor 탈출 경로:**
```
Editor ──(done)──→ SoftwareEngineer  (편집/테스트 완료 후 복귀)
```

---

#### 5. `SoftwareEngineer → swe_tool →(continue)→ SoftwareEngineer`

- SoftwareEngineer가 서브 에이전트에 위임하지 않고 **직접 도구를 사용**하는 경로
- `swe_tool` 실행 완료 후 `continue`로 SoftwareEngineer에게 결과 반환
- SoftwareEngineer는 결과를 받아 다시 다음 행동을 결정

---

#### 6. `SoftwareEngineer → end`

- 모든 태스크가 완료되었다고 판단할 때 워크플로우 종료
- 더 이상 분석/편집/도구 호출이 필요 없는 상태

---

### 전체 실행 시나리오 예시

```
start
  └→ SoftwareEngineer (태스크 수신)
       └→ [analyze_code] → CodeAnalyzer
               ↕ code_analysis_tool (반복)
               └→ [done] → SoftwareEngineer (분석 결과 수신)
                    └→ [edit_file] → Editor
                            ↕ code_edit_tool
                            ↕ test_tool (반복)
                            └→ [done] → SoftwareEngineer (수정 완료 수신)
                                 └→ [end] → 종료
```

---

### 설계 특징 요약

- **단일 진입/종료**: `start`와 `end`가 명확히 분리됨
- **오케스트레이터 패턴**: SoftwareEngineer가 모든 판단을 중앙에서 수행
- **도구 루프(ReAct 패턴)**: CodeAnalyzer와 Editor 모두 내부에서 `continue` 루프로 도구를 반복 호출
- **점선 엣지**: 조건부 분기(conditional edge)를 나타내며, LangGraph의 `add_conditional_edges`로 구현됨
- **서브 에이전트 완료 신호**: `done` 엣지를 통해 SoftwareEngineer에게 결과를 보고하고 제어권을 반환
