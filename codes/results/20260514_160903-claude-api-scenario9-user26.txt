이미지를 분석하여 워크플로우 노드들의 흐름을 상세히 서술합니다.

---

## LangGraph 워크플로우 노드 흐름 분석

### 노드 종류 구분

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` / `end` | Entry/Exit (타원형) | 워크플로우 시작/종료 |
| `SoftwareEngineer` | Agent Node (자주색 박스) | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent Node (자주색 박스) | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node (자주색 박스) | 코드 편집 전담 에이전트 |
| `swe_tool` | Tool Node (흰색 박스) | SWE 전용 도구 |
| `code_analysis_tool` | Tool Node (흰색 박스) | 코드 분석 도구 |
| `code_edit_tool` | Tool Node (흰색 박스) | 코드 편집 도구 |
| `test_tool` | Tool Node (흰색 박스) | 테스트 실행 도구 |

---

### 전체 흐름 상세 서술

#### 1. 진입점: `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 **SoftwareEngineer** 노드로 진입
- SoftwareEngineer는 **중앙 오케스트레이터(Supervisor)**로서 전체 작업을 판단하고 분기를 결정

---

#### 2. `SoftwareEngineer` 의 분기 로직 (4가지 경로)

```
SoftwareEngineer
  ├── analyze_code  → CodeAnalyzer
  ├── edit_file     → Editor
  ├── (swe_tool 호출) → swe_tool
  └── (작업 완료)  → end
```

- **`analyze_code`** : 코드를 분석해야 한다고 판단하면 `CodeAnalyzer` 에이전트로 위임
- **`edit_file`** : 코드를 편집해야 한다고 판단하면 `Editor` 에이전트로 위임
- **`swe_tool`** : 직접 SWE 도구를 사용해야 할 때 `swe_tool` 노드 실행
- **`end`** : 모든 작업이 완료되었다고 판단하면 워크플로우 종료

---

#### 3. `CodeAnalyzer` 서브그래프

```
CodeAnalyzer
  ├── (tool 호출)  → code_analysis_tool
  │                    └── continue → CodeAnalyzer (루프백)
  └── done         → SoftwareEngineer
```

- `CodeAnalyzer`는 코드 분석 작업을 수행하며 `code_analysis_tool`을 반복 호출할 수 있음
- 도구 실행 후 결과를 받아 **`continue`** 로 자기 자신에게 루프백 → 추가 분석 지속
- 분석이 충분히 완료되면 **`done`** 엣지로 `SoftwareEngineer`에게 결과 반환

---

#### 4. `Editor` 서브그래프

```
Editor
  ├── (tool 호출)  → code_edit_tool
  │                    └── continue → Editor (루프백)
  ├── (tool 호출)  → test_tool
  │                    └── continue → Editor (루프백)
  ├── continue     → CodeAnalyzer (교차 위임)
  └── done         → SoftwareEngineer
```

- `Editor`는 2가지 도구를 사용할 수 있음
  - **`code_edit_tool`**: 실제 코드 파일 수정 수행
  - **`test_tool`**: 편집 후 테스트 실행으로 결과 검증
- 각 도구 실행 결과를 받은 뒤 **`continue`** 로 루프백하여 추가 편집/테스트 반복
- 특이점: `Editor`에서 **`CodeAnalyzer`로 `continue` 위임**이 가능 → 편집 중 추가 분석이 필요할 때 CodeAnalyzer에게 재위임
- 편집 작업 완료 시 **`done`** 으로 `SoftwareEngineer`에 반환

---

#### 5. `swe_tool` → `SoftwareEngineer`

```
swe_tool
  └── continue → SoftwareEngineer
```

- SWE 도구 실행 후 결과를 **`continue`** 엣지로 `SoftwareEngineer`에게 반환
- SoftwareEngineer는 결과를 보고 다음 작업을 다시 판단

---

### 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer (작업 파악)
    → CodeAnalyzer (analyze_code)
      → code_analysis_tool (분석 실행)
      → CodeAnalyzer (continue, 결과 해석)
      → SoftwareEngineer (done, 분석 완료 보고)
    → Editor (edit_file)
      → code_edit_tool (파일 수정)
      → Editor (continue)
      → test_tool (테스트 실행)
      → Editor (continue, 결과 확인)
      → SoftwareEngineer (done, 편집 완료 보고)
    → end (모든 작업 완료)
```

---

### 핵심 설계 패턴 요약

| 패턴 | 설명 |
|------|------|
| **Supervisor Pattern** | `SoftwareEngineer`가 중앙에서 서브에이전트에 작업 위임 |
| **Tool Loop** | 에이전트가 도구를 호출하고 `continue`로 자신에게 루프백 → ReAct 패턴 |
| **Cross-agent delegation** | `Editor` → `CodeAnalyzer` 위임으로 에이전트 간 협업 가능 |
| **Conditional Routing** | 각 엣지 레이블(`done`, `continue`, `analyze_code` 등)로 상태 기반 분기 |
