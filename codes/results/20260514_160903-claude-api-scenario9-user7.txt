이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 설명하겠습니다.

---

## 노드 구성

### Agent 노드 (보라색 박스)
| 노드 | 역할 |
|------|------|
| **SoftwareEngineer** | 중앙 오케스트레이터. 작업을 분석하고 하위 노드로 라우팅 |
| **CodeAnalyzer** | 코드 분석 전담 에이전트 |
| **Editor** | 파일 수정 전담 에이전트 |

### Tool 노드 (연한 보라색 박스)
| 노드 | 역할 |
|------|------|
| **code_analysis_tool** | CodeAnalyzer가 호출하는 정적 분석 도구 |
| **code_edit_tool** | Editor가 호출하는 파일 편집 도구 |
| **test_tool** | Editor가 호출하는 테스트 실행 도구 |
| **swe_tool** | SoftwareEngineer가 직접 호출하는 범용 SWE 도구 |

---

## 흐름 상세 설명

### 1. 진입점
```
start → SoftwareEngineer
```
워크플로우 시작 시 즉시 **SoftwareEngineer** 노드로 진입합니다.

---

### 2. SoftwareEngineer (오케스트레이터)

중앙 라우팅 허브로, 현재 상태를 판단하여 **4가지 경로** 중 하나로 분기합니다:

| 조건/엣지 | 목적지 | 설명 |
|-----------|--------|------|
| `analyze_code` | → CodeAnalyzer | 코드 분석이 필요한 경우 |
| `edit_file` | → Editor | 파일 수정이 필요한 경우 |
| (직접 호출) | → swe_tool | 범용 SWE 작업 처리 |
| (태스크 완료) | → **end** | 최종 종료 |

---

### 3. CodeAnalyzer 서브루프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                      ↕ (dashed)
                                  code_analysis_tool
                                      ↓ continue
                                  CodeAnalyzer (self-loop)
                                      ↓ done
                              SoftwareEngineer
```

- **SoftwareEngineer → CodeAnalyzer**: `analyze_code` 엣지로 진입
- **CodeAnalyzer ↔ code_analysis_tool**: 점선(dashed) 화살표로 툴을 반복 호출
- **continue (자기 루프)**: 분석이 충분하지 않으면 CodeAnalyzer가 자기 자신으로 다시 돌아와 반복 분석
- **done**: 분석 완료 시 SoftwareEngineer로 결과 반환

---

### 4. Editor 서브루프

```
SoftwareEngineer --edit_file--> Editor
CodeAnalyzer     --continue--> Editor   ← 분석 결과를 바탕으로 편집 시작
                                  ↕ (dashed)
                    code_edit_tool / test_tool
                                  ↓ continue
                              CodeAnalyzer       ← 편집 후 재분석 필요 시
                                  ↓ done
                              SoftwareEngineer
```

- **2개의 진입 경로**:
  - SoftwareEngineer에서 `edit_file`로 직접 진입
  - CodeAnalyzer에서 `continue`로 진입 (분석 결과를 받아 편집 수행)
- **Editor ↔ code_edit_tool**: 실제 파일 수정 수행 (점선)
- **Editor ↔ test_tool**: 수정 후 테스트 실행 (점선)
- **continue → CodeAnalyzer**: 수정 후 재분석이 필요한 경우 CodeAnalyzer로 루프백
- **done → SoftwareEngineer**: 편집 완료 시 오케스트레이터에게 반환

---

### 5. swe_tool 경로

```
SoftwareEngineer → swe_tool --continue--> SoftwareEngineer
```

- SoftwareEngineer가 직접 범용 SWE 도구를 호출
- 작업 완료 후 `continue` 엣지로 SoftwareEngineer에 복귀

---

### 6. 종료

```
SoftwareEngineer → end
```

모든 하위 작업이 완료되고 SoftwareEngineer가 최종 종료 조건을 만족하면 **end** 노드로 전이하여 워크플로우를 마칩니다.

---

## 전체 흐름 요약

```
start
  └→ SoftwareEngineer (오케스트레이터)
        ├─[analyze_code]→ CodeAnalyzer ⇄ code_analysis_tool
        │                     └─[continue]→ (자기루프)
        │                     └─[done]→ SoftwareEngineer
        │
        ├─[edit_file]──→ Editor ⇄ code_edit_tool / test_tool
        │   ↑ continue        └─[continue]→ CodeAnalyzer
        │   └─────────────────└─[done]→ SoftwareEngineer
        │
        ├─────────────→ swe_tool
        │                └─[continue]→ SoftwareEngineer
        │
        └─────────────→ end
```

**핵심 설계 패턴**: SoftwareEngineer가 중앙 오케스트레이터로 모든 결과를 수렴받고, CodeAnalyzer ↔ Editor 사이의 `continue` 엣지가 분석-수정의 반복 사이클을 구성하는 **ReAct 패턴** 구조입니다.
