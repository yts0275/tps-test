## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 멀티 에이전트 시스템**으로, 1개의 오케스트레이터 에이전트와 2개의 전문 에이전트, 그리고 3개의 도구 노드로 구성되어 있다.

---

### 노드 목록

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 에이전트 | 최상위 오케스트레이터 |
| `CodeAnalyzer` | 에이전트 | 코드 분석 전담 |
| `Editor` | 에이전트 | 파일 편집 및 테스트 전담 |
| `swe_tool` | 도구 | SoftwareEngineer 직속 도구 |
| `code_analysis_tool` | 도구 | CodeAnalyzer 전용 분석 도구 |
| `code_edit_tool` | 도구 | Editor 전용 편집 도구 |
| `test_tool` | 도구 | Editor 전용 테스트 도구 |
| `end` | 종료점 | 워크플로우 완료 |

---

### 흐름 상세

#### 1. 진입 단계

```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입한다.

---

#### 2. SoftwareEngineer (오케스트레이터)

`SoftwareEngineer`는 작업의 성격을 판단하여 **4가지 경로**로 분기한다:

| 엣지 레이블 | 목적지 | 의미 |
|---|---|---|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | `Editor` | 파일 편집이 필요한 경우 |
| *(direct)* | `swe_tool` | 즉각적인 도구 호출이 필요한 경우 |
| `continue` | `end` | 모든 작업이 완료된 경우 |

- `swe_tool` 사용 후에는 다시 `SoftwareEngineer`로 복귀하여 다음 작업을 결정한다 (점선으로 표시된 루프).

---

#### 3. CodeAnalyzer (코드 분석 에이전트)

`SoftwareEngineer`로부터 `analyze_code` 신호를 받아 실행된다.

**내부 루프:**
```
CodeAnalyzer ⇄ code_analysis_tool  (continue 레이블)
```
- 분석이 완료될 때까지 `code_analysis_tool`을 반복 호출할 수 있다.
- `continue` 엣지로 도구 결과를 받아 자신의 상태를 업데이트하고 추가 분석 여부를 결정한다.

**이탈 경로:**

| 엣지 레이블 | 목적지 | 의미 |
|---|---|---|
| `done` | `SoftwareEngineer` | 분석 완료, 결과를 오케스트레이터에게 반환 |
| `continue` | `Editor` | 분석 결과를 바탕으로 즉시 편집 단계로 전달 |

> `CodeAnalyzer`는 분석 결과를 오케스트레이터를 거치지 않고 `Editor`에게 **직접 전달**하는 단축 경로를 가진다.

---

#### 4. Editor (편집 에이전트)

`SoftwareEngineer`로부터 `edit_file` 신호 또는 `CodeAnalyzer`로부터 `continue` 신호를 받아 실행된다.

**내부 루프:**
```
Editor ⇄ code_edit_tool  (continue 레이블)
Editor ⇄ test_tool        (continue 레이블)
```
- 파일 편집 작업: `code_edit_tool`을 반복 호출하여 점진적으로 파일을 수정한다.
- 테스트 실행: `test_tool`을 호출하여 수정한 코드의 검증을 수행한다.
- 편집→테스트→재편집 사이클을 `continue` 루프로 반복할 수 있다.

**이탈 경로:**

| 엣지 레이블 | 목적지 | 의미 |
|---|---|---|
| `done` | `SoftwareEngineer` | 편집 및 테스트 완료, 오케스트레이터에게 반환 |

---

### 전체 흐름 요약 (시나리오별)

**시나리오 A: 분석 후 편집**
```
start → SoftwareEngineer
  → (analyze_code) → CodeAnalyzer
    ↔ code_analysis_tool (루프)
  → (continue) → Editor
    ↔ code_edit_tool / test_tool (루프)
  → (done) → SoftwareEngineer
  → (continue) → end
```

**시나리오 B: 직접 편집**
```
start → SoftwareEngineer
  → (edit_file) → Editor
    ↔ code_edit_tool / test_tool (루프)
  → (done) → SoftwareEngineer
  → (continue) → end
```

**시나리오 C: 분석 후 오케스트레이터 복귀**
```
start → SoftwareEngineer
  → (analyze_code) → CodeAnalyzer
    ↔ code_analysis_tool (루프)
  → (done) → SoftwareEngineer
  → (edit_file) → Editor
  → ...
```

---

### 핵심 설계 패턴

1. **오케스트레이터-서브에이전트 패턴**: `SoftwareEngineer`가 모든 의사결정을 담당하고 전문 에이전트에게 작업을 위임한다.
2. **도구 루프 패턴**: 각 에이전트는 자신의 도구를 `continue` 루프로 반복 호출하여 복잡한 작업을 단계적으로 처리한다.
3. **단축 경로**: `CodeAnalyzer → Editor` 직접 연결로 오케스트레이터 병목을 우회할 수 있다.
4. **점선(dashed) 엣지**: 도구 호출 루프를 나타내며, 실선 엣지는 에이전트 간 상태 전환을 나타낸다.
