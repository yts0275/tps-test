## LangGraph Workflow 노드 흐름 상세 분석

### 전체 구조 개요

이 그래프는 **SoftwareEngineer**를 중심 오케스트레이터로 하는 계층형 멀티에이전트 워크플로우다. 실선은 무조건적(unconditional) 엣지, 점선은 조건부(conditional) 엣지를 나타낸다.

---

### 노드 구성

| 노드 | 역할 | 타입 |
|------|------|------|
| `start` | 워크플로우 진입점 | 시스템 노드 |
| `SoftwareEngineer` | 중앙 오케스트레이터 (라우팅 결정) | 에이전트 노드 |
| `CodeAnalyzer` | 코드 분석 전담 서브에이전트 | 에이전트 노드 |
| `Editor` | 파일 편집/테스트 전담 서브에이전트 | 에이전트 노드 |
| `swe_tool` | SoftwareEngineer 직접 도구 | 도구 노드 |
| `code_analysis_tool` | 코드 분석 도구 | 도구 노드 |
| `code_edit_tool` | 코드 편집 도구 | 도구 노드 |
| `test_tool` | 테스트 실행 도구 | 도구 노드 |
| `end` | 워크플로우 종료점 | 시스템 노드 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름
```
start → SoftwareEngineer (무조건 실행)
```
워크플로우가 시작되면 항상 `SoftwareEngineer`로 진입한다.

---

#### 2. SoftwareEngineer의 라우팅 (조건부 분기)

`SoftwareEngineer`는 현재 상태를 판단하여 4가지 경로 중 하나를 선택한다:

| 조건 | 이동 대상 | 의미 |
|------|-----------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요하다고 판단 |
| `edit_file` | `Editor` | 파일 편집이 필요하다고 판단 |
| `continue` | `swe_tool` | SoftwareEngineer 자신의 도구 직접 사용 |
| (완료 조건) | `end` | 작업이 모두 완료됨 |

---

#### 3. CodeAnalyzer 서브그래프 (내부 루프)

```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer
        ↑                                    |
        |                             [도구 필요시]
      [done]                                 ↓
        |                          code_analysis_tool
        └─────────────────── [continue] ─────┘
```

- `CodeAnalyzer`가 분석 중 도구 호출이 필요하면 → `code_analysis_tool` 실행
- `code_analysis_tool` 완료 후 `continue` 엣지로 `CodeAnalyzer`로 복귀 (내부 루프)
- `CodeAnalyzer`가 분석을 완료하면 `done` 엣지로 `SoftwareEngineer`에 결과 반환

---

#### 4. Editor 서브그래프 (내부 루프)

```
SoftwareEngineer --[edit_file]--> Editor
        ↑                            |          |
        |                    [편집 필요시]  [테스트 필요시]
      [done]                         ↓          ↓
        |                   code_edit_tool   test_tool
        |                         |              |
        └────────── [continue] ───┴──────────────┘
```

- `Editor`는 두 가지 도구를 호출할 수 있다:
  - `code_edit_tool` : 실제 파일 수정
  - `test_tool` : 수정 결과 테스트/검증
- 두 도구 모두 완료 후 `continue` 엣지로 `Editor`로 복귀 (내부 루프)
- 편집 작업이 완료되면 `done` 엣지로 `SoftwareEngineer`에 결과 반환

---

#### 5. swe_tool 흐름

```
SoftwareEngineer --[continue]--> swe_tool --> SoftwareEngineer
```

- `SoftwareEngineer`가 직접 처리해야 하는 작업(예: 검색, 조회 등)은 `swe_tool`을 통해 처리
- 완료 후 다시 `SoftwareEngineer`로 복귀하여 다음 라우팅 결정

---

### 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer (태스크 파악)
    → analyze_code → CodeAnalyzer
        → code_analysis_tool (분석 도구 실행)
        → CodeAnalyzer (결과 처리)
        → done → SoftwareEngineer (분석 결과 수신)
    → edit_file → Editor
        → code_edit_tool (코드 수정)
        → Editor (수정 결과 확인)
        → test_tool (테스트 실행)
        → Editor (테스트 결과 확인)
        → done → SoftwareEngineer (편집 완료 수신)
    → (모든 작업 완료 판단)
  → end
```

---

### 핵심 설계 패턴

1. **계층형 위임(Hierarchical Delegation)**: `SoftwareEngineer`가 작업 종류에 따라 전문 서브에이전트(`CodeAnalyzer`, `Editor`)에 위임
2. **내부 도구 루프(Internal Tool Loop)**: 각 서브에이전트는 도구 실행 후 자신에게 `continue`로 복귀하는 반복 루프를 가짐
3. **ReAct 패턴**: 각 에이전트가 Reason(판단) → Act(도구 호출) → Observe(결과 확인)를 반복
4. **중앙 집중식 종료 결정**: 오직 `SoftwareEngineer`만이 `end`로 가는 경로를 가지므로, 종료 여부 판단을 항상 오케스트레이터가 담당
