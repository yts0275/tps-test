## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 그래프는 **SoftwareEngineer**를 중앙 오케스트레이터로 하는 멀티에이전트 LangGraph 워크플로우다. 실선은 시작/종료 전환, 점선은 조건부 엣지(conditional edge) 혹은 툴 호출을 나타낸다.

---

### 노드 목록

| 노드 | 역할 |
|---|---|
| `SoftwareEngineer` | 메인 오케스트레이터 — 작업을 분석하고 하위 에이전트에 위임 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 |
| `Editor` | 코드 편집 및 테스트 전담 에이전트 |
| `swe_tool` | SoftwareEngineer가 직접 호출하는 툴 노드 |
| `code_analysis_tool` | CodeAnalyzer가 사용하는 툴 |
| `code_edit_tool` | Editor가 사용하는 편집 툴 |
| `test_tool` | Editor가 사용하는 테스트 툴 |

---

### 노드별 상세 흐름

#### 1. 진입 (`start` → `SoftwareEngineer`)
- 그래프 실행이 시작되면 **SoftwareEngineer** 노드가 첫 번째로 활성화된다.
- SoftwareEngineer는 사용자 요청을 받아 다음 4가지 경로 중 하나를 선택한다.

---

#### 2. `SoftwareEngineer` — 분기 결정 (4가지 엣지)

```
SoftwareEngineer
  ├─ analyze_code ──▶ CodeAnalyzer
  ├─ edit_file    ──▶ Editor
  ├─ (direct)     ──▶ swe_tool
  └─ (done)       ──▶ end
```

- **`analyze_code`**: 코드 구조나 버그를 파악해야 할 때 → `CodeAnalyzer`로 위임
- **`edit_file`**: 코드 수정이 필요할 때 → `Editor`로 위임
- **direct tool call**: SoftwareEngineer가 직접 `swe_tool`을 호출
- **종료 조건 충족 시**: `end`로 전환하여 그래프 종료

---

#### 3. `CodeAnalyzer` 서브그래프

```
CodeAnalyzer ◀──▶ code_analysis_tool  (반복 루프)
     │
     ├─ done     ──▶ SoftwareEngineer  (분석 완료, 결과 반환)
     └─ continue ──▶ Editor            (분석 후 편집 필요 시)
```

- `CodeAnalyzer`는 **`code_analysis_tool`**을 반복적으로 호출하며 코드를 분석한다.
- 분석 완료 시:
  - `done` → **SoftwareEngineer**로 결과를 반환
  - `continue` → 분석 결과를 바탕으로 바로 **Editor**에게 편집을 요청

---

#### 4. `Editor` 서브그래프

```
Editor ◀──▶ code_edit_tool  (반복 루프)
Editor ◀──▶ test_tool       (반복 루프)
  │
  ├─ done     ──▶ SoftwareEngineer  (편집 완료, 결과 반환)
  └─ continue ──▶ CodeAnalyzer      (편집 후 재분석 필요 시)
```

- `Editor`는 **`code_edit_tool`**로 코드를 수정하고, **`test_tool`**로 테스트를 실행한다.
- 편집 완료 시:
  - `done` → **SoftwareEngineer**로 결과를 반환
  - `continue` → 편집 결과 검증을 위해 **CodeAnalyzer**에게 재분석 요청

---

#### 5. `swe_tool` → `SoftwareEngineer`

```
swe_tool ──▶ (continue) ──▶ SoftwareEngineer
```

- SoftwareEngineer가 직접 호출한 `swe_tool`의 실행이 끝나면 `continue` 엣지를 통해 다시 **SoftwareEngineer**로 제어가 돌아온다.
- SoftwareEngineer는 결과를 받아 다음 액션을 결정한다.

---

### 전체 흐름 시나리오 예시

```
start
  └▶ SoftwareEngineer (요청 파악)
       └▶ analyze_code ──▶ CodeAnalyzer
                               └▶ code_analysis_tool (반복)
                               └▶ continue ──▶ Editor
                                                 └▶ code_edit_tool
                                                 └▶ test_tool (반복)
                                                 └▶ done ──▶ SoftwareEngineer
                                                                 └▶ end
```

---

### 핵심 설계 패턴

| 패턴 | 설명 |
|---|---|
| **Orchestrator-Subagent** | SoftwareEngineer가 전체 작업을 조율하고 전문 에이전트에게 위임 |
| **Tool-calling Loop** | 각 에이전트가 툴을 반복 호출하며 결과를 누적 |
| **Bidirectional Handoff** | CodeAnalyzer ↔ Editor 간 `continue` 엣지로 상호 위임 가능 |
| **Conditional Routing** | `done` / `continue` 조건에 따라 흐름이 동적으로 결정됨 |
