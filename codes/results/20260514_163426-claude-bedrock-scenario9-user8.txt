---

## LangGraph 워크플로우 상세 분석

### 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node | 코드 편집 전담 에이전트 |
| `swe_tool` | Tool Node | SoftwareEngineer 전용 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |
| `end` | 종료점 (oval, filled) | 워크플로우 종료 |

---

### 전체 흐름

```
start → SoftwareEngineer
```

`start` → `SoftwareEngineer`가 워크플로우의 단일 진입점이다.

---

### SoftwareEngineer (오케스트레이터)

**4가지 조건부 분기**가 존재한다:

```
SoftwareEngineer ──analyze_code──→ CodeAnalyzer
SoftwareEngineer ──edit_file────→ Editor
SoftwareEngineer ──────────────→ swe_tool
SoftwareEngineer ──────────────→ end
```

- **`analyze_code`**: 코드 분석이 필요하다고 판단하면 `CodeAnalyzer`에 위임
- **`edit_file`**: 파일 수정이 필요하다고 판단하면 `Editor`에 위임
- **`swe_tool`**: SoftwareEngineer가 직접 처리할 수 있는 도구 호출
- **`end`**: 모든 작업이 완료되었다고 판단하면 종료

---

### CodeAnalyzer 서브루프

```
CodeAnalyzer ←──────────────────────────────┐
     │                                        │
     ├──→ code_analysis_tool ──→ CodeAnalyzer (continue: 추가 분석 반복)
     │
     └──done──→ SoftwareEngineer
```

1. `SoftwareEngineer`로부터 `analyze_code` 엣지를 통해 진입
2. 내부에서 `code_analysis_tool`을 반복 호출하며 분석 수행 (`continue` 루프)
3. 분석 완료 시 `done` 엣지로 `SoftwareEngineer`에 결과 반환

---

### Editor 서브루프

```
Editor ←────────────────────────────────────────┐
  │                                               │
  ├──→ code_edit_tool ──→ Editor (continue: 추가 편집 반복)
  ├──→ test_tool      ──→ Editor (continue: 테스트 후 반복)
  │
  └──done──→ SoftwareEngineer
```

1. `SoftwareEngineer`로부터 `edit_file` 엣지를 통해 진입
2. `code_edit_tool`로 코드 편집, `test_tool`로 테스트 실행을 반복 (`continue` 루프)
3. 편집 및 테스트 완료 시 `done` 엣지로 `SoftwareEngineer`에 결과 반환

---

### swe_tool 흐름

```
SoftwareEngineer ──→ swe_tool ──continue──→ SoftwareEngineer
```

`swe_tool`은 서브에이전트가 아닌 **단순 도구 호출**로, 실행 후 `continue` 엣지를 통해 즉시 `SoftwareEngineer`로 제어권이 돌아온다.

---

### 전체 흐름 요약

```
start
  └→ SoftwareEngineer (판단 루프)
        ├─analyze_code→ CodeAnalyzer
        │                  ├─[continue]→ code_analysis_tool → CodeAnalyzer
        │                  └─[done]────→ SoftwareEngineer
        │
        ├─edit_file──→ Editor
        │                  ├─[continue]→ code_edit_tool → Editor
        │                  ├─[continue]→ test_tool      → Editor
        │                  └─[done]────→ SoftwareEngineer
        │
        ├──────────→ swe_tool
        │                  └─[continue]→ SoftwareEngineer
        │
        └──────────→ end
```

---

### 핵심 설계 패턴

1. **오케스트레이터-서브에이전트 패턴**: `SoftwareEngineer`가 작업의 성격에 따라 전문 에이전트(`CodeAnalyzer`, `Editor`)에 위임
2. **ReAct 루프 (continue)**: 각 서브에이전트는 도구를 반복 호출하며 작업을 완수할 때까지 자체 루프를 수행
3. **도구 계층 분리**: SoftwareEngineer 전용 도구(`swe_tool`)와 서브에이전트 전용 도구가 명확히 구분됨
4. **단일 종료점**: 모든 경로는 최종적으로 `SoftwareEngineer`를 거쳐 `end`로 수렴
