이미지에서 보이는 LangGraph 워크플로우를 상세히 분석한다.

---

## 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 멀티 에이전트 시스템**으로, `SoftwareEngineer`가 오케스트레이터(감독자) 역할을 하며 `CodeAnalyzer`와 `Editor` 두 서브 에이전트를 조율한다.

---

## 노드 구성

### 제어 노드 (Agent Nodes)
| 노드 | 역할 |
|------|------|
| `SoftwareEngineer` | 최상위 오케스트레이터. 작업을 분석해 서브 에이전트에 위임 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 |
| `Editor` | 파일 편집 및 테스트 전담 에이전트 |

### 도구 노드 (Tool Nodes)
| 노드 | 소유자 |
|------|--------|
| `swe_tool` | `SoftwareEngineer` 전용 도구 |
| `code_analysis_tool` | `CodeAnalyzer` 전용 도구 |
| `code_edit_tool` | `CodeAnalyzer` / `Editor` 공용 도구 |
| `test_tool` | `Editor` 전용 도구 |

---

## 흐름 상세 서술

### 1. 진입점: `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 **고정된 solid 엣지**로 `SoftwareEngineer`에게 초기 요청이 전달된다.

---

### 2. `SoftwareEngineer` — 오케스트레이터의 조건부 분기

`SoftwareEngineer`는 요청을 받은 후 **4가지 조건부 엣지(dashed)** 중 하나를 선택한다:

| 엣지 레이블 | 목적지 | 의미 |
|------------|--------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요한 경우 위임 |
| `edit_file` | `Editor` | 파일 수정이 필요한 경우 위임 |
| _(tool call)_ | `swe_tool` | 직접 도구 사용이 필요한 경우 |
| `done` | `end` | 모든 작업 완료 시 종료 |

---

### 3. `CodeAnalyzer` 서브 에이전트 흐름

`CodeAnalyzer`는 `SoftwareEngineer`로부터 `analyze_code` 명령을 받아 동작하며, **3가지 분기**를 가진다:

```
CodeAnalyzer
  ├─→ code_analysis_tool  (코드 읽기/검색 도구 호출)
  │     └─→ CodeAnalyzer  (도구 결과 반환 후 계속 분석)
  ├─→ code_edit_tool      (분석 중 간단한 수정 필요 시)
  │     └─→ CodeAnalyzer  (결과 반환)
  ├─→ SoftwareEngineer    (레이블: "done" — 분석 완료, 결과 보고)
  └─→ Editor              (레이블: "continue" — 수정 작업으로 핸드오프)
```

- `code_analysis_tool`: AST 파싱, 심볼 검색, 의존성 분석 등 읽기 전용 분석 수행
- `done` → `SoftwareEngineer`: 분석 결과를 상위에 보고하고 제어권 반환
- `continue` → `Editor`: 분석 후 수정이 필요하다고 판단하면 직접 `Editor`로 위임 (SoftwareEngineer를 거치지 않고)

---

### 4. `Editor` 서브 에이전트 흐름

`Editor`는 `SoftwareEngineer`의 `edit_file` 명령 또는 `CodeAnalyzer`의 `continue`를 받아 동작하며, **4가지 분기**를 가진다:

```
Editor
  ├─→ code_edit_tool   (실제 파일 수정 도구 호출)
  │     └─→ Editor     (수정 결과 반환 후 계속)
  ├─→ test_tool        (수정 후 테스트 실행)
  │     └─→ Editor     (테스트 결과 반환 후 계속)
  ├─→ SoftwareEngineer (레이블: "done" — 편집 완료, 결과 보고)
  └─→ CodeAnalyzer     (레이블: "continue" — 수정 후 재분석 필요 시 핸드오프)
```

- `code_edit_tool`: 실제 파일 쓰기/패치 수행
- `test_tool`: 수정된 코드에 대한 단위 테스트/통합 테스트 실행
- `done` → `SoftwareEngineer`: 편집 및 테스트 완료 후 상위에 보고
- `continue` → `CodeAnalyzer`: 수정 후 결과가 올바른지 재분석이 필요한 경우 루프백

---

### 5. `swe_tool` — SoftwareEngineer 전용 도구

```
SoftwareEngineer → swe_tool → SoftwareEngineer (레이블: "continue")
```

`SoftwareEngineer`가 서브 에이전트 위임 없이 직접 처리할 수 있는 작업(예: 계획 수립, 검색, 요약 등)에 사용되며, 완료 후 `continue`로 다시 `SoftwareEngineer`에게 제어가 돌아온다.

---

### 6. 종료: `SoftwareEngineer` → `end`

모든 서브 에이전트의 작업이 완료되고 `SoftwareEngineer`가 최종 결과를 취합한 후, `done` 엣지를 통해 `end` 노드(filled circle)로 워크플로우가 종료된다.

---

## 핵심 패턴 요약

```
start
  └─→ SoftwareEngineer ──(analyze_code)──→ CodeAnalyzer
            ↑                                    │ (done)
            │                                    ↓
            ├──────────────────────────── SoftwareEngineer
            │                                    │
            │                              (edit_file)
            │                                    ↓
            └──────(done)────────────── Editor
                                              │ (done)
                                              ↓
                                        SoftwareEngineer
                                              │
                                           (done)
                                              ↓
                                            end
```

**주목할 설계 포인트:**
- `CodeAnalyzer` ↔ `Editor` 간 **직접 핸드오프**(`continue`)가 가능해, `SoftwareEngineer`를 거치지 않는 효율적인 분석-수정 루프가 형성된다.
- 모든 도구 노드는 **호출자 에이전트로만 결과를 반환**하는 구조라 역할이 명확히 분리된다.
- `SoftwareEngineer`는 **항상 최종 게이트키퍼**로서, `end`로의 전환 권한을 독점한다.
