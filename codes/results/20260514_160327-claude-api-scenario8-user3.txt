## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 워크플로우는 **SoftwareEngineer를 중심 오케스트레이터**로 하는 멀티 에이전트 시스템이며, 코드 분석 → 편집 → 테스트 사이클을 반복 수행한다.

---

### 노드 구성

| 노드 | 유형 | 역할 |
|---|---|---|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 | 작업 라우팅 및 의사결정 |
| `CodeAnalyzer` | 에이전트 | 코드 분석 전담 |
| `Editor` | 에이전트 | 코드 편집 및 테스트 전담 |
| `swe_tool` | 도구 | SWE 범용 도구 실행 |
| `code_analysis_tool` | 도구 | 정적 분석 도구 |
| `code_edit_tool` | 도구 | 파일 편집 도구 |
| `test_tool` | 도구 | 테스트 실행 도구 |
| `end` | 종료점 | 워크플로우 종료 |

---

### 흐름 상세 설명

#### 1. 진입 (`start` → `SoftwareEngineer`)
워크플로우가 시작되면 **단일 solid 엣지**로 `SoftwareEngineer` 노드에 도달한다. 이 노드가 전체 작업의 허브 역할을 한다.

---

#### 2. `SoftwareEngineer` — 의사결정 분기

`SoftwareEngineer`는 현재 상태를 평가하여 **4가지 경로** 중 하나를 선택한다 (모두 dashed 엣지, 즉 조건부 라우팅):

```
SoftwareEngineer
  ├─[analyze_code]──▶ CodeAnalyzer   # 코드 분석이 필요한 경우
  ├─[edit_file]─────▶ Editor         # 파일 수정이 필요한 경우
  ├──────────────────▶ swe_tool      # 범용 도구 사용이 필요한 경우
  └──────────────────▶ end           # 작업 완료 판단 시
```

---

#### 3. `CodeAnalyzer` 서브루프

`CodeAnalyzer`는 자체적으로 **도구 호출 루프**를 가진다:

```
CodeAnalyzer
  ├─[continue]──▶ CodeAnalyzer         # 분석 미완료 → 자기 자신으로 재진입 (self-loop)
  ├─────────────▶ code_analysis_tool   # 정적 분석 도구 호출
  │                     │
  │                     └──────────────▶ CodeAnalyzer  (도구 결과 반환 후 재처리)
  └─[done]──────▶ SoftwareEngineer     # 분석 완료 → 오케스트레이터에 결과 반환
```

- `continue`: 분석 결과가 불충분하거나 추가 분석이 필요할 때 루프 유지
- `code_analysis_tool` 호출 후 결과를 받아 다시 `CodeAnalyzer`가 처리
- `done`: 분석이 충분히 완료되면 `SoftwareEngineer`로 결과를 넘김

---

#### 4. `Editor` 서브루프

`Editor`는 **두 가지 도구**를 활용하는 더 복잡한 루프를 가진다:

```
Editor
  ├─[continue]──▶ Editor              # 편집/테스트 미완료 → 자기 자신으로 재진입 (self-loop)
  ├─────────────▶ code_edit_tool      # 파일 직접 편집 도구 호출
  │                     │
  │                     └─────────────▶ Editor  (편집 결과 반환 후 재처리)
  ├─────────────▶ test_tool           # 테스트 실행 도구 호출
  │                     │
  │                     └─────────────▶ Editor  (테스트 결과 반환 후 재처리)
  └─[done]──────▶ SoftwareEngineer    # 편집+검증 완료 → 오케스트레이터에 결과 반환
```

- `code_edit_tool`: 실제 파일 수정 수행 후 `Editor`로 결과 반환
- `test_tool`: 수정된 코드에 대한 테스트 실행 후 `Editor`로 결과 반환
- 테스트 실패 시 → `continue`로 재진입하여 다시 `code_edit_tool` 호출 가능 (수정-테스트 반복 사이클)
- `done`: 편집 및 테스트 통과 시 `SoftwareEngineer`에 반환

---

#### 5. `swe_tool` — 단방향 도구 실행

```
SoftwareEngineer ──▶ swe_tool ──[continue]──▶ SoftwareEngineer
```

범용 SWE 도구를 실행하고, 결과를 `continue` 레이블로 바로 `SoftwareEngineer`에 반환한다. 내부 루프 없이 단순 실행-반환 구조다.

---

#### 6. 종료 (`SoftwareEngineer` → `end`)

`SoftwareEngineer`가 모든 하위 작업이 완료됐다고 판단하면 `end` 노드로 라우팅하여 워크플로우를 종료한다.

---

### 전체 실행 흐름 요약

```
start
  └─▶ SoftwareEngineer
        ├─(분석 필요)──▶ CodeAnalyzer ⟲ code_analysis_tool ──[done]──▶ SoftwareEngineer
        ├─(편집 필요)──▶ Editor ⟲ code_edit_tool / test_tool ──[done]──▶ SoftwareEngineer
        ├─(도구 필요)──▶ swe_tool ──[continue]──▶ SoftwareEngineer
        └─(완료)───────▶ end
```

핵심 설계 패턴: **ReAct 루프** — 각 에이전트가 Think → Act(Tool) → Observe → Think 사이클을 `continue` self-loop로 구현하고, 완료 시 상위 오케스트레이터에 제어권을 반환하는 계층적 멀티에이전트 구조다.
