이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 서술하겠습니다.

---

## LangGraph 워크플로우 상세 분석

### 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | 에이전트 | 중앙 오케스트레이터 |
| `CodeAnalyzer` | 에이전트 | 코드 분석 전담 |
| `Editor` | 에이전트 | 파일 편집 전담 |
| `swe_tool` | 도구 노드 | SWE 범용 도구 |
| `code_analysis_tool` | 도구 노드 | 코드 분석 도구 |
| `code_edit_tool` | 도구 노드 | 파일 편집 도구 |
| `test_tool` | 도구 노드 | 테스트 실행 도구 |
| `end` | 종료점 (oval) | 워크플로우 종료 |

---

### 엣지 유형

- **실선 화살표**: 확정적 전환 (deterministic transition)
- **점선 화살표**: 조건부 전환 / 도구 호출 반환 (conditional edge / tool return)

---

### 흐름 상세

#### 1. 진입 — `start → SoftwareEngineer`
워크플로우는 `start`에서 시작하여 무조건적으로 `SoftwareEngineer` 노드로 진입한다.

---

#### 2. `SoftwareEngineer` — 중앙 오케스트레이터 (라우팅 허브)

`SoftwareEngineer`는 현재 태스크 상태를 평가하여 **4가지 경로** 중 하나를 선택한다:

| 조건 | 레이블 | 다음 노드 |
|------|--------|-----------|
| 코드를 분석해야 할 때 | `analyze_code` | `CodeAnalyzer` |
| 파일을 수정해야 할 때 | `edit_file` | `Editor` |
| SWE 도구 직접 사용 시 | (없음) | `swe_tool` |
| 태스크 완료 시 | `continue` | `end` |

---

#### 3. `CodeAnalyzer` 서브그래프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                        ↕ (점선)
                                   code_analysis_tool
                                        |
                                    continue (복귀)
CodeAnalyzer --done--> SoftwareEngineer
```

- `SoftwareEngineer`가 `analyze_code` 조건으로 `CodeAnalyzer`를 호출한다.
- `CodeAnalyzer`는 내부 루프에서 `code_analysis_tool`을 점선(도구 호출)으로 반복 호출할 수 있다.
- `code_analysis_tool`은 결과를 `continue` 레이블로 `CodeAnalyzer`에 반환한다.
- `CodeAnalyzer`는 분석이 충분하면 `done` 레이블로 `SoftwareEngineer`에 제어권을 반환한다.
- `CodeAnalyzer`에서 `Editor`로의 점선(`continue`) 경로도 존재한다 — 분석 결과를 Editor에 직접 전달하는 핸드오프 경로다.

---

#### 4. `Editor` 서브그래프

```
SoftwareEngineer --edit_file--> Editor
                                    ↕ (점선)
                           code_edit_tool / test_tool
                                    |
                                continue (복귀)
Editor --done--> SoftwareEngineer
```

- `SoftwareEngineer`가 `edit_file` 조건으로 `Editor`를 호출한다.
- `Editor`는 두 가지 도구를 사용할 수 있다:
  - `code_edit_tool`: 실제 파일 수정 수행
  - `test_tool`: 수정 후 테스트 실행 및 검증
- 각 도구는 `continue`로 `Editor`에 결과를 반환한다.
- `Editor`는 편집과 테스트 루프를 반복하다가 완료 시 `done`으로 `SoftwareEngineer`에 반환한다.
- `CodeAnalyzer`에서 `Editor`로의 점선 경로도 수신할 수 있다.

---

#### 5. `swe_tool` 경로

```
SoftwareEngineer --> swe_tool --continue--> SoftwareEngineer
```

- `SoftwareEngineer`가 `CodeAnalyzer`나 `Editor`를 거치지 않고 직접 도구를 사용하는 경로다.
- 실행 완료 후 `continue`로 `SoftwareEngineer`에 제어권을 돌려준다.

---

#### 6. 종료 — `SoftwareEngineer --continue--> end`

- `SoftwareEngineer`가 태스크가 완전히 해결되었다고 판단하면 `continue` 레이블로 `end` 노드로 전환하여 워크플로우를 종료한다.

---

### 전체 실행 흐름 요약

```
start
  └─► SoftwareEngineer ◄────────────────────────────────┐
            │                                            │
      ┌─────┼──────────────┬──────────┐                  │
      ▼     ▼              ▼          ▼                  │
  CodeAnalyzer          Editor     swe_tool ─continue──►┘
      │  ↕tool               │  ↕tool,test               
      │  done                │  done                     
      └──────────────────────┘                          
                  (모두 SoftwareEngineer로 복귀)
                                        │
                                    continue
                                        ▼
                                       end
```

이 구조는 **ReAct 패턴의 멀티에이전트 오케스트레이션**으로, `SoftwareEngineer`가 전략적 판단을 담당하고 `CodeAnalyzer`와 `Editor`가 각자 도메인 특화 도구를 활용하는 계층적 협업 구조다.
