## LangGraph 워크플로우 노드 흐름 상세 분석

---

### 노드 구성

| 노드 | 종류 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 노드 | 중앙 의사결정 에이전트 |
| `CodeAnalyzer` | 서브에이전트 노드 | 코드 분석 전담 |
| `Editor` | 서브에이전트 노드 | 코드 편집/테스트 전담 |
| `swe_tool` | 도구 노드 | 범용 SWE 도구 |
| `code_analysis_tool` | 도구 노드 | 코드 분석 실행 |
| `code_edit_tool` | 도구 노드 | 코드 수정 실행 |
| `test_tool` | 도구 노드 | 테스트 실행 |
| `end` | 종료점 (filled oval) | 워크플로우 종료 |

---

### 전체 흐름

```
start
  │
  ▼
SoftwareEngineer  ──────────────────────────────► end
  │  ▲  ▲  ▲
  │  │  │  └─── (done) ◄── Editor
  │  │  └─────── (done) ◄── CodeAnalyzer
  │  └────────── (continue) ◄── swe_tool
  │
  ├─── [analyze_code] ──► CodeAnalyzer
  │                           │  ▲
  │                           │  │ (continue)
  │                           ▼  │
  │                       code_analysis_tool
  │
  ├─── [edit_file] ──► Editor
  │                       │  ▲  ▲
  │                       │  │  │ (continue)
  │                       ▼  │  │
  │               code_edit_tool  test_tool
  │
  └─── [swe_tool] ──► swe_tool
                          │
                          └─── (continue) ──► SoftwareEngineer
```

---

### 노드별 상세 흐름

#### 1. `start` → `SoftwareEngineer`
- 워크플로우의 진입점
- 초기 태스크(요구사항, 이슈 등)가 `SoftwareEngineer`에게 전달됨

#### 2. `SoftwareEngineer` (중앙 오케스트레이터)
조건부 엣지(conditional edge)로 다음 4가지 경로 중 하나를 선택:

| 조건 | 전이 |
|------|------|
| 코드 분석 필요 | `analyze_code` → `CodeAnalyzer` |
| 파일 편집 필요 | `edit_file` → `Editor` |
| 범용 도구 필요 | → `swe_tool` |
| 작업 완료 | → `end` |

#### 3. `CodeAnalyzer` 루프
```
SoftwareEngineer
    │ (analyze_code)
    ▼
CodeAnalyzer ──────────► code_analysis_tool
    ▲                          │
    └──────── (continue) ───────┘
    │
    └── (done) ──► SoftwareEngineer
```
- `CodeAnalyzer`는 `code_analysis_tool`을 반복 호출 가능 (`continue` 루프)
- 분석이 충분히 완료되면 `done` 신호로 `SoftwareEngineer`에 결과 반환

#### 4. `Editor` 루프
```
SoftwareEngineer
    │ (edit_file)
    ▼
Editor ──────► code_edit_tool ──┐
  │  ▲                          │ (continue)
  │  └──────────────────────────┘
  │
  ├──────► test_tool ──────────┐
  ▲                            │ (continue)
  └────────────────────────────┘
  │
  └── (done) ──► SoftwareEngineer
```
- `Editor`는 `code_edit_tool`과 `test_tool` 두 도구를 사용 가능
- 편집 또는 테스트 후 결과를 받아 루프를 반복할 수 있음 (`continue`)
- 편집/테스트가 완료되면 `done`으로 `SoftwareEngineer`에 반환

#### 5. `swe_tool` 경로
```
SoftwareEngineer
    │
    ▼
swe_tool
    │ (continue)
    ▼
SoftwareEngineer
```
- 단순 1회성 도구 호출
- 실행 후 `continue`로 즉시 `SoftwareEngineer`에 제어권 반환

#### 6. `SoftwareEngineer` → `end`
- 모든 서브태스크 완료 후 종료 조건 충족 시 `end`로 전이

---

### 핵심 아키텍처 패턴

1. **ReAct 패턴**: `SoftwareEngineer`가 Reason(상황 판단) → Act(노드 선택)를 반복
2. **계층적 에이전트**: `SoftwareEngineer`(상위) → `CodeAnalyzer`/`Editor`(하위) 구조
3. **도구 루프**: 서브에이전트들은 도구를 여러 번 반복 호출한 뒤 상위 에이전트에 결과를 반환
4. **중앙 집중형 오케스트레이션**: 모든 분기와 종료 결정이 `SoftwareEngineer`에 귀결됨
