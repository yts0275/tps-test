## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 워크플로우는 **다중 에이전트 소프트웨어 엔지니어링 시스템**으로, `SoftwareEngineer`가 오케스트레이터(감독자) 역할을 하고, `CodeAnalyzer`와 `Editor`가 전문 작업자 역할을 담당하는 **계층적 에이전트 구조**다.

---

### 노드 유형 분류

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 (rounded rect) | 전체 계획 수립 및 작업 분배 |
| `CodeAnalyzer` | 전문 에이전트 (rounded rect) | 코드 분석 담당 |
| `Editor` | 전문 에이전트 (rounded rect) | 코드 편집 및 테스트 담당 |
| `swe_tool` | 도구 노드 (rect) | SoftwareEngineer 전용 도구 |
| `code_analysis_tool` | 도구 노드 (rect) | 코드 분석 전용 도구 |
| `code_edit_tool` | 도구 노드 (rect) | 코드 편집 전용 도구 |
| `test_tool` | 도구 노드 (rect) | 테스트 실행 도구 |
| `end` | 종료점 (filled circle) | 워크플로우 종료 |

---

### 엣지 및 조건부 라우팅 상세

#### 1. `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 **무조건** `SoftwareEngineer`로 진입
- 실선(solid) 엣지: 결정론적 전이

---

#### 2. `SoftwareEngineer` (오케스트레이터)의 분기 결정

`SoftwareEngineer`는 현재 태스크 상태를 판단하여 4가지 경로 중 하나를 선택:

| 조건 라우팅 레이블 | 목적지 | 의미 |
|---|---|---|
| `analyze_code` | → `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | → `Editor` | 코드 수정이 필요한 경우 |
| (dashed) | → `swe_tool` | 자체 도구 사용이 필요한 경우 |
| `continue` | → `end` | 모든 작업 완료, 종료 |

---

#### 3. `SoftwareEngineer` ↔ `swe_tool` 루프

```
SoftwareEngineer --[dashed]--> swe_tool
swe_tool --[continue]--> SoftwareEngineer
```

- `SoftwareEngineer`가 직접 사용하는 전용 도구(예: 파일 탐색, 검색 등)
- 도구 실행 완료 후 `continue` 레이블로 `SoftwareEngineer`로 복귀
- 복귀 후 다시 다음 행동을 결정

---

#### 4. `CodeAnalyzer` 노드의 동작

```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer
CodeAnalyzer --[dashed, loop]--> code_analysis_tool
CodeAnalyzer --[done]--> SoftwareEngineer
CodeAnalyzer --[continue]--> Editor
```

- `SoftwareEngineer`로부터 `analyze_code` 명령을 받아 진입
- **`code_analysis_tool`을 반복 호출** (dashed self-loop): 필요에 따라 분석 도구를 여러 번 사용 가능
- 분석 완료 후 두 가지 경로 중 선택:
  - `done` → `SoftwareEngineer` : 분석 결과를 오케스트레이터에 보고
  - `continue` → `Editor` : 분석 결과를 바탕으로 즉시 편집 에이전트에 핸드오프

---

#### 5. `Editor` 노드의 동작

```
SoftwareEngineer --[edit_file]--> Editor
CodeAnalyzer --[continue]--> Editor
Editor --[dashed, loop]--> code_edit_tool
Editor --[dashed, loop]--> test_tool
Editor --[done]--> SoftwareEngineer
Editor --[continue]--> CodeAnalyzer
```

- `SoftwareEngineer`로부터 직접 또는 `CodeAnalyzer`로부터 핸드오프 받아 진입
- **`code_edit_tool`** 과 **`test_tool`** 을 반복 호출(dashed loop): 편집 후 테스트 → 수정 → 재테스트 사이클 가능
- 작업 완료 후 두 가지 경로 중 선택:
  - `done` → `SoftwareEngineer` : 편집 결과를 오케스트레이터에 보고
  - `continue` → `CodeAnalyzer` : 추가 분석이 필요하다고 판단 시 재분석 요청

---

### 핵심 동작 패턴

#### 패턴 1: 단순 코드 분석 흐름
```
start → SoftwareEngineer --[analyze_code]--> CodeAnalyzer 
     --> code_analysis_tool (반복) 
     --> [done] → SoftwareEngineer --[continue]--> end
```

#### 패턴 2: 단순 코드 편집 흐름
```
start → SoftwareEngineer --[edit_file]--> Editor 
     --> code_edit_tool / test_tool (반복) 
     --> [done] → SoftwareEngineer --[continue]--> end
```

#### 패턴 3: 분석 → 편집 협업 흐름 (CodeAnalyzer 주도)
```
start → SoftwareEngineer --[analyze_code]--> CodeAnalyzer 
     --> code_analysis_tool 
     --> [continue] → Editor 
     --> code_edit_tool / test_tool 
     --> [done] → SoftwareEngineer --[continue]--> end
```

#### 패턴 4: 편집 → 재분석 피드백 루프
```
SoftwareEngineer --[edit_file]--> Editor 
     --> [continue] → CodeAnalyzer 
     --> [done] → SoftwareEngineer → ...
```

#### 패턴 5: 복합 반복 루프 (실제 복잡한 태스크)
```
SoftwareEngineer 
  --[analyze_code]--> CodeAnalyzer (분석)
  --[continue]--> Editor (편집+테스트)
  --[continue]--> CodeAnalyzer (재분석)
  --[done]--> SoftwareEngineer
  --[edit_file]--> Editor (추가 수정)
  --[done]--> SoftwareEngineer
  --[continue]--> end
```

---

### 설계 특징 요약

1. **계층적 감독 구조**: `SoftwareEngineer`가 전체 흐름을 제어하며, 하위 에이전트들은 결과를 반드시 보고하거나 서로 핸드오프
2. **에이전트 간 직접 협업**: `CodeAnalyzer` ↔ `Editor` 간 `continue` 엣지를 통해 오케스트레이터를 거치지 않고 직접 협업 가능
3. **도구 반복 사용**: 각 에이전트는 자신의 도구를 루프로 반복 호출하여 복잡한 작업 처리
4. **단일 종료점**: 모든 경로는 결국 `SoftwareEngineer`로 수렴 후 `end`로 종료되어 일관된 완료 조건 보장
