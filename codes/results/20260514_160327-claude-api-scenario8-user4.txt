이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 설명합니다.

---

## 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 에이전트 시스템**으로, `SoftwareEngineer`가 중심 오케스트레이터(Orchestrator) 역할을 하고, `CodeAnalyzer`와 `Editor`가 전문화된 서브 에이전트로 동작합니다.

---

## 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | 에이전트 노드 (purple rect) | 중앙 오케스트레이터 — 작업 분배 및 의사결정 |
| `CodeAnalyzer` | 에이전트 노드 (purple rect) | 코드 분석 전담 서브 에이전트 |
| `Editor` | 에이전트 노드 (purple rect) | 코드 편집 및 테스트 전담 서브 에이전트 |
| `swe_tool` | 도구 노드 (light rect) | SoftwareEngineer가 직접 사용하는 도구 |
| `code_analysis_tool` | 도구 노드 (light purple) | CodeAnalyzer가 호출하는 분석 도구 |
| `code_edit_tool` | 도구 노드 (light purple) | Editor가 호출하는 편집 도구 |
| `test_tool` | 도구 노드 (light purple) | Editor가 호출하는 테스트 도구 |
| `end` | 종료점 (purple oval) | 워크플로우 종료 |

---

## 엣지(Edge) 흐름 상세

### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입합니다.

---

### 2. SoftwareEngineer — 중앙 라우터

`SoftwareEngineer`는 현재 상태(State)를 판단하여 **4가지 조건부 엣지** 중 하나를 선택합니다.

```
SoftwareEngineer
 ├─[analyze_code]──→ CodeAnalyzer
 ├─[edit_file]─────→ Editor
 ├─[swe_tool]──────→ swe_tool
 └─[end]───────────→ end
```

- **`analyze_code`**: 코드 분석이 필요하다고 판단 → `CodeAnalyzer`에게 위임
- **`edit_file`**: 코드 편집이 필요하다고 판단 → `Editor`에게 위임
- **`swe_tool`**: 직접 도구 호출이 필요한 경우 → `swe_tool` 실행
- **`end`**: 작업이 완료되었다고 판단 → 워크플로우 종료

---

### 3. CodeAnalyzer — 분석 루프

```
CodeAnalyzer
 ├─[도구 호출, dashed]──→ code_analysis_tool
 │                              │
 │       [continue, dashed] ←──┘
 ├──────────────────────────────┘  (자기 자신으로 순환)
 └─[done]───────────────────→ SoftwareEngineer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 **반복적으로 호출**할 수 있습니다 (dashed 화살표 = 도구 호출).
- 도구 결과를 받은 후 `continue`로 자기 자신에게 돌아와 추가 분석을 이어갑니다.
- 분석이 완료되면 `done` 엣지로 **`SoftwareEngineer`에게 결과를 반환**합니다.

---

### 4. Editor — 편집/테스트 루프

```
Editor
 ├─[도구 호출, dashed]──→ code_edit_tool
 ├─[도구 호출, dashed]──→ test_tool
 │                              │
 │       [continue, dashed] ←──┘
 ├──────────────────────────────┘  (자기 자신으로 순환)
 └─[done]───────────────────→ SoftwareEngineer
```

- `Editor`는 `code_edit_tool`로 코드를 수정하고, `test_tool`로 테스트를 실행합니다.
- 편집 → 테스트 → 재편집 사이클을 `continue`를 통해 반복할 수 있습니다.
- 작업이 완료되면 `done` 엣지로 `SoftwareEngineer`에 결과를 반환합니다.

---

### 5. swe_tool → 복귀

```
swe_tool ──[continue]──→ SoftwareEngineer
```

`swe_tool` 실행이 끝나면 `continue`를 통해 `SoftwareEngineer`로 돌아옵니다.

---

## 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer (작업 파악)
    → [analyze_code] CodeAnalyzer
        → code_analysis_tool (반복 가능)
        → [done] SoftwareEngineer (분석 결과 전달)
    → [edit_file] Editor
        → code_edit_tool (수정)
        → test_tool (테스트)
        → [continue] Editor (실패 시 재수정)
        → [done] SoftwareEngineer (수정 완료 보고)
    → [end] end
```

---

## 설계 패턴 요약

- **실선 화살표**: 에이전트 간 상태 전환 (State Transition)
- **점선 화살표**: 도구 호출 및 결과 반환 (Tool Call / ToolMessage)
- **`continue` 엣지**: 서브 에이전트의 자기 루프 — 도구를 여러 번 호출하며 작업을 반복
- **`done` 엣지**: 서브 에이전트의 임무 완료 후 오케스트레이터 복귀
- `SoftwareEngineer`는 전체 진행 상황을 계속 감시하며, 서브 에이전트 결과를 받아 다음 단계를 결정하는 **ReAct 패턴 기반 오케스트레이터**입니다.
