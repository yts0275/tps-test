## LangGraph Workflow 노드 흐름 분석

### 전체 구조 개요

이 워크플로우는 **SoftwareEngineer**를 중앙 오케스트레이터로 두고, `CodeAnalyzer`와 `Editor`가 협력하는 **계층형 멀티 에이전트** 구조다.

---

### 노드 목록 및 역할

| 노드 | 종류 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 노드 | 작업 분류 및 라우팅 |
| `CodeAnalyzer` | 서브 에이전트 노드 | 코드 분석 담당 |
| `Editor` | 서브 에이전트 노드 | 코드 편집/테스트 담당 |
| `swe_tool` | 도구 노드 | SoftwareEngineer 전용 도구 |
| `code_analysis_tool` | 도구 노드 | 코드 분석 도구 |
| `code_edit_tool` | 도구 노드 | 코드 편집 도구 |
| `test_tool` | 도구 노드 | 테스트 실행 도구 |
| `end` | 종료점 | 워크플로우 종료 |

---

### 엣지 흐름 상세 설명

#### 1. 워크플로우 시작
```
start → SoftwareEngineer
```
- 워크플로우가 시작되면 가장 먼저 `SoftwareEngineer` 노드가 실행된다.

---

#### 2. SoftwareEngineer의 라우팅 결정 (조건부 분기)

`SoftwareEngineer`는 작업의 성격에 따라 4가지 방향으로 분기한다:

| 조건 | 목적지 | 설명 |
|------|--------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | `Editor` | 코드 편집이 필요한 경우 |
| (도구 호출) | `swe_tool` | 도구 직접 사용이 필요한 경우 |
| `continue` | `end` | 작업 완료, 워크플로우 종료 |

---

#### 3. CodeAnalyzer 서브 루프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
```

`CodeAnalyzer`는 내부적으로 다음 두 도구를 점선(dashed) 화살표로 호출한다:
- `code_analysis_tool`: 코드 정적 분석 수행
- `code_edit_tool`: 분석 결과에 따른 경미한 수정

`CodeAnalyzer`의 작업 완료 후 분기:

| 조건 | 목적지 | 설명 |
|------|--------|------|
| `done` | `SoftwareEngineer` | 분석 완료, 결과를 오케스트레이터에 보고 |
| `continue` | `Editor` | 분석 후 편집 작업이 연속으로 필요한 경우 |

---

#### 4. Editor 서브 루프

```
SoftwareEngineer --edit_file--> Editor
```

`Editor`는 내부적으로 다음 두 도구를 점선 화살표로 호출한다:
- `code_edit_tool`: 실제 코드 파일 수정
- `test_tool`: 수정 후 테스트 실행 및 검증

`Editor`의 작업 완료 후 분기:

| 조건 | 목적지 | 설명 |
|------|--------|------|
| `done` | `SoftwareEngineer` | 편집 완료, 결과를 오케스트레이터에 보고 |
| `continue` | `CodeAnalyzer` | 편집 후 재분석이 필요한 경우 |

---

#### 5. CodeAnalyzer ↔ Editor 순환 루프

```
CodeAnalyzer --continue--> Editor --continue--> CodeAnalyzer
```

- `CodeAnalyzer`와 `Editor`는 서로 `continue` 엣지로 연결되어 **순환(loop)** 구조를 형성한다.
- 분석 → 편집 → 재분석 → 재편집 사이클이 완전히 해결될 때까지 반복된다.
- 최종적으로 어느 한 노드가 `done`을 반환하면 `SoftwareEngineer`로 복귀한다.

---

#### 6. swe_tool 호출 및 복귀

```
SoftwareEngineer --> swe_tool --> SoftwareEngineer (continue)
```

- `SoftwareEngineer`가 직접 도구를 사용해야 할 때 `swe_tool`을 호출한다.
- 도구 실행 완료 후 `continue` 엣지로 `SoftwareEngineer`에게 결과를 반환한다.

---

#### 7. 워크플로우 종료

```
SoftwareEngineer --continue--> end
```

- `SoftwareEngineer`가 모든 작업이 완료되었다고 판단하면 `end` 노드로 라우팅하여 워크플로우를 종료한다.

---

### 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer (작업 분석)
    → CodeAnalyzer (코드 분석 필요)
      ↔ code_analysis_tool (분석 실행)
      → Editor (continue: 수정 필요)
        ↔ code_edit_tool (코드 수정)
        ↔ test_tool (테스트 실행)
        → CodeAnalyzer (continue: 재분석 필요)
          ↔ code_analysis_tool (재분석)
          → SoftwareEngineer (done: 분석 완료)
    → swe_tool (추가 작업)
      → SoftwareEngineer (continue: 복귀)
    → end (작업 완료)
```

---

### 핵심 설계 패턴 요약

- **점선 화살표**: 에이전트 → 도구 호출 (Tool Call), 결과는 즉시 해당 에이전트로 반환
- **실선 화살표**: 에이전트 간 상태 전환 (State Transition), 조건부 라우팅
- **`done`**: 하위 작업 완료, 상위 오케스트레이터로 제어권 반환
- **`continue`**: 작업 미완료, 다음 협력 노드로 제어권 이전 (루프 유지)
