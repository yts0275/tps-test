이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 설명합니다.

---

## 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 자동화 에이전트** 시스템으로, 중앙 오케스트레이터(`SoftwareEngineer`)가 전문화된 하위 노드들에게 작업을 위임하는 **감독자(Supervisor) 패턴**으로 설계되어 있습니다.

---

## 노드 구성

| 노드 | 역할 | 종류 |
|------|------|------|
| `start` | 워크플로우 진입점 | 시스템 노드 |
| `SoftwareEngineer` | 중앙 오케스트레이터 (의사결정) | Agent 노드 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 | Agent 노드 |
| `Editor` | 코드 편집 전담 에이전트 | Agent 노드 |
| `swe_tool` | 범용 SWE 도구 실행기 | Tool 노드 |
| `code_analysis_tool` | 코드 분석 도구 | Tool 노드 |
| `code_edit_tool` | 코드 편집 도구 | Tool 노드 |
| `test_tool` | 테스트 실행 도구 | Tool 노드 |
| `end` | 워크플로우 종료 | 시스템 노드 |

---

## 흐름 상세 분석

### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입합니다. 이 노드가 전체 작업의 중심이며 **라우팅 결정권**을 가집니다.

---

### 2. SoftwareEngineer의 조건부 분기 (Conditional Edges)

`SoftwareEngineer`는 현재 상태를 평가하여 4가지 방향 중 하나를 선택합니다:

#### 분기 A: `analyze_code` → `CodeAnalyzer`
- 코드 분석이 필요하다고 판단할 때 `CodeAnalyzer`로 위임
- 예: 버그 원인 파악, 코드 구조 이해, 변경 영향도 분석

#### 분기 B: `edit_file` → `Editor`
- 파일 수정이 필요하다고 판단할 때 `Editor`로 위임
- 예: 코드 작성, 버그 수정, 리팩토링

#### 분기 C: `swe_tool` (직접 실행)
- 분석이나 편집 없이 SWE 범용 도구를 직접 실행
- 예: 파일 탐색, 디렉터리 구조 확인 등 단순 작업

#### 분기 D: `end` (종료)
- 모든 작업이 완료되었다고 판단할 때 워크플로우를 종료

---

### 3. CodeAnalyzer 서브루프

```
CodeAnalyzer ⟷ code_analysis_tool  (도구 호출 루프)
CodeAnalyzer --[done]-→ SoftwareEngineer  (분석 완료 후 복귀)
CodeAnalyzer --[continue]-→ Editor  (분석 후 편집 필요 시 직접 전달)
```

- `CodeAnalyzer`는 **`code_analysis_tool`을 반복 호출**하며 분석을 수행합니다 (ReAct 패턴).
- 분석이 완료되면 두 가지 선택:
  - `done` → `SoftwareEngineer`로 결과 보고 후 다음 지시 대기
  - `continue` → `Editor`로 직접 전환 (중간 판단: 수정이 필요함을 감지)

---

### 4. Editor 서브루프

```
Editor ⟷ code_edit_tool  (편집 도구 호출 루프)
Editor ⟷ test_tool        (테스트 도구 호출 루프)
Editor --[done]-→ SoftwareEngineer  (편집 완료 후 복귀)
Editor --[continue]-→ CodeAnalyzer  (편집 후 재분석 필요 시 직접 전달)
```

- `Editor`는 **`code_edit_tool`과 `test_tool`을 반복 호출**하며 편집과 검증을 수행합니다.
- 편집 완료 후 두 가지 선택:
  - `done` → `SoftwareEngineer`로 결과 보고 후 다음 지시 대기
  - `continue` → `CodeAnalyzer`로 직접 전환 (편집 후 추가 분석이 필요함을 감지)

---

### 5. swe_tool 복귀 흐름

```
swe_tool --[continue]-→ SoftwareEngineer
```

`swe_tool` 실행이 끝나면 결과를 `SoftwareEngineer`에 반환하고, `SoftwareEngineer`가 다시 다음 행동을 결정합니다.

---

## 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer (작업 파악)
    → CodeAnalyzer [analyze_code]
        → code_analysis_tool (반복 호출)
        → Editor [continue] (분석 중 수정 필요 감지)
            → code_edit_tool (수정)
            → test_tool (테스트)
            → SoftwareEngineer [done] (완료 보고)
  → SoftwareEngineer (결과 평가)
    → end (모든 작업 완료)
```

---

## 핵심 설계 특징

1. **감독자 패턴**: `SoftwareEngineer`가 항상 최종 결정권을 가지며, 하위 에이전트들은 완료 후 반드시 보고하거나 직접 협력 에이전트로 전달합니다.
2. **에이전트 간 직접 협력**: `CodeAnalyzer ↔ Editor` 간 `continue` 엣지를 통해 `SoftwareEngineer`를 거치지 않고 직접 작업을 넘길 수 있어 **불필요한 라운드트립을 줄입니다**.
3. **ReAct 루프**: 각 에이전트 노드(CodeAnalyzer, Editor)는 전용 도구와 반복 루프를 형성하여 **멀티스텝 작업을 자율적으로 처리**합니다.
4. **점선 엣지**: 조건부 라우팅(conditional edges)을 의미하며, 런타임 상태에 따라 동적으로 결정됩니다.
