## LangGraph Workflow 노드 흐름 상세 설명

---

### 노드 구성

| 노드 | 역할 |
|---|---|
| `start` | 워크플로우 진입점 |
| `SoftwareEngineer` | 중앙 오케스트레이터 (의사결정 허브) |
| `CodeAnalyzer` | 코드 분석 전담 서브에이전트 |
| `Editor` | 코드 편집/테스트 전담 서브에이전트 |
| `swe_tool` | 범용 소프트웨어 엔지니어링 도구 |
| `end` | 워크플로우 종료 |
| `code_analysis_tool` | CodeAnalyzer가 호출하는 분석 도구 |
| `code_edit_tool` | Editor가 호출하는 편집 도구 |
| `test_tool` | Editor가 호출하는 테스트 도구 |

---

### 전체 흐름

```
start
  │
  ▼
SoftwareEngineer  ◄──────────────────────────────┐
  │                                               │
  ├─[analyze_code]──► CodeAnalyzer                │
  │                     │   ▲                     │
  │                     │   │ [continue]          │
  │                     │   ▼                     │
  │                  code_analysis_tool            │
  │                     │                         │
  │                     └──[done]──────────────►  │
  │                                               │
  ├─[edit_file]────► Editor  ◄──[continue]──────┐ │
  │                   │  │                      │ │
  │                   │  └──► code_edit_tool     │ │
  │                   │       test_tool          │ │
  │                   │  [continue]──────────────┘ │
  │                   └──[done]──────────────────► │
  │                                               │
  ├──────────────────► swe_tool                   │
  │                       └──[continue]──────────► │
  │
  └──────────────────► end
```

---

### 단계별 상세 흐름

#### 1. `start` → `SoftwareEngineer`
워크플로우가 시작되면 무조건적으로 `SoftwareEngineer` 노드로 진입한다. 이 노드는 사용자의 요청을 받아 다음 행동을 결정하는 **중앙 오케스트레이터**다.

---

#### 2. `SoftwareEngineer`의 조건부 라우팅 (4가지 경로)

`SoftwareEngineer`는 현재 상태를 분석하여 아래 4가지 경로 중 하나를 선택한다.

| 조건 | 목적지 | 의미 |
|---|---|---|
| `analyze_code` | `CodeAnalyzer` | 코드를 분석해야 할 때 |
| `edit_file` | `Editor` | 파일을 편집/수정해야 할 때 |
| (직접 호출) | `swe_tool` | 기타 소프트웨어 엔지니어링 작업 |
| (태스크 완료) | `end` | 모든 작업이 완료된 경우 |

---

#### 3. `CodeAnalyzer` 서브그래프

`SoftwareEngineer`로부터 `analyze_code` 신호를 받아 활성화된다.

- **내부 루프**: `CodeAnalyzer`는 `code_analysis_tool`을 반복 호출하여 코드 구조, 의존성, 버그 등을 분석한다. 분석이 끝나지 않았으면 `continue`로 자기 자신 혹은 `Editor`로 루프를 이어간다.
- **완료 신호**: 분석이 충분히 완료되면 `done`을 반환하여 `SoftwareEngineer`로 결과를 보고하고 제어권을 반환한다.

```
CodeAnalyzer
    │
    ├──► code_analysis_tool (반복 호출 가능)
    │
    ├─[continue]──► Editor (분석 결과를 기반으로 편집 필요 시)
    └─[done]──────► SoftwareEngineer (분석 완료 보고)
```

---

#### 4. `Editor` 서브그래프

`SoftwareEngineer`로부터 `edit_file` 신호를 받거나 `CodeAnalyzer`로부터 `continue`를 받아 활성화된다.

- **도구 사용**: `code_edit_tool`로 실제 파일 수정을 수행하고, `test_tool`로 수정 후 테스트를 실행한다.
- **재분석 루프**: 테스트 실패 또는 추가 분석이 필요하면 `continue`로 다시 `CodeAnalyzer`로 돌아간다.
- **완료 신호**: 편집과 테스트가 성공하면 `done`을 반환하여 `SoftwareEngineer`에 제어권을 넘긴다.

```
Editor
    │
    ├──► code_edit_tool (파일 수정)
    ├──► test_tool      (테스트 실행)
    │
    ├─[continue]──► CodeAnalyzer (테스트 실패 → 재분석)
    └─[done]──────► SoftwareEngineer (편집+테스트 완료 보고)
```

---

#### 5. `swe_tool`

`SoftwareEngineer`가 직접 호출하는 범용 도구 노드로, 코드 분석/편집 이외의 소프트웨어 엔지니어링 작업(예: 파일 탐색, 명령 실행 등)을 처리한다. 작업 완료 후 `continue` 신호와 함께 `SoftwareEngineer`로 결과를 반환한다.

---

#### 6. `SoftwareEngineer` → `end`

`SoftwareEngineer`가 서브에이전트들의 `done` 보고를 받고, 사용자 요청이 완전히 해결되었다고 판단하면 `end` 노드로 전환하여 워크플로우를 종료한다.

---

### 핵심 설계 패턴 요약

- **Hub-and-Spoke**: `SoftwareEngineer`가 허브 역할을 하며, 모든 서브에이전트는 작업 완료 후 다시 허브로 복귀한다.
- **ReAct 루프**: `CodeAnalyzer`와 `Editor`는 각자 도구를 반복 호출하며 `continue/done` 신호로 루프를 제어한다.
- **양방향 협력**: `CodeAnalyzer` ↔ `Editor` 간 `continue` 엣지를 통해 분석→편집→재분석의 반복적 협력이 가능하다.
