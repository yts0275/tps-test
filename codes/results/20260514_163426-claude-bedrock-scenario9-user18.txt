## LangGraph 워크플로우 노드 흐름 분석

### 전체 구조 개요

이 워크플로우는 **SoftwareEngineer** 를 중심 오케스트레이터로 하는 **멀티 에이전트 시스템**이다. 에지는 실선(무조건 전이)과 점선(조건부 전이/라우팅)으로 구분된다.

---

### 노드별 상세 설명

#### 1. `start` → `SoftwareEngineer` (실선)
- 워크플로우 진입점. 실행이 시작되면 반드시 **SoftwareEngineer** 로 진입한다.

---

#### 2. `SoftwareEngineer` (중앙 오케스트레이터 에이전트)
전체 작업을 이해하고 다음 4가지 경로 중 하나를 **조건부로** 선택한다:

| 출력 결정 | 이동 대상 | 의미 |
|---|---|---|
| `analyze_code` | → `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | → `Editor` | 파일 수정이 필요한 경우 |
| (직접 도구 호출) | → `swe_tool` | SoftwareEngineer 자체 도구 실행 |
| (작업 완료) | → `end` | 모든 작업이 완료된 경우 |

`swe_tool`에서 `continue`를 받으면 다시 **SoftwareEngineer**로 복귀한다.

---

#### 3. `CodeAnalyzer` (코드 분석 전담 에이전트)
코드 구조·로직 분석을 담당하며 세 가지 경로를 가진다:

- **`code_analysis_tool` 호출** → 실제 코드 분석 도구를 실행하고 결과를 받아 처리
- **`done`** → 분석 완료 후 `SoftwareEngineer`에게 결과 반환
- **`continue`** → 추가 분석이 필요하면 자기 자신(`CodeAnalyzer`)으로 루프 반복

또한 `Editor` 노드로부터도 `continue` 신호를 받아 재진입할 수 있다 (편집 후 재분석 시나리오).

---

#### 4. `Editor` (코드 편집 전담 에이전트)
파일 수정 및 테스트 실행을 담당하며 네 가지 경로를 가진다:

- **`code_edit_tool` 호출** → 파일 편집 도구 실행
- **`test_tool` 호출** → 테스트 실행 도구 실행
- **`done`** → 편집/테스트 완료 후 `SoftwareEngineer`에게 결과 반환
- **`continue`** → 두 방향으로 분기:
  - → `CodeAnalyzer` : 편집 후 재분석이 필요한 경우
  - → `Editor` 자기 루프 : 추가 편집이 필요한 경우

---

#### 5. `swe_tool` (SoftwareEngineer 전용 도구 노드)
- `SoftwareEngineer`가 직접 사용하는 범용 도구
- 실행 완료 후 **`continue`** 를 통해 반드시 `SoftwareEngineer`로 복귀

---

#### 6. `end` (종료 노드)
- `SoftwareEngineer`가 모든 작업이 완료됐다고 판단할 때만 도달
- 워크플로우를 종료한다

---

### 전체 실행 흐름 예시

```
start
  └─▶ SoftwareEngineer
        ├─[analyze_code]─▶ CodeAnalyzer
        │                    ├─▶ code_analysis_tool ─▶ (결과 반환)
        │                    ├─[continue]─▶ CodeAnalyzer (재분석 루프)
        │                    └─[done]─▶ SoftwareEngineer
        │
        ├─[edit_file]─▶ Editor
        │                ├─▶ code_edit_tool ─▶ (편집 완료)
        │                ├─▶ test_tool ─▶ (테스트 실행)
        │                ├─[continue]─▶ CodeAnalyzer (재분석)
        │                ├─[continue]─▶ Editor (재편집 루프)
        │                └─[done]─▶ SoftwareEngineer
        │
        ├─▶ swe_tool ─[continue]─▶ SoftwareEngineer
        │
        └─▶ end
```

---

### 설계 패턴 요약

- **SoftwareEngineer**: Plan-and-Dispatch 패턴의 중앙 조정자
- **CodeAnalyzer / Editor**: 전문화된 서브에이전트 (Specialist Agent)
- **`continue` 루프**: 작업이 완료될 때까지 반복 실행을 허용하는 자기 루프 (ReAct 패턴)
- **`done` 신호**: 서브에이전트가 작업 완료를 오케스트레이터에게 명시적으로 알리는 핸드오프 신호
