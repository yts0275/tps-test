## LangGraph Workflow 노드 흐름 상세 설명

---

### 전체 구조 개요

이 워크플로우는 **SoftwareEngineer**를 중심 오케스트레이터로 두고, **CodeAnalyzer**와 **Editor** 두 개의 서브에이전트가 각자의 도구를 활용해 작업을 처리하는 **계층형 멀티에이전트 아키텍처**다.

---

### 노드 목록

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 에이전트 | 작업 분석 및 라우팅 결정 |
| `CodeAnalyzer` | 서브에이전트 | 코드 분석 전담 |
| `Editor` | 서브에이전트 | 코드 편집/테스트 전담 |
| `swe_tool` | 도구 노드 | SoftwareEngineer 직접 도구 |
| `code_analysis_tool` | 도구 노드 | CodeAnalyzer 전용 분석 도구 |
| `code_edit_tool` | 도구 노드 | Editor 전용 편집 도구 |
| `test_tool` | 도구 노드 | Editor 전용 테스트 도구 |
| `end` | 종료점 | 워크플로우 완료 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입한다.

---

#### 2. SoftwareEngineer (중앙 라우터)

`SoftwareEngineer`는 현재 상태를 판단해 다음 4가지 경로 중 하나를 선택하는 **조건부 라우팅**을 수행한다.

```
SoftwareEngineer ──analyze_code──→ CodeAnalyzer
SoftwareEngineer ──edit_file──────→ Editor
SoftwareEngineer ──────────────────→ swe_tool
SoftwareEngineer ──────────────────→ end
```

| 전이 조건 | 목적지 | 의미 |
|-----------|--------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | `Editor` | 파일 편집이 필요한 경우 |
| (직접 도구 호출) | `swe_tool` | SE가 직접 처리할 도구 작업 |
| (작업 완료) | `end` | 모든 작업이 종료된 경우 |

---

#### 3. CodeAnalyzer 서브그래프

`CodeAnalyzer`는 **자체 루프(self-loop)** 를 가진 에이전트로, 분석이 완료될 때까지 반복 실행된다.

```
CodeAnalyzer ──(tool call)──→ code_analysis_tool
code_analysis_tool ──────────→ CodeAnalyzer   ← 도구 결과 반환
CodeAnalyzer ──continue──────→ CodeAnalyzer   ← 추가 분석 필요 시 자기 자신으로
CodeAnalyzer ──done──────────→ SoftwareEngineer
```

- **`continue`**: 아직 분석이 더 필요한 경우, 자기 자신(CodeAnalyzer)으로 다시 돌아와 `code_analysis_tool`을 추가 호출
- **`done`**: 분석 완료 시 결과를 가지고 `SoftwareEngineer`로 복귀

> 점선(dashed) 화살표는 LangGraph의 **ToolNode 패턴** — 에이전트가 도구를 호출하고 결과를 받아 다시 에이전트로 돌아오는 표준 사이클이다.

---

#### 4. Editor 서브그래프

`Editor`도 `CodeAnalyzer`와 유사하게 **자체 루프**를 가지며, **두 가지 도구**를 활용한다.

```
Editor ──(tool call)──→ code_edit_tool
Editor ──(tool call)──→ test_tool
code_edit_tool ─────────→ Editor   ← 편집 결과 반환
test_tool ──────────────→ Editor   ← 테스트 결과 반환
Editor ──continue───────→ Editor   ← 추가 편집/테스트 필요 시
Editor ──done───────────→ SoftwareEngineer
```

- **`code_edit_tool`**: 실제 파일 수정 수행
- **`test_tool`**: 수정된 코드에 대한 테스트 실행
- **`continue`**: 테스트 실패 또는 추가 편집이 필요한 경우 루프 반복
- **`done`**: 편집 및 테스트 완료 후 `SoftwareEngineer`로 복귀

---

#### 5. swe_tool → SoftwareEngineer 복귀

```
swe_tool ──continue──→ SoftwareEngineer
```

`SoftwareEngineer`가 직접 호출한 도구(`swe_tool`) 실행 후 `continue` 엣지로 오케스트레이터에게 결과를 반환하고, 다음 라우팅 결정을 기다린다.

---

### 전체 실행 시나리오 예시

```
start
  └→ SoftwareEngineer (태스크 수신, 분석 필요 판단)
       └→ [analyze_code] CodeAnalyzer
            ├→ code_analysis_tool (분석 도구 호출)
            ├→ code_analysis_tool (추가 호출, continue 루프)
            └→ [done] SoftwareEngineer (분석 결과 전달)
                 └→ [edit_file] Editor
                      ├→ code_edit_tool (코드 수정)
                      ├→ test_tool (테스트 실행)
                      ├→ code_edit_tool (테스트 실패 → 재수정, continue 루프)
                      ├→ test_tool (재테스트)
                      └→ [done] SoftwareEngineer (편집 완료)
                           └→ end (모든 작업 완료)
```

---

### 핵심 설계 패턴 요약

1. **오케스트레이터-서브에이전트 패턴**: `SoftwareEngineer`가 전체 흐름을 제어하고 전문 에이전트에게 위임
2. **ReAct 루프 (Reason + Act)**: 각 서브에이전트가 도구 호출 → 결과 수신 → 판단 → 재호출을 반복
3. **조건부 엣지**: `done` / `continue` 조건으로 루프 종료 여부 결정
4. **점선 = ToolNode 사이클**: LangGraph 표준 도구 실행 패턴 (에이전트 → 도구 → 에이전트)
