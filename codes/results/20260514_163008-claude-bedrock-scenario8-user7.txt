## LangGraph 워크플로우 노드 흐름 분석

### 노드 구성

| 노드명 | 역할 | 타입 |
|--------|------|------|
| `start` | 워크플로우 진입점 | Entry Node |
| `SoftwareEngineer` | 중앙 오케스트레이터 | Agent Node |
| `CodeAnalyzer` | 코드 분석 서브에이전트 | Agent Node |
| `Editor` | 파일 편집 서브에이전트 | Agent Node |
| `swe_tool` | 범용 SWE 도구 실행 | Tool Node |
| `code_analysis_tool` | 코드 분석 도구 | Tool Node |
| `code_edit_tool` | 코드 편집 도구 | Tool Node |
| `test_tool` | 테스트 실행 도구 | Tool Node |
| `end` | 워크플로우 종료점 | End Node |

---

### 전체 흐름 개요

```
start
  └─► SoftwareEngineer ──────────────────────────────────► end
           │          ▲ (continue / done)                    ▲
           │          │                                       │
     ┌─────┼─────────────────────────────────────────────────┤
     │     │                                                  │
     │  analyze_code                                     swe_tool
     │     │                                                  │
     │     ▼                                                  │
     │  CodeAnalyzer ◄──────────────────────┐                │
     │     │    ▲                            │                │
     │     │    └── (continue) ── code_analysis_tool         │
     │     │ (done)                                           │
     │     └──────────────────► SoftwareEngineer             │
     │                                                        │
  edit_file                                                   │
     │                                                        │
     ▼                                                        │
   Editor ◄──────────────────────────────┐                   │
     │    ▲                              │                    │
     │    ├── (continue) ── code_edit_tool                   │
     │    └── (continue) ── test_tool                        │
     │ (done)                                                 │
     └──────────────────────► SoftwareEngineer ──────────────┘
```

---

### 상세 흐름 서술

#### 1. 진입 단계: `start` → `SoftwareEngineer`

워크플로우는 `start` 노드에서 시작되어 **SoftwareEngineer** 에이전트로 진입한다. 이 노드는 전체 작업의 **중앙 오케스트레이터**로서, 작업 내용을 파악하고 어떤 서브에이전트 또는 도구로 라우팅할지 결정하는 역할을 한다.

---

#### 2. SoftwareEngineer의 조건부 라우팅 (Conditional Edge)

`SoftwareEngineer`는 현재 상태를 평가하여 다음 4가지 경로 중 하나를 선택한다:

| 전이 레이블 | 목적지 | 의미 |
|------------|--------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요할 때 |
| `edit_file` | `Editor` | 파일 수정이 필요할 때 |
| `swe_tool` | `swe_tool` | 범용 SWE 작업 실행 |
| `continue` | `SoftwareEngineer` (자기 자신) | 추가 사고/판단이 필요할 때 자기 루프 |
| (암묵적 종료 조건) | `end` | 모든 작업이 완료되었을 때 |

---

#### 3. CodeAnalyzer 서브그래프

`SoftwareEngineer`가 `analyze_code`를 선택하면 **CodeAnalyzer** 노드로 이동한다.

- **CodeAnalyzer** → `code_analysis_tool` 호출: 실제 코드 분석 도구를 실행한다.
- `code_analysis_tool` → **CodeAnalyzer** (`continue`): 도구 실행 결과를 받아 CodeAnalyzer가 결과를 처리한다. 분석이 충분하지 않으면 **반복(loop)** 한다.
- **CodeAnalyzer** → `SoftwareEngineer` (`done`): 분석이 완료되면 결과를 SoftwareEngineer에게 반환하여 다음 판단을 맡긴다.

---

#### 4. Editor 서브그래프

`SoftwareEngineer`가 `edit_file`을 선택하면 **Editor** 노드로 이동한다.

- **Editor** → `code_edit_tool` 또는 `test_tool` 호출: 파일 편집 혹은 테스트 실행 도구를 사용한다.
- `code_edit_tool` / `test_tool` → **Editor** (`continue`): 도구 결과를 받아 Editor가 처리하며, 추가 편집/테스트가 필요하면 **반복(loop)** 한다.
- **Editor** → `SoftwareEngineer` (`done`): 편집 및 검증이 완료되면 SoftwareEngineer에게 제어권을 반환한다.

---

#### 5. SoftwareEngineer로의 귀환과 재판단

서브에이전트(`CodeAnalyzer`, `Editor`)가 `done`을 반환하면 다시 **SoftwareEngineer**가 제어권을 가져온다. SoftwareEngineer는 전체 진행 상황을 재평가하여:
- 추가 분석이 필요하면 다시 `CodeAnalyzer`로
- 추가 편집이 필요하면 다시 `Editor`로
- 다른 도구가 필요하면 `swe_tool`로
- 모든 작업이 완료되었으면 `end`로 라우팅한다.

---

#### 6. 종료: `end`

모든 작업이 완료되었다고 SoftwareEngineer가 판단하면 `end` 노드로 전이하며 워크플로우가 종료된다.

---

### 핵심 설계 패턴 요약

- **허브-앤-스포크(Hub-and-Spoke)**: `SoftwareEngineer`가 허브 역할을 하며 모든 서브에이전트를 조율한다.
- **Tool-calling Loop**: `CodeAnalyzer`와 `Editor` 각각이 자신의 도구(`code_analysis_tool`, `code_edit_tool`, `test_tool`)와 내부 루프를 형성하여, 도구 실행 → 결과 처리 → 재실행을 반복할 수 있다.
- **ReAct 패턴**: SoftwareEngineer의 `continue` 자기 루프는 ReAct(Reason + Act) 패턴으로, 충분한 정보가 모일 때까지 추론을 반복한다.
- **조건부 전이(Conditional Edges)**: 모든 분기는 점선(dashed)으로 표현되어 있으며, 에이전트의 판단에 따라 동적으로 경로가 결정된다.
