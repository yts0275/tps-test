이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 설명합니다.

---

## 전체 구조 개요

이 워크플로우는 소프트웨어 엔지니어링 작업을 자동화하는 **멀티 에이전트 시스템**으로, `SoftwareEngineer`를 중심 오케스트레이터로 두고 두 개의 전문 에이전트(`CodeAnalyzer`, `Editor`)와 도구 노드들이 협력하는 구조입니다.

---

## 노드 분류

### 에이전트 노드 (Agent Nodes)
| 노드 | 역할 |
|---|---|
| `SoftwareEngineer` | 중앙 오케스트레이터, 작업 분배 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 |
| `Editor` | 파일 편집 및 테스트 전담 에이전트 |

### 도구 노드 (Tool Nodes)
| 노드 | 사용 주체 |
|---|---|
| `code_analysis_tool` | CodeAnalyzer |
| `code_edit_tool` | Editor |
| `test_tool` | Editor |
| `swe_tool` | SoftwareEngineer 직접 사용 |

---

## 노드별 흐름 상세 분석

### 1. `start` → `SoftwareEngineer`
- 그래프 진입점. 워크플로우가 시작되면 즉시 `SoftwareEngineer` 노드로 제어권이 넘어갑니다.

---

### 2. `SoftwareEngineer` (중앙 라우터)
워크플로우의 핵심 의사결정 노드. 현재 상태(state)를 평가하여 다음 4가지 경로 중 하나를 선택합니다.

```
SoftwareEngineer
  ├─[analyze_code]──▶ CodeAnalyzer    # 코드 분석이 필요할 때
  ├─[edit_file]────▶ Editor           # 파일 수정이 필요할 때
  ├─────────────────▶ swe_tool        # 직접 도구 호출이 필요할 때
  └─────────────────▶ end             # 작업 완료 시
```

조건부 엣지(conditional edge)로 구성되어, LLM의 판단 또는 상태값에 따라 라우팅됩니다.

---

### 3. `CodeAnalyzer` 서브 루프

```
CodeAnalyzer ──▶ code_analysis_tool
     ▲                 │
     └─────────────────┘   (도구 실행 후 결과 반환)
     
CodeAnalyzer ──[continue]──▶ CodeAnalyzer   (반복 분석 필요 시 자기 자신으로)
CodeAnalyzer ──[done]──────▶ SoftwareEngineer (분석 완료 시)
```

- `code_analysis_tool`을 호출하여 코드를 분석하고 결과를 받습니다.
- 분석이 불충분하면 `continue` 엣지로 **자기 자신에게 루프**합니다.
- 분석이 완료되면 `done` 엣지로 `SoftwareEngineer`에게 결과를 반환합니다.

---

### 4. `Editor` 서브 루프

```
Editor ──▶ code_edit_tool    (파일 편집)
Editor ──▶ test_tool         (테스트 실행)
  ▲              │
  └──────────────┘  (도구 실행 결과 반환)

Editor ──[continue]──▶ CodeAnalyzer       (편집 후 재분석 필요 시)
Editor ──[done]──────▶ SoftwareEngineer   (편집 완료 시)
```

- `code_edit_tool`로 파일을 수정하고, `test_tool`로 테스트를 실행합니다.
- 편집 후 코드 재검토가 필요하면 `continue` 엣지로 `CodeAnalyzer`에게 넘깁니다.
- 편집이 완료되면 `done` 엣지로 `SoftwareEngineer`에게 결과를 반환합니다.

---

### 5. `swe_tool` → `SoftwareEngineer`
- `SoftwareEngineer`가 직접 사용하는 범용 도구 노드입니다.
- 실행 완료 후 `continue` 엣지로 `SoftwareEngineer`에게 결과를 반환하여 다음 판단을 이어갑니다.

---

### 6. `SoftwareEngineer` → `end`
- 모든 작업이 완료되었다고 판단하면 `end` 노드로 종료합니다.

---

## 전체 흐름 시나리오 예시

```
start
  → SoftwareEngineer  (작업 파악 후 코드 분석 필요 판단)
    → CodeAnalyzer    (analyze_code)
      → code_analysis_tool → CodeAnalyzer (도구 결과 수신)
      → CodeAnalyzer  (continue: 추가 분석)
      → code_analysis_tool → CodeAnalyzer
      → SoftwareEngineer  (done: 분석 완료 보고)
    → Editor          (edit_file: 분석 결과 기반 수정 지시)
      → code_edit_tool → Editor
      → test_tool → Editor
      → CodeAnalyzer  (continue: 수정 코드 검증 요청)
        → code_analysis_tool → CodeAnalyzer
        → SoftwareEngineer  (done)
      → Editor        (추가 수정)
      → SoftwareEngineer  (done: 편집 완료)
  → end               (전체 작업 완료)
```

---

## 핵심 설계 패턴

- **Hub-and-Spoke**: `SoftwareEngineer`가 허브, 나머지가 스포크
- **자율 루프**: 각 에이전트가 스스로 반복 여부(`continue`)와 완료 여부(`done`)를 결정
- **에이전트 간 직접 위임**: `Editor` → `CodeAnalyzer`처럼 `SoftwareEngineer`를 거치지 않고 직접 넘길 수 있어 효율적
