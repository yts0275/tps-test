## LangGraph Workflow 노드 흐름 상세 분석

---

### 노드 구성

| 노드 | 타입 | 역할 |
|------|------|------|
| `SoftwareEngineer` | Agent (오케스트레이터) | 전체 작업 라우팅 및 의사결정 |
| `CodeAnalyzer` | Agent (전문가) | 코드 분석 전담 |
| `Editor` | Agent (전문가) | 코드 편집 및 테스트 전담 |
| `swe_tool` | Tool Node | SoftwareEngineer 전용 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |

---

### 전체 흐름

#### 1. 진입점: `start` → `SoftwareEngineer`

워크플로우는 `start`에서 시작하여 **SoftwareEngineer** 노드로 진입한다. SoftwareEngineer는 오케스트레이터로서, 작업 내용을 파악하고 다음 행동을 결정하는 **중앙 라우터** 역할을 한다.

---

#### 2. SoftwareEngineer의 라우팅 분기

SoftwareEngineer는 상황에 따라 5가지 방향으로 분기한다:

```
SoftwareEngineer
 ├─[analyze_code]──→ CodeAnalyzer      # 코드 분석이 필요할 때
 ├─[edit_file]─────→ Editor            # 파일 편집이 필요할 때
 ├─────────────────→ swe_tool          # 자체 도구 사용이 필요할 때
 ├─[continue]──────→ SoftwareEngineer  # 추가 판단이 필요할 때 (자기 순환)
 └─────────────────→ end               # 작업 완료
```

---

#### 3. CodeAnalyzer 서브플로우

`analyze_code` 엣지를 통해 진입하며, 내부에서 도구를 반복 호출할 수 있다.

```
CodeAnalyzer
 ├─(dashed)──→ code_analysis_tool ──→ CodeAnalyzer  # 분석 도구 호출 및 결과 수신
 ├─(dashed)──→ code_edit_tool     ──→ CodeAnalyzer  # 편집 도구도 사용 가능
 ├─[continue]──→ CodeAnalyzer                        # 추가 분석 필요 시 자기 순환
 └─[done]─────→ SoftwareEngineer                    # 분석 완료 후 오케스트레이터에 반환
```

- **실선(solid)**: 조건부 엣지 — 분석 완료 시 `done`으로 SoftwareEngineer에 제어권 반환
- **점선(dashed)**: 도구 호출 — `code_analysis_tool`, `code_edit_tool`을 호출하고 결과를 받음

---

#### 4. Editor 서브플로우

`edit_file` 엣지를 통해 진입하며, 편집과 테스트를 반복 수행한다.

```
Editor
 ├─(dashed)──→ code_edit_tool ──→ Editor  # 파일 편집 도구 호출
 ├─(dashed)──→ test_tool      ──→ Editor  # 테스트 실행 도구 호출
 ├─[continue]──→ CodeAnalyzer             # 편집 후 분석이 추가로 필요한 경우
 ├─[continue]──→ Editor                   # 추가 편집 작업이 필요할 때 자기 순환
 └─[done]─────→ SoftwareEngineer          # 편집 완료 후 오케스트레이터에 반환
```

- Editor는 CodeAnalyzer와 달리, 완료 전 **CodeAnalyzer로 제어권을 넘길 수 있다** — 편집 후 분석 재검증 패턴을 지원

---

#### 5. swe_tool 흐름

SoftwareEngineer가 직접 필요로 하는 도구를 실행한다.

```
SoftwareEngineer ──→ swe_tool ──[continue]──→ SoftwareEngineer
```

도구 실행 결과를 받아 다시 SoftwareEngineer가 다음 행동을 결정한다.

---

### 전체 실행 시나리오 예시

```
start
  └→ SoftwareEngineer (작업 파악)
       └→ [analyze_code] CodeAnalyzer
            ├→ code_analysis_tool (분석 실행)
            └→ [done] SoftwareEngineer (분석 결과 수신)
                 └→ [edit_file] Editor
                      ├→ code_edit_tool (파일 수정)
                      ├→ test_tool (테스트 실행)
                      └→ [done] SoftwareEngineer (편집 완료)
                           └→ end
```

---

### 핵심 설계 패턴

| 패턴 | 설명 |
|------|------|
| **Hub-and-Spoke** | SoftwareEngineer가 중심에서 모든 에이전트를 조율 |
| **Self-Loop** | 각 에이전트가 `continue`로 자기 자신을 반복 호출하여 다단계 작업 처리 |
| **Tool-Call Pattern** | 점선(dashed) 엣지가 도구 호출과 응답 수신을 나타냄 |
| **Cross-Agent Handoff** | Editor → CodeAnalyzer 간 직접 제어 이전 가능 (SoftwareEngineer 경유 없이) |
