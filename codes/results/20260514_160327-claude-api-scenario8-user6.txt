---

## LangGraph 소프트웨어 엔지니어링 워크플로우 분석

### 노드 구성

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 | 중앙 의사결정 에이전트 |
| `CodeAnalyzer` | 서브 에이전트 | 코드 분석 전담 |
| `Editor` | 서브 에이전트 | 파일 수정/테스트 전담 |
| `swe_tool` | 도구 노드 | SWE 범용 도구 |
| `code_analysis_tool` | 도구 노드 | CodeAnalyzer 전용 도구 |
| `code_edit_tool` | 도구 노드 | Editor 전용 편집 도구 |
| `test_tool` | 도구 노드 | Editor 전용 테스트 도구 |
| `end` | 종료점 | 워크플로우 종료 |

---

### 엣지 흐름 상세 설명

#### 1. 진입 (start → SoftwareEngineer)
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입. 이 노드가 전체 작업의 **슈퍼바이저** 역할을 수행.

---

#### 2. SoftwareEngineer의 라우팅 결정 (조건부 분기)
`SoftwareEngineer`는 현재 상태를 판단해 4가지 방향으로 분기:

```
SoftwareEngineer
  ├─ analyze_code → CodeAnalyzer   (코드 이해/분석이 필요할 때)
  ├─ edit_file    → Editor         (파일 수정이 필요할 때)
  ├─ (직접 호출)  → swe_tool       (간단한 SWE 작업 직접 처리)
  └─ (종료 조건)  → end            (작업 완료 판단 시)
```

---

#### 3. CodeAnalyzer 서브그래프
```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                       │
                              (반복 도구 호출, 점선)
                                       ↕
                              code_analysis_tool
                                       │
                    ┌──────────────────┴──────────────────┐
                    │ done                          continue│
                    ▼                                      ▼
             SoftwareEngineer                          Editor
```
- `code_analysis_tool`은 **점선 화살표** → 실제 LLM 도구 호출(tool call)
- 분석 완료 시(`done`) → `SoftwareEngineer`로 결과 반환
- 분석 후 바로 편집이 필요하면(`continue`) → `Editor`로 직접 전달

---

#### 4. Editor 서브그래프
```
SoftwareEngineer --edit_file--> Editor
CodeAnalyzer ------continue---> Editor
                                   │
                    ┌──────────────┼──────────────┐
              (점선)↕        (점선)↕          (점선)↕
         code_edit_tool    test_tool       (내부 반복)
                                   │
                    ┌──────────────┴──────────────┐
                    │ done                  continue│
                    ▼                              ▼
             SoftwareEngineer               CodeAnalyzer
```
- `code_edit_tool`: 실제 파일 수정 도구
- `test_tool`: 수정 후 테스트 검증 도구
- 편집/테스트 완료 시(`done`) → `SoftwareEngineer`로 복귀
- 테스트 실패 등으로 재분석이 필요하면(`continue`) → `CodeAnalyzer`로 피드백 루프

---

#### 5. swe_tool 처리 경로
```
SoftwareEngineer → swe_tool --continue--> SoftwareEngineer
```
간단한 작업은 서브 에이전트 없이 `swe_tool`에서 처리 후 `continue` 레이블로 다시 `SoftwareEngineer`로 복귀.

---

### 전체 실행 시나리오 예시

```
start
  → SoftwareEngineer  [태스크 수신, 분석 결정]
    → CodeAnalyzer    [코드 파악]
      ↕ code_analysis_tool  [도구 반복 호출]
      → Editor        [분석 결과 기반 수정 시작, continue]
        ↕ code_edit_tool    [파일 수정]
        ↕ test_tool         [테스트 실행]
        → CodeAnalyzer  [테스트 실패, 재분석 필요, continue]
          ↕ code_analysis_tool
          → SoftwareEngineer  [done, 분석 결과 보고]
            → Editor    [재수정 지시, edit_file]
              → SoftwareEngineer  [done, 최종 보고]
                → end
```

---

### 핵심 설계 패턴 요약

| 패턴 | 설명 |
|------|------|
| **Supervisor 패턴** | `SoftwareEngineer`가 모든 서브 에이전트를 조율 |
| **양방향 피드백 루프** | `CodeAnalyzer ↔ Editor` 간 `continue`로 반복 개선 |
| **도구 캡슐화** | 각 에이전트는 전용 도구만 사용 (점선 = tool call) |
| **조건부 종료** | `SoftwareEngineer`만 `end`로 진입 가능 — 최종 판단 중앙화 |
