## LangGraph 워크플로우 구조 분석

### 전체 구성 요소

| 구분 | 노드 |
|------|------|
| 진입/종료 | `start`, `end` |
| Agent 노드 | `SoftwareEngineer`, `CodeAnalyzer`, `Editor` |
| Tool 노드 | `swe_tool`, `code_analysis_tool`, `code_edit_tool`, `test_tool` |

---

### 노드별 역할 및 흐름

#### 1. `start` → `SoftwareEngineer`
- 워크플로우의 진입점
- 사용자 요청이 들어오면 가장 먼저 `SoftwareEngineer` 노드로 라우팅됨
- `SoftwareEngineer`는 **중앙 오케스트레이터** 역할을 담당

---

#### 2. `SoftwareEngineer` (메인 의사결정 노드)
워크플로우 전체를 조율하는 핵심 노드. 현재 상태를 판단해 **4가지 경로** 중 하나를 선택:

| 전환 조건 | 목적지 | 설명 |
|-----------|--------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | `Editor` | 파일 편집이 필요한 경우 |
| (직접 라우팅) | `swe_tool` | SWE 전용 도구 직접 호출 |
| (종료 조건) | `end` | 작업 완료 시 종료 |

---

#### 3. `CodeAnalyzer` (코드 분석 서브 에이전트)
`analyze_code` 조건으로 진입하며, **2가지 내부 흐름**을 가짐:

```
CodeAnalyzer ──(tool call)──▶ code_analysis_tool
                ◀────────────── (결과 반환)
```

- **`continue` (자기 루프)**: 분석이 완료되지 않았거나 추가 분석이 필요하면 `code_analysis_tool`을 반복 호출
- **`done` → `SoftwareEngineer`**: 분석 완료 시 결과를 `SoftwareEngineer`에게 반환

---

#### 4. `Editor` (코드 편집 서브 에이전트)
`edit_file` 조건으로 진입하며, **2개의 도구**를 사용하고 **2가지 전환** 가능:

```
Editor ──(edit call)──▶ code_edit_tool
       ◀────────────── (결과 반환)

Editor ──(test call)──▶ test_tool
       ◀────────────── (결과 반환)
```

- **`continue` (자기 루프)**: 편집 후 테스트 실패 또는 추가 수정이 필요한 경우 반복
  - `code_edit_tool`: 실제 파일 수정 수행
  - `test_tool`: 수정 후 테스트 실행 및 검증
- **`done` → `SoftwareEngineer`**: 편집 및 테스트 통과 시 결과 반환

---

#### 5. `swe_tool` (SWE 전용 도구)
- `SoftwareEngineer`가 `CodeAnalyzer`/`Editor`를 거치지 않고 **직접 호출**하는 도구
- 실행 후 **`continue`** 레이블로 다시 `SoftwareEngineer`로 복귀
- 단순 조회나 간단한 작업 처리에 사용될 것으로 추정

---

### 전체 실행 흐름 요약

```
start
  │
  ▼
SoftwareEngineer  ◀─────────────────────────────────────┐
  │                                                      │
  ├─[analyze_code]─▶ CodeAnalyzer ─[continue loop]─┐    │
  │                       │        code_analysis_tool│   │
  │                       └─────────────────────────┘   │
  │                       │                              │
  │                  [done]▼                             │
  │              SoftwareEngineer ──────────────────────▶│
  │                                                      │
  ├─[edit_file]──▶ Editor ──[continue loop]─────────┐    │
  │                  │   code_edit_tool / test_tool   │   │
  │                  └───────────────────────────────┘   │
  │                  │                                    │
  │             [done]▼                                   │
  │          SoftwareEngineer ───────────────────────────▶│
  │                                                      │
  ├─────────────▶ swe_tool                               │
  │                  │ [continue]                        │
  │                  └──────────────────────────────────▶│
  │
  └─[종료 조건]──▶ end
```

---

### 설계 특징

1. **계층적 에이전트 구조**: `SoftwareEngineer`가 전략을 결정하고 하위 에이전트(`CodeAnalyzer`, `Editor`)에게 위임
2. **반복 루프 지원**: 각 서브 에이전트는 `continue` 자기 루프로 도구를 반복 호출 가능 (ReAct 패턴)
3. **집중화된 복귀**: 모든 서브 에이전트는 작업 완료 후 반드시 `SoftwareEngineer`로 복귀 (`done`)
4. **도구 분리**: 분석용(`code_analysis_tool`)과 편집/테스트용(`code_edit_tool`, `test_tool`) 도구가 각 에이전트에 귀속됨
