## LangGraph 워크플로우 노드 흐름 상세 설명

### 노드 구성 개요

| 노드 | 타입 | 역할 |
|---|---|---|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 | 전체 흐름 제어 및 작업 분배 |
| `CodeAnalyzer` | 전문 에이전트 | 코드 분석 담당 |
| `Editor` | 전문 에이전트 | 코드 편집 및 테스트 담당 |
| `swe_tool` | 도구 노드 | 범용 SWE 도구 실행 |
| `end` | 종료점 (filled oval) | 워크플로우 종료 |

---

### 도구 (Tool) 노드

| 도구 | 연결 노드 |
|---|---|
| `code_analysis_tool` | CodeAnalyzer |
| `code_edit_tool` | CodeAnalyzer, Editor (공유) |
| `test_tool` | Editor |

---

### 상세 흐름

#### 1. 시작 → SoftwareEngineer
```
start ──(solid)──► SoftwareEngineer
```
워크플로우가 시작되면 즉시 `SoftwareEngineer` 노드로 진입한다. 이 노드는 전체 작업의 **중앙 오케스트레이터** 역할을 하며, 사용자 요청을 분석하여 다음 행동을 결정한다.

---

#### 2. SoftwareEngineer의 분기 라우팅 (조건부 엣지)

`SoftwareEngineer`는 상태(state)를 평가하여 4가지 방향으로 분기한다:

```
SoftwareEngineer ──(analyze_code)──► CodeAnalyzer
SoftwareEngineer ──(edit_file)──────► Editor
SoftwareEngineer ──────────────────► swe_tool
SoftwareEngineer ──────────────────► end
```

- **`analyze_code`**: 코드 이해가 필요한 경우 → `CodeAnalyzer`로 위임
- **`edit_file`**: 파일 수정이 필요한 경우 → `Editor`로 위임
- **`swe_tool`**: 그 외 SWE 도구 실행이 필요한 경우
- **`end`**: 작업이 완료된 경우 종료

---

#### 3. CodeAnalyzer 서브루프

```
CodeAnalyzer ◄──(continue)──► CodeAnalyzer  (자기 루프)
CodeAnalyzer ──(done)──► SoftwareEngineer
```

**사용 도구:**
- `code_analysis_tool`: 코드 구조, 의존성, 문제점 분석
- `code_edit_tool`: 분석 과정 중 소규모 수정 가능

**흐름:**
1. `SoftwareEngineer`로부터 분석 요청 수신
2. `code_analysis_tool`을 호출하여 코드 탐색/분석
3. 분석이 불완전하면 → `continue`로 자기 자신에게 루프 (추가 분석 반복)
4. 분석 완료 시 → `done`으로 `SoftwareEngineer`에게 결과 반환

---

#### 4. Editor 서브루프

```
Editor ◄──(continue)──► Editor  (자기 루프)
Editor ──(done)──► SoftwareEngineer
```

**사용 도구:**
- `code_edit_tool`: 실제 파일 수정, 코드 작성
- `test_tool`: 수정 후 테스트 실행 및 검증

**흐름:**
1. `SoftwareEngineer`로부터 편집 요청 수신
2. `code_edit_tool`로 코드 수정 수행
3. `test_tool`로 변경 사항 검증
4. 테스트 실패 또는 추가 수정 필요 시 → `continue`로 자기 루프 반복
5. 수정 및 테스트 완료 시 → `done`으로 `SoftwareEngineer`에게 반환

---

#### 5. swe_tool → SoftwareEngineer

```
swe_tool ──(continue)──► SoftwareEngineer
```

`swe_tool`은 단일 실행 후 결과를 `continue` 엣지로 `SoftwareEngineer`에게 다시 반환한다. `SoftwareEngineer`는 이 결과를 바탕으로 다시 분기를 결정한다.

---

### 전체 실행 사이클 요약

```
start
  └──► SoftwareEngineer ◄─────────────────────────────────┐
            │                                               │
            ├──(analyze_code)──► CodeAnalyzer              │
            │                     ├──(continue)──┐         │
            │                     │              ▼         │
            │                     └──────► CodeAnalyzer    │
            │                     └──(done)────────────────┘
            │                                               │
            ├──(edit_file)──► Editor                        │
            │                  ├──(continue)──┐             │
            │                  │              ▼             │
            │                  └──────► Editor              │
            │                  └──(done)────────────────────┘
            │                                               │
            ├──────────────► swe_tool                       │
            │                  └──(continue)────────────────┘
            │
            └──────────────► end
```

### 핵심 설계 패턴

1. **Hub-and-Spoke**: `SoftwareEngineer`가 허브 역할, 모든 에이전트는 결과를 허브로 반환
2. **Self-loop (ReAct 패턴)**: `CodeAnalyzer`와 `Editor` 모두 작업 완료 전까지 자기 루프로 반복 실행
3. **도구 공유**: `code_edit_tool`은 `CodeAnalyzer`와 `Editor` 양쪽에서 접근 가능
4. **조건부 종료**: `SoftwareEngineer`만이 `end`로의 전환 권한을 가짐
