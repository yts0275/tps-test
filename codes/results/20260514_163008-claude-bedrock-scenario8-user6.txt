## LangGraph 워크플로우 노드 흐름 분석

---

### 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | Entry Point | 워크플로우 시작점 |
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node | 코드 편집 전담 에이전트 |
| `swe_tool` | Tool Node | SoftwareEngineer 직접 사용 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |
| `end` | End Node | 워크플로우 종료점 |

---

### 전체 흐름

#### 1. 진입 (`start` → `SoftwareEngineer`)
워크플로우가 시작되면 `SoftwareEngineer` 노드가 가장 먼저 실행된다. 이 노드가 전체 흐름의 **중앙 라우터(hub)** 역할을 한다.

---

#### 2. `SoftwareEngineer`의 조건부 분기 (Conditional Edges)

`SoftwareEngineer`는 현재 상태를 판단하여 4가지 경로 중 하나로 분기한다:

```
SoftwareEngineer
├── analyze_code  → CodeAnalyzer
├── edit_file     → Editor
├── (직접 실행)   → swe_tool
└── (작업 완료)   → end
```

- **`analyze_code`**: 코드 분석이 필요하다고 판단하면 `CodeAnalyzer`로 위임
- **`edit_file`**: 파일 수정이 필요하다고 판단하면 `Editor`로 위임
- **`swe_tool`**: 별도 에이전트 위임 없이 직접 도구를 호출해야 할 때
- **`end`**: 모든 작업이 완료되었다고 판단하면 종료

---

#### 3. `CodeAnalyzer` 서브 루프

```
CodeAnalyzer ⇄ code_analysis_tool  (continue: 도구 결과 처리 반복)
CodeAnalyzer ⇄ code_edit_tool      (필요 시 편집 도구도 활용)
CodeAnalyzer → SoftwareEngineer    (done: 분석 완료 후 복귀)
```

- `CodeAnalyzer`는 `code_analysis_tool`을 호출하고, 결과를 받아 추가 분석이 필요하면 **`continue`** 레이블로 자기 자신으로 다시 돌아오는 루프를 형성
- 분석 과정에서 코드 수정이 병행될 경우 `code_edit_tool`도 호출 가능
- 분석이 완료되면 **`done`** 엣지를 통해 `SoftwareEngineer`로 결과를 반환

---

#### 4. `Editor` 서브 루프

```
Editor ⇄ code_edit_tool   (continue: 편집 결과 처리 반복)
Editor ⇄ test_tool        (continue: 테스트 결과 처리 반복)
Editor → CodeAnalyzer     (continue: 분석이 추가로 필요한 경우)
Editor → SoftwareEngineer (done: 편집 완료 후 복귀)
```

- `Editor`는 `code_edit_tool`로 실제 파일을 수정하고, `test_tool`로 테스트를 실행
- 각 도구의 결과를 받아 추가 작업이 필요하면 **`continue`** 루프로 반복
- 편집 후 코드 분석이 필요하면 `CodeAnalyzer`로 넘길 수도 있음
- 모든 편집/테스트가 완료되면 **`done`** 엣지로 `SoftwareEngineer`에 복귀

---

#### 5. `swe_tool` → `SoftwareEngineer` 복귀

```
swe_tool → SoftwareEngineer  (continue)
```

- `SoftwareEngineer`가 직접 호출한 도구의 실행이 끝나면 **`continue`** 엣지로 `SoftwareEngineer`에 결과를 반환
- `SoftwareEngineer`는 이 결과를 바탕으로 다시 다음 분기를 결정

---

### 전체 실행 시나리오 예시

```
start
  └─► SoftwareEngineer
         │
         ├─[analyze_code]─► CodeAnalyzer
         │                      ├─► code_analysis_tool ─[continue]─► CodeAnalyzer
         │                      └─[done]─────────────────────────────► SoftwareEngineer
         │
         ├─[edit_file]────► Editor
         │                      ├─► code_edit_tool ─[continue]─► Editor
         │                      ├─► test_tool      ─[continue]─► Editor
         │                      └─[done]───────────────────────► SoftwareEngineer
         │
         ├─(직접호출)─────► swe_tool ─[continue]─► SoftwareEngineer
         │
         └─(완료)─────────────────────────────────────────────► end
```

---

### 핵심 설계 패턴 요약

| 패턴 | 설명 |
|------|------|
| **Hub-and-Spoke** | `SoftwareEngineer`가 모든 서브 에이전트를 중앙에서 조율 |
| **Tool Call Loop** | `continue` 엣지로 에이전트-도구 간 반복 실행 구현 |
| **Delegation & Return** | 서브 에이전트는 작업 완료 시 `done`으로 상위 노드에 제어권 반환 |
| **Conditional Routing** | `SoftwareEngineer`의 상태 판단에 따라 동적으로 경로 결정 |
