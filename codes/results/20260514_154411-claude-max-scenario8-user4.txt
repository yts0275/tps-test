## LangGraph 워크플로우 상세 분석

### 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터/라우터 |
| `CodeAnalyzer` | Agent Node | 코드 분석 담당 |
| `Editor` | Agent Node | 코드 편집/테스트 담당 |
| `swe_tool` | Tool Node | SWE 범용 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 실행 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 실행 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |
| `end` | 종료점 (oval) | 워크플로우 종료 |

---

### 엣지 흐름 (실선 = 일반 전이, 점선 = 조건부 전이)

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer`로 진입.

---

#### 2. SoftwareEngineer (중앙 라우터)

`SoftwareEngineer`는 현재 상태를 판단해 5가지 경로로 분기하는 **조건부 엣지(conditional edges)** 를 가진다:

| 조건 | 전이 대상 | 설명 |
|------|-----------|------|
| `analyze_code` | → `CodeAnalyzer` | 코드 분석이 필요한 경우 |
| `edit_file` | → `Editor` | 파일 편집이 필요한 경우 |
| (직접 도구 호출) | → `swe_tool` | 범용 SWE 작업 필요 시 |
| `continue` | → `SoftwareEngineer` (self-loop) | 추가 판단이 필요해 자신을 재호출 |
| (완료 판정) | → `end` | 작업 완료, 종료 |

---

#### 3. CodeAnalyzer 서브그래프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                        |
                              (실선) code_analysis_tool
                                        |
                              code_analysis_tool → CodeAnalyzer (결과 반환)
                                        |
                        ┌──────────────┴──────────────┐
                      continue                        done
                        ↓                              ↓
                  CodeAnalyzer (self-loop)    SoftwareEngineer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 호출하여 실제 분석을 수행
- 분석 결과가 불충분하면 `continue`로 **자기 자신을 재호출** (반복 분석)
- 분석이 완료되면 `done`으로 `SoftwareEngineer`에게 결과 반환

---

#### 4. Editor 서브그래프

```
SoftwareEngineer --edit_file--> Editor
                                   |
                     ┌─────────────┴─────────────┐
              (실선) code_edit_tool          (실선) test_tool
                     |                             |
                     └──────────┬──────────────────┘
                                ↓ (결과 반환)
                             Editor
                                |
                   ┌────────────┴────────────┐
                 continue                   done
                   ↓                         ↓
            Editor (self-loop)       SoftwareEngineer
```

- `Editor`는 **두 가지 도구**를 보유:
  - `code_edit_tool`: 실제 코드 수정 수행
  - `test_tool`: 수정 후 테스트 실행
- 편집/테스트 사이클이 완료되지 않으면 `continue`로 **자기 자신을 재호출**
- 완료되면 `done`으로 `SoftwareEngineer`에게 반환

---

#### 5. swe_tool 흐름

```
SoftwareEngineer → swe_tool
swe_tool --continue--> SoftwareEngineer
```

- 범용 도구 실행 후 항상 `continue` 레이블로 `SoftwareEngineer`로 복귀

---

### 전체 흐름 요약 (대표 시나리오)

```
start
  └→ SoftwareEngineer
         ├─[analyze_code]→ CodeAnalyzer
         │                    └→ code_analysis_tool (분석 수행)
         │                    └→ [continue: 재분석] or [done: 결과 반환]
         │                              └→ SoftwareEngineer
         │
         ├─[edit_file]→ Editor
         │                └→ code_edit_tool (코드 수정)
         │                └→ test_tool (테스트 실행)
         │                └→ [continue: 재편집] or [done: 결과 반환]
         │                              └→ SoftwareEngineer
         │
         ├─[swe_tool]→ swe_tool
         │                └─[continue]→ SoftwareEngineer
         │
         ├─[continue]→ SoftwareEngineer (재판단)
         │
         └─[완료]→ end
```

---

### 설계 패턴 특징

1. **Supervisor 패턴**: `SoftwareEngineer`가 모든 서브에이전트를 조율하는 중앙 라우터 역할
2. **ReAct 루프**: 각 에이전트 노드가 `continue` self-loop를 통해 도구 호출 → 관찰 → 재판단 사이클을 구현
3. **Tool Node 분리**: 실제 실행 로직은 별도 Tool Node(`code_analysis_tool`, `code_edit_tool`, `test_tool`)에 위임하여 에이전트 로직과 실행 로직을 분리
4. **단방향 복귀**: 서브에이전트(`CodeAnalyzer`, `Editor`)는 `done` 조건 달성 시 반드시 `SoftwareEngineer`로 복귀 — 서브에이전트 간 직접 통신 없음
