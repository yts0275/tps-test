---

## LangGraph 워크플로우 노드 흐름 분석

### 노드 구성

**에이전트 노드 (Agent Nodes)** — 보라색 테두리 사각형
| 노드 | 역할 |
|---|---|
| `SoftwareEngineer` | 중앙 오케스트레이터 에이전트 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 |
| `Editor` | 코드 수정 전담 에이전트 |

**툴 노드 (Tool Nodes)** — 연보라 채움 사각형
| 노드 | 역할 |
|---|---|
| `code_analysis_tool` | 정적 분석, 구조 파악 등 코드 분석 도구 |
| `code_edit_tool` | 파일 쓰기/수정 도구 |
| `test_tool` | 테스트 실행 도구 |
| `swe_tool` | 범용 소프트웨어 엔지니어링 도구 |

**제어 노드**
- `start` (타원) — 진입점
- `end` (채움 타원) — 종료점

---

### 엣지 유형
- **실선 화살표**: 무조건적 전이 (unconditional transition)
- **점선 화살표**: 조건부 전이 (conditional routing), 레이블이 라우팅 조건을 나타냄

---

### 전체 흐름 상세 서술

#### 1. 진입 — `start` → `SoftwareEngineer`
워크플로우가 시작되면 실선으로 `SoftwareEngineer` 에이전트가 먼저 활성화된다. 이 노드가 **중앙 의사결정자** 역할을 한다.

---

#### 2. `SoftwareEngineer` 에이전트의 라우팅 분기

`SoftwareEngineer`는 현재 상태(state)를 평가하여 다음 5가지 경로 중 하나로 조건부 분기한다.

| 라우팅 조건 | 목적지 | 설명 |
|---|---|---|
| `analyze_code` | `CodeAnalyzer` | 코드 이해/분석이 필요한 경우 |
| `edit_file` | `Editor` | 코드 수정이 필요한 경우 |
| (직접 연결) | `swe_tool` | 범용 도구 사용이 필요한 경우 |
| (직접 연결) | `end` | 작업이 완료된 경우 종료 |
| `continue` | `SoftwareEngineer` (자기 자신) | 추가 판단이 필요해 루프 |

---

#### 3. `CodeAnalyzer` 서브그래프 흐름

```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer
                                          |
                              ┌───────────┴───────────────┐
                              ↓                           ↓
                    code_analysis_tool             (계속 분석 필요)
                              |                           |
                        [continue]──────────────→ CodeAnalyzer (루프)
                              |
                           [done]
                              ↓
                    SoftwareEngineer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 호출하여 코드를 분석한다.
- 툴 실행 결과가 반환되면 `continue` 조건으로 자기 자신(`CodeAnalyzer`)에게 다시 돌아와 추가 분석을 이어갈 수 있다.
- 분석이 충분히 완료되면 `done` 조건으로 `SoftwareEngineer`에게 결과를 반환한다.
- `CodeAnalyzer` ↔ `Editor` 간의 점선도 존재하여, 분석 중 수정이 필요한 경우 `Editor`로 직접 넘어가는 경로도 있다.

---

#### 4. `Editor` 서브그래프 흐름

```
SoftwareEngineer --[edit_file]--> Editor
                                     |
                     ┌───────────────┼───────────────┐
                     ↓               ↓               ↓
              code_edit_tool      test_tool    (계속 수정 필요)
                     |               |               |
              [continue]──────────────────────→ Editor (루프)
                     |
              [continue]──────────────────────→ CodeAnalyzer
                     |
                  [done]
                     ↓
             SoftwareEngineer
```

- `Editor`는 `code_edit_tool`로 실제 파일을 수정하거나, `test_tool`로 변경 사항을 검증한다.
- 수정 후 테스트가 실패하거나 추가 작업이 필요하면 `continue`로 자기 자신에게 루프한다.
- 수정 결과에 대해 재분석이 필요하면 `continue`로 `CodeAnalyzer`에게 제어권을 넘긴다.
- 수정이 완료되면 `done`으로 `SoftwareEngineer`에게 결과를 반환한다.

---

#### 5. `swe_tool` 흐름

```
SoftwareEngineer ──→ swe_tool
                         |
                     [continue]
                         ↓
                  SoftwareEngineer
```

- `SoftwareEngineer`가 범용 작업(검색, 명령 실행 등)에 `swe_tool`을 직접 호출한다.
- 툴 실행 완료 후 `continue`로 `SoftwareEngineer`로 복귀하여 다음 결정을 내린다.

---

#### 6. 종료 — `end`

`SoftwareEngineer`가 모든 하위 작업이 완료되었다고 판단하면 `end` 노드로 전이하여 워크플로우가 종료된다.

---

### 전체 흐름 요약

```
start
  ↓
SoftwareEngineer ←──────────────────────────────────────────┐
  ├─[analyze_code]→ CodeAnalyzer ↔ code_analysis_tool        │
  │                     ↑  ↕ [continue 루프]                 │
  │                     └──[done]──────────────────────────→ │
  │                                                           │
  ├─[edit_file]──→ Editor ↔ code_edit_tool / test_tool        │
  │                  ├── [continue] → CodeAnalyzer ──────────→│
  │                  └──[done]────────────────────────────→   │
  │                                                           │
  ├─────────────→ swe_tool ──[continue]──────────────────────→┘
  │
  └─────────────→ end
```

**핵심 설계 원칙**: `SoftwareEngineer`가 플래너(Planner)로 중앙에서 작업을 분배하고, `CodeAnalyzer`와 `Editor`는 각자의 전문 영역에서 도구를 사용하며 루프를 돌다가 완료 시 오케스트레이터에게 제어권을 반환하는 **계층적 멀티에이전트 패턴**이다.
