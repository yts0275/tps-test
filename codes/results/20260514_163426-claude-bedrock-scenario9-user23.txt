---

## 워크플로우 전체 구조

### 노드 구성

| 노드 | 유형 | 역할 |
|---|---|---|
| `start` | Entry Point | 워크플로우 시작 |
| `SoftwareEngineer` | Agent Node | 메인 오케스트레이터 LLM |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node | 코드 수정 전담 에이전트 |
| `swe_tool` | Tool Node | SWE 전용 직접 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |
| `end` | Terminal Node | 워크플로우 종료 |

---

## 노드별 흐름 상세

### 1. `start` → `SoftwareEngineer`
워크플로우 진입 시 무조건 `SoftwareEngineer` 로 라우팅됨. 초기 작업 지시/요청을 수신하는 출발점.

---

### 2. `SoftwareEngineer` (핵심 오케스트레이터)

메인 LLM Agent로, 현재 상태를 판단하여 **조건부 엣지**로 분기:

```
SoftwareEngineer
    ├──[analyze_code]──▶ CodeAnalyzer    # 코드 분석이 필요한 경우
    ├──[edit_file]─────▶ Editor          # 코드 수정이 필요한 경우
    ├──────────────────▶ swe_tool        # 직접 SWE 도구 사용
    └──────────────────▶ end             # 작업 완료 판단
```

- 모든 Sub-Agent(`CodeAnalyzer`, `Editor`)와 도구(`swe_tool`)의 결과는 최종적으로 이 노드로 복귀
- `ReAct` 패턴의 중앙 허브 역할

---

### 3. `CodeAnalyzer` ↔ `code_analysis_tool` (분석 루프)

```
CodeAnalyzer ──▶ code_analysis_tool
     ▲                    │
     └──────[continue]────┘
     │
     └──[done]──▶ SoftwareEngineer
```

- `code_analysis_tool`을 반복 호출하며 **분석이 완료될 때까지 루프**
- 도구 실행 결과가 `continue`로 돌아오면 추가 분석 계속 수행
- 분석 완료(`done`) 시 `SoftwareEngineer`로 결과 반환

---

### 4. `Editor` ↔ `code_edit_tool` / `test_tool` (편집 루프)

```
Editor ──▶ code_edit_tool ──[continue]──▶ Editor
Editor ──▶ test_tool      ──[continue]──▶ Editor
Editor ──[continue]──────────────────────▶ CodeAnalyzer  # 편집 후 재분석 필요 시
Editor ──[done]──────────────────────────▶ SoftwareEngineer
```

- 코드 편집(`code_edit_tool`)과 테스트(`test_tool`)를 반복적으로 수행
- 편집 후 결과 검증이 필요하면 `CodeAnalyzer`로 재분석 요청 가능
- 모든 편집/테스트 완료(`done`) 시 `SoftwareEngineer`로 결과 반환

---

### 5. `swe_tool` → `SoftwareEngineer`

```
SoftwareEngineer ──▶ swe_tool ──[continue]──▶ SoftwareEngineer
```

- `SoftwareEngineer`가 직접 호출하는 단일 도구
- 실행 결과를 `continue`로 `SoftwareEngineer`에 반환하여 다음 판단 수행

---

### 6. `end`

`SoftwareEngineer`가 작업 완료를 판단하면 종료 노드로 라우팅되어 워크플로우 종결.

---

## 전체 실행 흐름 시나리오 예시

```
start
  │
  ▼
SoftwareEngineer (작업 수신 및 초기 판단)
  │
  ├─[analyze_code]─▶ CodeAnalyzer
  │                      │ code_analysis_tool 반복 호출
  │                      └─[done]─▶ SoftwareEngineer (분석 결과 수신)
  │
  ├─[edit_file]────▶ Editor
  │                      │ code_edit_tool / test_tool 반복 호출
  │                      │ (필요시 CodeAnalyzer 재호출)
  │                      └─[done]─▶ SoftwareEngineer (편집 결과 수신)
  │
  ├──────────────▶ swe_tool ─[continue]─▶ SoftwareEngineer
  │
  └──────────────▶ end
```

---

## 설계 패턴 요약

이 워크플로우는 **Supervisor + ReAct 혼합 패턴**:

- `SoftwareEngineer`는 **Supervisor** 역할 — 전체 흐름 결정
- `CodeAnalyzer`, `Editor`는 각자 **도구 루프를 가진 Sub-Agent** — 전문 작업 수행
- 점선 엣지는 **도구 호출 루프**, 실선 엣지는 **에이전트 간 라우팅**
