---

## LangGraph 워크플로우 노드 흐름 분석

### 전체 구조 개요

총 **3개의 에이전트 노드**, **3개의 툴 노드**, **1개의 진입점(start)**, **1개의 종료점(end)**으로 구성된 계층형 멀티에이전트 그래프.

---

### 노드 목록

| 노드 | 종류 | 역할 |
|---|---|---|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 에이전트 | 전체 작업 조율 및 라우팅 |
| `CodeAnalyzer` | 서브 에이전트 | 코드 분석 전담 |
| `Editor` | 서브 에이전트 | 코드 편집 및 테스트 전담 |
| `swe_tool` | 툴 노드 | SWE 전용 도구 |
| `code_analysis_tool` | 툴 노드 | 코드 분석 도구 |
| `code_edit_tool` | 툴 노드 | 코드 편집 도구 |
| `test_tool` | 툴 노드 | 테스트 실행 도구 |
| `end` | 종료점 | 워크플로우 종료 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 즉시 `SoftwareEngineer` 노드로 제어가 넘어간다.

---

#### 2. SoftwareEngineer (오케스트레이터)

메인 라우터 역할. 작업 내용에 따라 **4가지 분기**로 조건부 라우팅:

```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer    # 코드 분석이 필요한 경우
SoftwareEngineer --[edit_file]----> Editor           # 파일 편집이 필요한 경우
SoftwareEngineer -(점선)----------> swe_tool         # 직접 SWE 도구 사용
SoftwareEngineer -(점선)----------> end              # 작업 완료 시 종료
```

- **실선 엣지**: 특정 서브 에이전트로 작업을 위임
- **점선 엣지**: 조건부/선택적 전환 (툴 직접 호출 or 종료)

---

#### 3. CodeAnalyzer 서브그래프 내부 루프

`CodeAnalyzer`는 `code_analysis_tool`을 반복 호출하며 ReAct 패턴으로 동작:

```
CodeAnalyzer <--[continue]--> code_analysis_tool   # 도구 호출 ↔ 결과 수신 반복
```

- `continue`: 분석이 아직 완료되지 않아 도구를 계속 호출하는 루프
- 분석이 완료되면 `done` 엣지로 오케스트레이터에 반환:

```
CodeAnalyzer --[done]--> SoftwareEngineer
```

---

#### 4. Editor 서브그래프 내부 루프

`Editor`는 **2개의 툴**을 반복 호출:

```
Editor <--[continue]--> code_edit_tool   # 파일 수정 도구
Editor <--[continue]--> test_tool        # 테스트 실행 도구
```

- 편집 → 테스트 → 재편집의 반복 루프가 가능
- 작업 완료 시:

```
Editor --[done]--> SoftwareEngineer
```

- **추가 경로**: Editor에서 `CodeAnalyzer`로 `continue` 전환도 존재
  - 편집 중 추가 코드 분석이 필요한 경우 `CodeAnalyzer`로 위임 후 다시 결과를 수신

---

#### 5. swe_tool 반환 흐름

```
swe_tool --[continue]--> SoftwareEngineer
```

`SoftwareEngineer`가 직접 호출한 `swe_tool`의 결과가 다시 `SoftwareEngineer`로 반환되어 다음 판단을 수행.

---

#### 6. 종료 흐름

```
SoftwareEngineer --[done]--> end
```

모든 작업이 완료되었다고 판단할 때 `end` 노드로 전환하여 워크플로우 종료.

---

### 전체 실행 시나리오 예시

```
start
 └─► SoftwareEngineer (작업 분석)
       ├─[analyze_code]─► CodeAnalyzer
       │                    ├─[continue]─► code_analysis_tool ─► 반환
       │                    ├─[continue]─► code_analysis_tool ─► 반환  (반복)
       │                    └─[done]─────► SoftwareEngineer
       │
       ├─[edit_file]────► Editor
       │                    ├─[continue]─► code_edit_tool ──► 반환
       │                    ├─[continue]─► test_tool ───────► 반환
       │                    ├─[continue]─► CodeAnalyzer ────► done ─► Editor  (필요 시)
       │                    └─[done]─────► SoftwareEngineer
       │
       ├─(swe_tool)─────► swe_tool
       │                    └─[continue]─► SoftwareEngineer
       │
       └─[done]─────────► end
```

---

### 핵심 설계 패턴 요약

1. **계층적 오케스트레이션**: `SoftwareEngineer`가 전체를 조율하고 전문화된 서브 에이전트에 위임
2. **ReAct 루프**: 각 서브 에이전트(`CodeAnalyzer`, `Editor`)는 툴 호출 → 결과 관찰 → 재호출의 반복 루프 수행
3. **조건부 라우팅**: `done` / `continue` 엣지로 작업 완료 여부에 따라 흐름 분기
4. **크로스 에이전트 협력**: `Editor`가 필요 시 `CodeAnalyzer`를 호출하는 에이전트 간 협업 구조
