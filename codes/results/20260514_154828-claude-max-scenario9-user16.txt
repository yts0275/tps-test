## LangGraph Workflow 노드 흐름 상세 설명

---

### 노드 구성

| 노드 | 종류 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 에이전트 (오케스트레이터) | 전체 흐름 판단 및 라우팅 |
| `CodeAnalyzer` | 에이전트 | 코드 분석 수행 |
| `Editor` | 에이전트 | 코드 편집 수행 |
| `swe_tool` | 도구 노드 | SoftwareEngineer 전용 도구 실행 |
| `code_analysis_tool` | 도구 노드 | CodeAnalyzer가 사용하는 도구 |
| `code_edit_tool` | 도구 노드 | Editor가 코드 수정 시 사용 |
| `test_tool` | 도구 노드 | Editor가 테스트 실행 시 사용 |
| `end` | 종료점 | 워크플로우 종료 |

---

### 전체 흐름

```
start → SoftwareEngineer → (조건 분기)
```

---

### 1. 진입: `start` → `SoftwareEngineer`

워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입한다. 이 노드가 **중앙 오케스트레이터** 역할을 하며, 현재 상태를 평가해 다음 행동을 결정한다.

---

### 2. `SoftwareEngineer` 조건 분기 (4가지 경로)

`SoftwareEngineer`는 상황에 따라 4개의 경로 중 하나를 선택한다.

#### 경로 A: `analyze_code` → `CodeAnalyzer`
- 코드 분석이 필요하다고 판단하면 `CodeAnalyzer`로 라우팅
- **CodeAnalyzer 내부 루프:**
  1. `CodeAnalyzer` → `code_analysis_tool` (`continue`): 분석 도구 실행
  2. `code_analysis_tool` → `CodeAnalyzer` (`continue`): 결과 반환 후 추가 분석 여부 판단
  3. 분석 완료 시 `CodeAnalyzer` → `SoftwareEngineer` (`done`): 결과를 오케스트레이터에 반환

#### 경로 B: `edit_file` → `Editor`
- 파일 편집이 필요하다고 판단하면 `Editor`로 라우팅
- **Editor 내부 루프:**
  1. `Editor` → `code_edit_tool` (`continue`): 코드 수정 도구 실행
  2. `Editor` → `test_tool` (`continue`): 수정 후 테스트 실행
  3. 두 도구 모두 `continue`로 다시 `Editor`로 결과를 반환하며, 필요시 반복
  4. 편집 완료 시 `Editor` → `SoftwareEngineer` (`done`): 결과 반환
- `CodeAnalyzer`와 `Editor`는 `continue` 엣지를 통해 **서로 간에도 연결**되어 있어, Editor가 분석 결과를 참조하거나 분석 후 편집으로 이어지는 흐름도 가능하다.

#### 경로 C: `swe_tool` 직접 실행
- `SoftwareEngineer`가 직접 `swe_tool`을 호출
- `swe_tool` → `SoftwareEngineer` (`continue`): 도구 실행 후 다시 오케스트레이터로 복귀

#### 경로 D: `end`
- 작업이 완전히 완료되었다고 판단하면 `end` 노드로 이동해 워크플로우 종료

---

### 3. 반복 구조 (Re-entry Loop)

`CodeAnalyzer`와 `Editor`가 `done`으로 `SoftwareEngineer`에 반환하면, `SoftwareEngineer`는 다시 조건을 평가하여 **추가 작업이 필요하면 또 다른 노드로 라우팅**하거나, 완료 시 `end`로 이동한다. 즉 `SoftwareEngineer`는 **반복 루프의 허브** 역할을 한다.

---

### 요약 흐름도 (텍스트)

```
start
  └─► SoftwareEngineer ◄────────────────────────────┐
          │                                           │
          ├─[analyze_code]─► CodeAnalyzer ────────────┤(done)
          │                      ↕ (continue)         │
          │                  code_analysis_tool        │
          │                                           │
          ├─[edit_file]────► Editor ──────────────────┤(done)
          │                  ↕(continue) ↕(continue)  │
          │            code_edit_tool  test_tool       │
          │                                           │
          ├──────────────► swe_tool ──────────────────┘(continue)
          │
          └─[complete]─► end
```

---

### 핵심 설계 패턴

- **Supervisor Pattern**: `SoftwareEngineer`가 하위 에이전트(`CodeAnalyzer`, `Editor`)를 조율
- **Tool-Agent Loop**: 각 에이전트는 도구를 `continue` 엣지로 반복 호출하며 작업 완료 시 `done` 반환
- **Conditional Edge**: 모든 분기는 점선(`dashed`)으로 표현되어 있으며, 이는 LangGraph의 조건부 엣지(`conditional_edge`)임을 의미
