## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 에이전트 시스템**으로, `SoftwareEngineer`가 중앙 오케스트레이터 역할을 하며 여러 전문 노드에 작업을 위임하는 구조입니다.

---

### 노드 종류

| 노드 | 역할 | 타입 |
|---|---|---|
| `start` | 워크플로우 진입점 | 시스템 노드 |
| `SoftwareEngineer` | 중앙 오케스트레이터, 작업 분기 결정 | Agent 노드 |
| `CodeAnalyzer` | 코드 분석 수행 | Agent 노드 |
| `Editor` | 파일 편집 및 테스트 수행 | Agent 노드 |
| `swe_tool` | 범용 소프트웨어 엔지니어링 도구 실행 | Tool 노드 |
| `code_analysis_tool` | 코드 분석 전용 도구 | Tool 노드 |
| `code_edit_tool` | 코드 편집 전용 도구 | Tool 노드 |
| `test_tool` | 테스트 실행 도구 | Tool 노드 |
| `end` | 워크플로우 종료 | 시스템 노드 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름 (실선)
```
start → SoftwareEngineer
```
워크플로우 시작 시 즉시 `SoftwareEngineer`로 진입. 조건 없이 항상 실행되는 **무조건 엣지(unconditional edge)**.

---

#### 2. SoftwareEngineer의 조건부 분기 (점선 = conditional edge)

`SoftwareEngineer`는 현재 상태(State)를 분석하여 다음 4가지 중 하나로 분기합니다:

```
SoftwareEngineer ──analyze_code──→ CodeAnalyzer   # 코드 분석이 필요한 경우
SoftwareEngineer ──edit_file────→ Editor           # 파일 수정이 필요한 경우
SoftwareEngineer ──────────────→ swe_tool          # 범용 도구 호출이 필요한 경우
SoftwareEngineer ──────────────→ end               # 작업 완료 시
```

`SoftwareEngineer`가 이 분기를 결정하는 **라우터(router) 역할**을 수행합니다.

---

#### 3. CodeAnalyzer 내부 루프

```
CodeAnalyzer ──→ code_analysis_tool ──continue──→ CodeAnalyzer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 호출하여 코드를 분석합니다.
- 분석이 완료되지 않았거나 추가 분석이 필요하면 **`continue`** 엣지를 통해 자기 자신으로 루프백합니다.
- 분석이 완료되면 **`done`** 엣지로 `SoftwareEngineer`에게 제어권을 반환합니다:

```
CodeAnalyzer ──done──→ SoftwareEngineer
```

---

#### 4. Editor 내부 루프

```
Editor ──→ code_edit_tool ──continue──→ Editor
Editor ──→ test_tool      ──continue──→ Editor
```

- `Editor`는 `code_edit_tool`(파일 편집)과 `test_tool`(테스트 실행) 두 가지 도구를 사용합니다.
- 편집 또는 테스트 후 결과가 만족스럽지 않으면 **`continue`** 루프를 반복합니다 (예: 테스트 실패 → 재편집 → 재테스트).
- 작업 완료 시 **`done`** 엣지로 반환:

```
Editor ──done──→ SoftwareEngineer
```

---

#### 5. swe_tool 흐름

```
SoftwareEngineer ──→ swe_tool ──continue──→ SoftwareEngineer
```

- `swe_tool` 실행 후 **`continue`**로 `SoftwareEngineer`에 결과를 반환합니다.
- `SoftwareEngineer`는 결과를 받아 다음 단계를 재결정합니다.

---

### 전체 실행 흐름 예시

```
start
  └→ SoftwareEngineer (요구사항 파악)
       ├─analyze_code→ CodeAnalyzer
       │                 ├─continue→ code_analysis_tool → CodeAnalyzer (반복)
       │                 └─done───→ SoftwareEngineer
       │
       ├─edit_file──→ Editor
       │               ├─continue→ code_edit_tool → Editor
       │               ├─continue→ test_tool       → Editor (테스트 실패 시 반복)
       │               └─done───→ SoftwareEngineer
       │
       ├────────────→ swe_tool
       │               └─continue→ SoftwareEngineer
       │
       └────────────→ end
```

---

### 핵심 설계 패턴 요약

1. **Hub-and-Spoke 패턴**: `SoftwareEngineer`가 허브로서 모든 결정을 중앙 집중적으로 관리
2. **ReAct 루프**: 각 Agent 노드(`CodeAnalyzer`, `Editor`)가 도구를 호출하고 결과를 관찰한 뒤 재실행 여부를 결정
3. **조건부 라우팅**: 점선 엣지들은 모두 `SoftwareEngineer`의 상태 판단에 따라 동적으로 결정
4. **작업 전문화**: 분석/편집/도구 호출을 별도 노드로 분리하여 단일 책임 원칙 적용
