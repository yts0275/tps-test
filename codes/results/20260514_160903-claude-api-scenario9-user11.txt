## LangGraph Workflow 노드 흐름 상세 설명

---

### 전체 구조 개요

이 워크플로우는 **중앙 오케스트레이터 패턴**으로 설계된 Multi-Agent 시스템이다. `SoftwareEngineer` 노드가 허브 역할을 하며, 작업 유형에 따라 전문 에이전트/도구 노드로 분기한다.

---

### 노드 목록

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | 진입점 | 워크플로우 시작 |
| `SoftwareEngineer` | 오케스트레이터 | 작업 분석 및 라우팅 결정 |
| `CodeAnalyzer` | 에이전트 | 코드 분석 전담 |
| `Editor` | 에이전트 | 파일 편집 전담 |
| `swe_tool` | 도구 노드 | SWE 전용 도구 직접 실행 |
| `end` | 종료점 | 워크플로우 완료 |
| `code_analysis_tool` | 툴 | CodeAnalyzer가 사용하는 코드 분석 도구 |
| `code_edit_tool` | 툴 | Editor가 사용하는 코드 편집 도구 |
| `test_tool` | 툴 | Editor가 사용하는 테스트 실행 도구 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 항상 `SoftwareEngineer` 노드가 먼저 실행된다. 이 노드는 주어진 작업(task/state)을 파악하고 다음 행동을 결정한다.

---

#### 2. SoftwareEngineer의 분기 조건 (조건부 엣지)

`SoftwareEngineer`는 현재 상태를 평가하여 4가지 경로 중 하나를 선택한다:

| 엣지 레이블 | 목적지 | 발동 조건 |
|------------|--------|----------|
| `analyze_code` | `CodeAnalyzer` | 코드 구조·의존성·버그 분석이 필요할 때 |
| `edit_file` | `Editor` | 파일 수정·생성·삭제가 필요할 때 |
| _(레이블 없음)_ | `swe_tool` | SWE 전용 도구를 직접 호출해야 할 때 |
| _(종료 조건)_ | `end` | 모든 작업이 완료되었다고 판단할 때 |

---

#### 3. CodeAnalyzer 서브루프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                        ↕ (dashed)
                                   code_analysis_tool
                                        ↓
                          [continue] 자기 자신 (루프)
                          [done] → SoftwareEngineer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 반복 호출(점선 양방향 화살표)하여 코드를 분석한다.
- 분석이 더 필요하면 `continue` → 자기 자신으로 재실행 (내부 루프).
- 분석이 완료되면 `done` → `SoftwareEngineer`로 결과를 반환한다.

---

#### 4. Editor 서브루프

```
SoftwareEngineer --edit_file--> Editor
                                    ↕ (dashed)
                              code_edit_tool
                              test_tool
                                    ↓
                      [continue] 자기 자신 (루프)
                      [done] → SoftwareEngineer
```

- `Editor`는 `code_edit_tool`로 실제 파일을 수정하고, `test_tool`로 변경 결과를 검증한다.
- 테스트 실패 등으로 추가 수정이 필요하면 `continue` → 자기 자신으로 재실행.
- 편집 및 검증이 완료되면 `done` → `SoftwareEngineer`로 복귀한다.

---

#### 5. swe_tool 경로

```
SoftwareEngineer → swe_tool --continue--> SoftwareEngineer
```

- `SoftwareEngineer`가 직접 단순 도구 호출로 처리 가능한 작업을 `swe_tool`에 위임한다.
- 실행 후 `continue` 엣지로 `SoftwareEngineer`에게 결과를 반환하고, `SoftwareEngineer`가 다음 행동을 재결정한다.

---

#### 6. 종료 흐름

```
SoftwareEngineer → end
```

- `SoftwareEngineer`가 모든 요청 작업이 완료되었다고 판단하면 `end` 노드로 전이하여 워크플로우를 종료한다.

---

### 전체 실행 흐름 시나리오 예시

```
start
  → SoftwareEngineer (작업 파악: "버그 수정 요청")
    → CodeAnalyzer (analyze_code: 관련 코드 분석)
      → code_analysis_tool 호출
      → [continue] 추가 분석
      → code_analysis_tool 재호출
      → [done] 분석 결과 반환
  → SoftwareEngineer (분석 결과 수신, 수정 계획 수립)
    → Editor (edit_file: 코드 수정)
      → code_edit_tool 호출 (파일 수정)
      → test_tool 호출 (테스트 실행)
      → [continue] 테스트 실패, 추가 수정
      → code_edit_tool 재호출
      → test_tool 재호출
      → [done] 수정 완료
  → SoftwareEngineer (결과 확인, 작업 완료 판단)
    → end
```

---

### 핵심 설계 패턴 요약

1. **Hub-and-Spoke**: `SoftwareEngineer`가 모든 라우팅을 담당하며 전체 상태를 인지한다.
2. **Self-loop (내부 루프)**: `CodeAnalyzer`와 `Editor`는 각자의 작업이 끝날 때까지 자기 자신을 반복 실행할 수 있어 복잡한 작업을 단계적으로 처리한다.
3. **Tool Separation**: 각 에이전트는 자신에게 특화된 도구만 접근한다 (관심사 분리).
4. **점선 vs 실선**: 점선은 도구 호출(tool call), 실선/굵은선은 에이전트 간 상태 전이를 의미한다.
