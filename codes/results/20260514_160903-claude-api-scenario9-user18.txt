이미지를 분석해 LangGraph 워크플로우의 노드 흐름을 상세히 설명하겠습니다.

---

## 워크플로우 노드 구조 및 흐름

### 전체 구성

```
start → SoftwareEngineer ↔ CodeAnalyzer ↔ code_analysis_tool
                        ↔ Editor ↔ code_edit_tool
                               ↔ test_tool
                        → swe_tool
                        → end
```

---

### 노드별 상세 설명

#### 1. `start` (진입점)
- 워크플로우의 시작 노드
- 유일한 출력 엣지: `SoftwareEngineer`로 무조건 전이

---

#### 2. `SoftwareEngineer` (중앙 오케스트레이터)
- 전체 워크플로우의 **중심 라우팅 노드**
- 들어오는 엣지:
  - `start`로부터 최초 진입
  - `CodeAnalyzer`로부터 `done` 수신 시 복귀
  - `Editor`로부터 `done` 수신 시 복귀
  - `swe_tool`로부터 `continue` 수신 시 복귀
- 나가는 엣지 (조건부 라우팅):
  | 조건 | 목적지 |
  |------|--------|
  | `analyze_code` | `CodeAnalyzer` |
  | `edit_file` | `Editor` |
  | (직접 도구 호출) | `swe_tool` |
  | 작업 완료 | `end` |

---

#### 3. `CodeAnalyzer` (코드 분석 서브그래프)
- 코드 분석을 담당하는 전문화 노드
- 들어오는 엣지:
  - `SoftwareEngineer`로부터 `analyze_code`
  - `code_analysis_tool`로부터 결과 반환 (루프)
  - `Editor`로부터 `continue` (분석 재요청)
- 나가는 엣지:
  | 조건 | 목적지 |
  |------|--------|
  | 도구 호출 필요 | `code_analysis_tool` |
  | 분석 완료 | `SoftwareEngineer` (`done`) |
  | 추가 분석 필요 | 자기 자신 (`continue` 루프) |

---

#### 4. `code_analysis_tool` (도구 노드)
- `CodeAnalyzer`가 호출하는 실제 코드 분석 도구
- **단방향**: `CodeAnalyzer` → `code_analysis_tool` → `CodeAnalyzer`
- 실행 후 반드시 `CodeAnalyzer`로 결과 반환

---

#### 5. `Editor` (코드 편집 서브그래프)
- 코드 수정 및 테스트를 담당하는 전문화 노드
- 들어오는 엣지:
  - `SoftwareEngineer`로부터 `edit_file`
  - `code_edit_tool`로부터 결과 반환 (루프)
  - `test_tool`로부터 결과 반환 (루프)
- 나가는 엣지:
  | 조건 | 목적지 |
  |------|--------|
  | 편집 도구 호출 | `code_edit_tool` |
  | 테스트 도구 호출 | `test_tool` |
  | 편집 완료 | `SoftwareEngineer` (`done`) |
  | 분석 필요 | `CodeAnalyzer` (`continue`) |
  | 추가 편집 필요 | 자기 자신 (`continue` 루프) |

---

#### 6. `code_edit_tool` (도구 노드)
- `Editor`가 호출하는 실제 파일 편집 도구
- **단방향**: `Editor` → `code_edit_tool` → `Editor`

---

#### 7. `test_tool` (도구 노드)
- `Editor`가 호출하는 테스트 실행 도구
- **단방향**: `Editor` → `test_tool` → `Editor`

---

#### 8. `swe_tool` (도구 노드)
- `SoftwareEngineer`가 직접 호출하는 범용 SWE 도구
- **단방향**: `SoftwareEngineer` → `swe_tool` → `SoftwareEngineer` (`continue`)

---

#### 9. `end` (종료점)
- 워크플로우의 최종 종료 노드 (채워진 보라색 원)
- `SoftwareEngineer`가 모든 작업 완료를 판단했을 때 전이

---

### 전체 실행 흐름 패턴

```
start
  └─→ SoftwareEngineer
        ├─→ [analyze_code] → CodeAnalyzer
        │       ├─→ code_analysis_tool → (루프)
        │       ├─→ [continue] Editor ←→ code_edit_tool / test_tool
        │       └─→ [done] SoftwareEngineer
        │
        ├─→ [edit_file] → Editor
        │       ├─→ code_edit_tool → (루프)
        │       ├─→ test_tool → (루프)
        │       ├─→ [continue] CodeAnalyzer → (분석 후 복귀)
        │       └─→ [done] SoftwareEngineer
        │
        ├─→ swe_tool → [continue] SoftwareEngineer
        │
        └─→ end
```

---

### 설계 특징 요약

| 특징 | 설명 |
|------|------|
| **중앙 집중형 오케스트레이션** | `SoftwareEngineer`가 모든 라우팅 결정 담당 |
| **서브그래프 루프** | `CodeAnalyzer`와 `Editor`가 각각 자체 도구 루프 보유 |
| **양방향 협력** | `CodeAnalyzer` ↔ `Editor` 간 `continue`로 상호 위임 가능 |
| **계층적 도구 접근** | 도구 노드는 전담 서브그래프(또는 메인 노드)를 통해서만 접근 |
| **명시적 종료 조건** | `done` 엣지를 통해 단계 완료를 명시적으로 신호 |
