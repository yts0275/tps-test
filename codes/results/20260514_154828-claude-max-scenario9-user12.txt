## LangGraph 워크플로우 노드 흐름 상세 분석

### 전체 구조 개요

이 그래프는 **소프트웨어 엔지니어링 멀티 에이전트 시스템**으로, `SoftwareEngineer`가 오케스트레이터 역할을 하며 두 개의 전문 에이전트(`CodeAnalyzer`, `Editor`)와 도구들을 조율하는 구조다.

---

### 노드 목록

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` | Entry Point | 그래프 진입 |
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node | 코드 편집/테스트 전담 에이전트 |
| `swe_tool` | Tool Node | SWE 전용 직접 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |
| `end` | Terminal Node | 그래프 종료 |

---

### 상세 흐름

#### 1. 진입 (`start` → `SoftwareEngineer`)
```
start ──────────► SoftwareEngineer
```
- 그래프가 시작되면 무조건 `SoftwareEngineer`로 진입
- 태스크 전체를 파악하고 이후 라우팅을 결정하는 **계획 단계**

---

#### 2. `SoftwareEngineer`의 조건부 라우팅 (핵심 분기점)

`SoftwareEngineer`는 현재 상태를 평가하여 4가지 경로 중 하나를 선택한다:

```
SoftwareEngineer ──analyze_code──► CodeAnalyzer
                 ──edit_file─────► Editor
                 ───────────────► swe_tool
                 ───────────────► end
```

| 엣지 | 조건 | 설명 |
|------|------|------|
| `analyze_code` | 코드 분석이 필요한 경우 | `CodeAnalyzer`에게 위임 |
| `edit_file` | 파일 편집이 필요한 경우 | `Editor`에게 위임 |
| (직접) | 즉각적 도구 사용이 필요한 경우 | `swe_tool` 직접 호출 |
| (직접) | 모든 작업 완료 | `end`로 종료 |

---

#### 3. `CodeAnalyzer` 서브그래프

```
CodeAnalyzer ◄──────────────────────────────────────
     │                                              │ continue (자기 루프)
     ├──(tool call)──► code_analysis_tool ──────────┤
     │                                              │
     └──(tool call)──► code_edit_tool ──────────────┘
     
     └──done──► SoftwareEngineer
```

- **`continue` (자기 루프)**: 분석이 미완료된 경우 자신에게 재진입하여 반복 분석
- **`code_analysis_tool`**: 정적 분석, AST 파싱, 코드 검색 등 수행 후 결과 반환
- **`code_edit_tool`**: 분석 과정에서 필요한 소규모 편집 수행 후 결과 반환
- **`done`**: 분석 완료 시 `SoftwareEngineer`로 결과 보고 후 제어권 반환

---

#### 4. `Editor` 서브그래프

```
Editor ◄───────────────────────────────────────────
     │                                             │ continue (자기 루프)
     ├──(tool call)──► code_edit_tool ─────────────┤
     │                                             │
     └──(tool call)──► test_tool ──────────────────┘
     
     └──done──► SoftwareEngineer
```

- **`continue` (자기 루프)**: 편집→테스트→수정 사이클을 반복 (테스트 실패 시 계속 루프)
- **`code_edit_tool`**: 실제 파일 수정, 코드 삽입/삭제/교체
- **`test_tool`**: 수정된 코드에 대한 테스트 실행 및 결과 피드백
- **`done`**: 편집+검증 완료 시 `SoftwareEngineer`에 결과 보고

---

#### 5. `swe_tool` 처리

```
SoftwareEngineer ──► swe_tool ──continue──► SoftwareEngineer
```

- `SoftwareEngineer`가 직접 사용하는 **범용 SWE 도구**
- 처리 완료 후 `continue` 엣지로 `SoftwareEngineer`에 결과 반환
- `SoftwareEngineer`는 결과를 바탕으로 다시 라우팅 결정

---

#### 6. 종료 (`SoftwareEngineer` → `end`)

```
SoftwareEngineer ──► end
```
- 모든 태스크가 완료되었다고 판단하면 `end`로 전이
- 그래프 실행 완전 종료

---

### 전체 실행 시나리오 예시

```
start
  └─► SoftwareEngineer (태스크 분석: "버그 수정 요청")
        └─[analyze_code]─► CodeAnalyzer
              ├─► code_analysis_tool (버그 위치 파악)
              ├─► (continue: 추가 분석 필요)
              ├─► code_analysis_tool (의존성 확인)
              └─[done]─► SoftwareEngineer (분석 결과 수신)
                    └─[edit_file]─► Editor
                          ├─► code_edit_tool (버그 수정)
                          ├─► test_tool (테스트 실행 → 실패)
                          ├─► (continue: 재수정)
                          ├─► code_edit_tool (재수정)
                          ├─► test_tool (테스트 실행 → 성공)
                          └─[done]─► SoftwareEngineer
                                └─► end
```

---

### 설계 특징 요약

- **실선 엣지**: 에이전트 간 상태 전이 (라우팅 결정)
- **점선 엣지**: 도구 호출 및 결과 반환 (tool call loop)
- **자기 루프(`continue`)**: 각 전문 에이전트가 작업 완료 전까지 반복 수행 가능한 내부 루프
- **`done` 시그널**: 전문 에이전트 → 오케스트레이터로의 제어권 반환 신호
