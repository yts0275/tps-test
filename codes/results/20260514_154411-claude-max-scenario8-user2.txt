이미지를 분석하여 LangGraph 워크플로우의 노드 흐름을 상세히 설명하겠습니다.

---

## 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 에이전트 시스템**으로, 오케스트레이터 노드가 전문화된 하위 노드들에 작업을 위임하는 **계층적 멀티 에이전트 구조**입니다.

---

## 노드 분류

### 에이전트 노드 (보라색 실선 박스)
| 노드 | 역할 |
|------|------|
| `SoftwareEngineer` | 중앙 오케스트레이터. 전체 작업을 판단하고 적절한 하위 에이전트에 위임 |
| `CodeAnalyzer` | 코드 분석 전담. 분석 도구를 호출하고 결과를 상위 노드에 반환 |
| `Editor` | 코드 수정 및 테스트 전담. 편집/테스트 도구를 호출 |

### 도구 노드 (연한 보라색 박스, 점선 연결)
| 노드 | 역할 |
|------|------|
| `code_analysis_tool` | 실제 코드 정적 분석 실행 |
| `code_edit_tool` | 실제 파일 수정 실행 |
| `test_tool` | 테스트 실행 |
| `swe_tool` | SoftwareEngineer 전용 범용 도구 |

### 진입/종료 노드
| 노드 | 역할 |
|------|------|
| `start` | 워크플로우 시작점 |
| `end` | 워크플로우 종료점 (채워진 보라 원) |

---

## 엣지 흐름 상세

### 1. `start` → `SoftwareEngineer`
워크플로우가 시작되면 무조건 `SoftwareEngineer`로 진입. 이 노드가 전체 작업의 **판단 허브** 역할을 함.

---

### 2. `SoftwareEngineer`의 조건부 분기 (실선)

```
SoftwareEngineer
  ├─[analyze_code]──→ CodeAnalyzer
  ├─[edit_file]────→ Editor
  ├─────────────────→ swe_tool
  └─[done]─────────→ end
```

- **`analyze_code`**: 코드 분석이 필요하다고 판단하면 `CodeAnalyzer`로 라우팅
- **`edit_file`**: 파일 수정이 필요하다고 판단하면 `Editor`로 라우팅
- **`swe_tool`**: SoftwareEngineer 자체가 도구를 직접 호출해야 할 경우 (범용 작업)
- **`done`**: 모든 작업이 완료되었다고 판단하면 `end`로 종료

---

### 3. `CodeAnalyzer`의 흐름

```
CodeAnalyzer
  ├─(점선)──→ code_analysis_tool ──(점선)──→ (CodeAnalyzer로 반환)
  ├─(점선)──→ code_edit_tool     ──(점선)──→ (CodeAnalyzer로 반환)
  └─[done]──→ SoftwareEngineer
```

- `code_analysis_tool`과 `code_edit_tool`을 **도구 호출(tool call)** 방식으로 사용 (점선)
- 도구 실행 결과를 받아 처리한 후 **`done`** 조건으로 `SoftwareEngineer`에 결과 반환
- `Editor`로부터 **`continue`** 신호를 받아 재진입할 수도 있음 (양방향성)

---

### 4. `Editor`의 흐름

```
Editor
  ├─(점선)──→ code_edit_tool ──(점선)──→ (Editor로 반환)
  ├─(점선)──→ test_tool      ──(점선)──→ (Editor로 반환)
  ├─[continue]─(점선)──→ CodeAnalyzer   (재분석 요청)
  └─[done]──→ SoftwareEngineer
```

- `code_edit_tool`로 실제 파일 수정을 수행
- `test_tool`로 수정 후 테스트를 실행
- 테스트 결과 분석이 더 필요하면 **`continue`** 조건으로 `CodeAnalyzer`에 재위임
- 작업이 완료되면 **`done`** 으로 `SoftwareEngineer`에 반환

---

### 5. `swe_tool` → `SoftwareEngineer` (`continue`)

`swe_tool` 실행 후 **`continue`** 엣지로 `SoftwareEngineer`에 제어권 반환. 이후 `SoftwareEngineer`는 다음 액션을 다시 판단함.

---

## 전형적인 실행 시나리오

### 시나리오 A: 코드 분석 후 수정
```
start
  → SoftwareEngineer (작업 판단)
  → [analyze_code] CodeAnalyzer
      → code_analysis_tool (분석 실행)
      → [done] SoftwareEngineer (분석 결과 보고)
  → [edit_file] Editor
      → code_edit_tool (수정 실행)
      → test_tool (테스트 실행)
      → [done] SoftwareEngineer (수정 완료 보고)
  → [done] end
```

### 시나리오 B: 수정 후 재분석이 필요한 경우
```
SoftwareEngineer
  → Editor
      → code_edit_tool
      → test_tool (테스트 실패)
      → [continue] CodeAnalyzer (재분석 요청)
          → code_analysis_tool
          → [done] SoftwareEngineer
  → [edit_file] Editor (재수정)
  ...
```

## 핵심 설계 패턴 요약

| 패턴 | 설명 |
|------|------|
| **오케스트레이터-워커** | `SoftwareEngineer`가 중심에서 모든 흐름을 통제 |
| **조건부 라우팅** | 실선 엣지 + 레이블로 현재 상태에 따라 다른 노드로 분기 |
| **도구 호출 루프** | 점선 엣지로 도구 호출 → 결과 반환 → 노드 재실행 |
| **노드 간 협업** | `Editor` ↔ `CodeAnalyzer` 간 `continue` 엣지로 상호 위임 가능 |
| **명확한 종료 조건** | `done` 레이블이 있는 엣지만이 `end` 또는 상위 노드로 복귀 가능 |
