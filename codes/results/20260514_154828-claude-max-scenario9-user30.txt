## LangGraph Workflow 상세 분석

### 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 자동화 멀티 에이전트 시스템**으로, 중앙 오케스트레이터(`SoftwareEngineer`)가 전문화된 서브 에이전트들을 조율하는 구조다.

---

### 노드 목록

| 노드/도구 | 유형 | 역할 |
|---|---|---|
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 |
| `Editor` | Agent Node | 파일 편집 전담 |
| `swe_tool` | Tool Node | SWE 범용 도구 |
| `code_analysis_tool` | Tool Node | 코드 분석 도구 |
| `code_edit_tool` | Tool Node | 코드 편집 도구 |
| `test_tool` | Tool Node | 테스트 실행 도구 |

---

### 엣지(Edge) 흐름 상세

#### 1. 진입점: `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 무조건 `SoftwareEngineer`로 진입
- 실선(unconditional edge)으로 표시됨

---

#### 2. `SoftwareEngineer` (중앙 오케스트레이터)

`SoftwareEngineer`는 현재 상태를 평가하여 다음 4가지 경로 중 하나를 선택하는 **조건부 라우터** 역할을 한다.

```
SoftwareEngineer
  ├─[analyze_code]──► CodeAnalyzer   (코드 분석이 필요한 경우)
  ├─[edit_file]─────► Editor         (파일 편집이 필요한 경우)
  ├─────────────────► swe_tool       (범용 SWE 작업이 필요한 경우)
  └─────────────────► end            (작업 완료 판단 시)
```

---

#### 3. `CodeAnalyzer` 서브그래프

`CodeAnalyzer`는 내부적으로 도구를 호출하는 **ReAct 루프**를 가진다.

```
CodeAnalyzer
  ├─────────────────► code_analysis_tool  (코드 분석 실행)
  │                         │
  │                   [결과 반환]
  │◄────────────────────────┘
  │
  ├─[done]──────────► SoftwareEngineer   (분석 완료 후 오케스트레이터로 복귀)
  └─[continue]──────► Editor             (분석 후 바로 편집 단계로 전환)
```

- `code_analysis_tool`과의 관계는 양방향 점선으로, **도구 호출 → 결과 수신**의 ReAct 패턴
- `done`: 분석 결과를 `SoftwareEngineer`에게 보고하고 다음 지시를 기다림
- `continue`: 분석 결과에 따라 즉시 편집 작업으로 이동 (오케스트레이터 우회)

---

#### 4. `Editor` 서브그래프

`Editor`는 두 가지 도구를 활용하며 더 복잡한 내부 루프를 가진다.

```
Editor
  ├─────────────────► code_edit_tool     (실제 파일 수정)
  ├─────────────────► test_tool          (수정 후 테스트 실행)
  │
  ├─[done]──────────► SoftwareEngineer   (편집 완료 후 오케스트레이터로 복귀)
  └─[continue]──────► CodeAnalyzer       (편집 후 재분석 필요 시)
```

- `code_edit_tool`: 코드를 실제로 수정
- `test_tool`: 수정 결과를 검증
- `done`: 편집 완료를 `SoftwareEngineer`에게 보고
- `continue`: 편집 후 결과를 `CodeAnalyzer`에게 넘겨 재검증 요청

---

#### 5. `swe_tool` 노드

```
SoftwareEngineer ──► swe_tool
                         │
                  [continue]
                         │
                         ▼
                  SoftwareEngineer
```

- `SoftwareEngineer`가 직접 범용 SWE 도구를 실행
- 완료 후 `continue` 엣지로 반드시 `SoftwareEngineer`로 복귀

---

#### 6. 종료: `SoftwareEngineer` → `end`

- `SoftwareEngineer`가 작업이 완전히 완료되었다고 판단할 때 `end`로 라우팅
- 점선(conditional edge)으로 표시됨

---

### 전체 실행 흐름 예시

```
start
  │
  ▼
SoftwareEngineer  ─[analyze_code]──►  CodeAnalyzer
      ▲                                    │ [code_analysis_tool 호출/반환]
      │                                    │
      │◄──────────────[done]───────────────┤
      │                                    │ [continue]
      │                                    ▼
      │                                 Editor
      │                            [code_edit_tool / test_tool 호출]
      │                                    │
      │◄──────────────[done]───────────────┤
      │
      ├─[swe_tool]──► swe_tool ──[continue]──► (다시 SoftwareEngineer)
      │
      └─[완료 판단]──► end
```

---

### 핵심 설계 패턴

1. **오케스트레이터-서브에이전트 패턴**: `SoftwareEngineer`가 모든 흐름을 통제
2. **ReAct 루프**: `CodeAnalyzer`, `Editor` 각각 내부에서 도구 호출 반복 가능
3. **에이전트 간 직접 전환**: `CodeAnalyzer ↔ Editor` 간 `continue` 엣지로 오케스트레이터를 거치지 않는 단축 경로 존재 (효율성 최적화)
4. **조건부 라우팅**: 모든 주요 엣지가 점선(dashed)으로 표시되어 상태에 따른 동적 라우팅임을 나타냄
