## LangGraph 워크플로우 노드 흐름 상세 서술

### 전체 구조 개요

이 그래프는 **SoftwareEngineer**를 중심 오케스트레이터로 하는 계층적 멀티에이전트 워크플로우입니다. 실선은 상태 전이(state transition), 점선은 도구 호출(tool call) 루프를 나타냅니다.

---

### 노드 목록

| 노드 | 역할 | 타입 |
|---|---|---|
| `start` | 진입점 | Entry |
| `SoftwareEngineer` | 중앙 오케스트레이터 | Agent |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 | Agent |
| `Editor` | 코드 편집/테스트 전담 에이전트 | Agent |
| `swe_tool` | SoftwareEngineer 전용 도구 | Tool |
| `code_analysis_tool` | CodeAnalyzer 전용 분석 도구 | Tool |
| `code_edit_tool` | Editor 전용 편집 도구 | Tool |
| `test_tool` | Editor 전용 테스트 도구 | Tool |
| `end` | 종료점 | Terminal |

---

### 흐름 상세

#### 1. 진입: `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 가장 먼저 `SoftwareEngineer` 노드로 진입합니다.
- `SoftwareEngineer`는 작업 전체를 이해하고 **다음 행동을 결정하는 라우터** 역할을 합니다.

---

#### 2. `SoftwareEngineer` 의 분기 결정 (조건부 엣지)

`SoftwareEngineer`는 현재 상태를 판단하여 4가지 경로 중 하나를 선택합니다:

**경로 A — `analyze_code` → `CodeAnalyzer`**
- 코드를 분석해야 한다고 판단하면 `CodeAnalyzer` 노드에 작업을 위임합니다.

**경로 B — `edit_file` → `Editor`**
- 파일을 수정해야 한다고 판단하면 `Editor` 노드에 작업을 위임합니다.

**경로 C — `continue` → `swe_tool` (자기 루프)**
- `SoftwareEngineer` 자신이 직접 도구(`swe_tool`)를 호출해야 할 경우 도구를 실행한 후 **자신에게 다시 돌아와** 상태를 갱신하고 다음 결정을 반복합니다.

**경로 D — `end`**
- 모든 작업이 완료되었다고 판단하면 워크플로우를 종료합니다.

---

#### 3. `CodeAnalyzer` 내부 루프

```
SoftwareEngineer --analyze_code--> CodeAnalyzer
                                       ↕ continue (도구 호출 루프)
                                  code_analysis_tool
                                       |
                                    done
                                       ↓
                                  SoftwareEngineer
```

- `CodeAnalyzer`는 `code_analysis_tool`을 반복 호출하며 코드를 분석합니다 (`continue` 루프).
- 분석이 완료되면 `done` 엣지를 통해 결과를 `SoftwareEngineer`에게 반환합니다.
- 이때 `CodeAnalyzer`와 `Editor` 사이에도 `continue` 엣지가 존재하여, 분석 과정 중 편집이 필요한 경우 `Editor`를 직접 호출할 수도 있습니다.

---

#### 4. `Editor` 내부 루프

```
SoftwareEngineer --edit_file--> Editor
                                    ↕ continue (도구 호출 루프)
                             code_edit_tool / test_tool
                                    |
                                  done
                                    ↓
                               SoftwareEngineer
```

- `Editor`는 `code_edit_tool`로 파일을 수정하고, `test_tool`로 테스트를 실행합니다.
- 두 도구를 번갈아 호출하며 **수정 → 테스트 → 재수정** 사이클을 반복할 수 있습니다 (`continue` 루프).
- 편집 및 테스트가 완료되면 `done` 엣지를 통해 `SoftwareEngineer`에게 제어권을 반환합니다.

---

### 전체 흐름 요약

```
start
  └─► SoftwareEngineer ─── continue ──► swe_tool
            │                                 │ (루프)
            │◄────────────────────────────────┘
            │
            ├─ analyze_code ──► CodeAnalyzer ─── continue ──► code_analysis_tool
            │                       │  ↕                            │ (루프)
            │                       │  └────────────────────────────┘
            │◄──────── done ─────────┘
            │
            ├─ edit_file ──► Editor ─── continue ──► code_edit_tool
            │                   │                         │
            │                   │       continue ──► test_tool
            │                   │                         │ (루프)
            │◄─────── done ──────┘
            │
            └─► end
```

---

### 핵심 설계 패턴

1. **계층적 위임(Hierarchical Delegation)**: `SoftwareEngineer`가 판단하고, 전문 에이전트(`CodeAnalyzer`, `Editor`)가 실행합니다.
2. **도구 루프(Tool Loop)**: 각 에이전트는 `continue` 신호로 도구를 반복 호출하며 내부 상태를 누적합니다.
3. **결과 복귀(Done Signal)**: 하위 에이전트가 `done`을 반환하면 오케스트레이터가 다시 전체 상태를 재평가합니다.
4. **자기 복귀 루프(Self-loop)**: `SoftwareEngineer` 자신도 `swe_tool`을 직접 활용할 수 있어 유연성을 확보합니다.
