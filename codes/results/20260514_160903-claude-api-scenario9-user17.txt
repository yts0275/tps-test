## LangGraph Workflow 상세 분석

### 노드 구성

| 노드 | 타입 | 역할 |
|------|------|------|
| `start` | 진입점 (oval) | 워크플로우 시작 |
| `SoftwareEngineer` | Agent 노드 | 중앙 오케스트레이터 |
| `CodeAnalyzer` | Agent 노드 | 코드 분석 담당 |
| `Editor` | Agent 노드 | 코드 편집 담당 |
| `swe_tool` | Tool 노드 | 범용 소프트웨어 엔지니어링 도구 |
| `code_analysis_tool` | Tool 노드 | 코드 분석 전용 도구 |
| `code_edit_tool` | Tool 노드 | 코드 편집 전용 도구 |
| `test_tool` | Tool 노드 | 테스트 실행 도구 |
| `end` | 종료점 (filled circle) | 워크플로우 종료 |

---

### 엣지 흐름 (실선 = 상태 전이, 점선 = 조건부/도구 호출)

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
워크플로우가 시작되면 무조건 `SoftwareEngineer` 노드로 진입한다.

---

#### 2. SoftwareEngineer (중앙 오케스트레이터)

`SoftwareEngineer`는 현재 상태를 평가하여 다음 4가지 경로 중 하나를 선택하는 **라우터** 역할을 한다:

| 조건 | 목적지 | 엣지 레이블 |
|------|--------|-------------|
| 코드 분석이 필요할 때 | `CodeAnalyzer` | `analyze_code` |
| 파일 편집이 필요할 때 | `Editor` | `edit_file` |
| 기타 도구 사용이 필요할 때 | `swe_tool` | (레이블 없음) |
| 작업 완료 판단 시 | `end` | (레이블 없음) |

---

#### 3. CodeAnalyzer 서브그래프

```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer
    CodeAnalyzer <--[continue]--> code_analysis_tool  (반복 루프)
    CodeAnalyzer --[done]--> SoftwareEngineer
```

- `CodeAnalyzer`는 분석 작업 중 `code_analysis_tool`을 반복 호출할 수 있다 (`continue` 루프).
- 분석이 완료되면 `done` 엣지를 통해 결과를 `SoftwareEngineer`에 반환한다.
- `CodeAnalyzer` ↔ `code_analysis_tool` 간의 **자기 순환(self-loop)** 구조는 다단계 분석(예: 파일 여러 개 순차 분석)을 지원한다.

---

#### 4. Editor 서브그래프

```
SoftwareEngineer --[edit_file]--> Editor
    Editor <--[continue]--> code_edit_tool  (반복 루프)
    Editor <--[continue]--> test_tool       (반복 루프)
    Editor <--[continue]--> CodeAnalyzer    (분석 요청 가능)
    Editor --[done]--> SoftwareEngineer
```

- `Editor`는 편집 작업 중 `code_edit_tool`로 실제 파일을 수정하고, `test_tool`로 변경사항을 즉시 검증할 수 있다.
- `Editor` → `CodeAnalyzer` → `Editor`로 이어지는 경로도 존재하여, 편집 중 코드 분석이 추가로 필요한 경우 `CodeAnalyzer`에 요청 후 결과를 받아 편집을 이어갈 수 있다.
- 모든 편집 및 검증이 완료되면 `done` 엣지로 `SoftwareEngineer`에 반환한다.

---

#### 5. swe_tool 처리

```
SoftwareEngineer --> swe_tool --[continue]--> SoftwareEngineer
```

- `swe_tool`은 `CodeAnalyzer`나 `Editor`에 해당하지 않는 범용 작업(예: 파일 검색, 빌드 실행 등)을 처리한다.
- 처리 후 `continue` 엣지로 `SoftwareEngineer`에 결과를 반환한다.

---

#### 6. 종료 흐름

```
SoftwareEngineer --> end
```

`SoftwareEngineer`가 모든 작업이 완료되었다고 판단하면 `end` 노드로 전이하여 워크플로우를 종료한다.

---

### 전체 제어 흐름 요약

```
start
  └─▶ SoftwareEngineer (계획 수립 및 라우팅)
        ├─[analyze_code]─▶ CodeAnalyzer ⟷ code_analysis_tool
        │                        └─[done]─▶ SoftwareEngineer
        │
        ├─[edit_file]───▶ Editor ⟷ code_edit_tool
        │                  Editor ⟷ test_tool
        │                  Editor ─▶ CodeAnalyzer ─▶ Editor
        │                        └─[done]─▶ SoftwareEngineer
        │
        ├──────────────▶ swe_tool
        │                    └─[continue]─▶ SoftwareEngineer
        │
        └──────────────▶ end
```

---

### 핵심 설계 패턴

1. **Hub-and-Spoke**: `SoftwareEngineer`가 허브로서 모든 서브 에이전트를 조율한다.
2. **ReAct Loop**: 각 Agent 노드(CodeAnalyzer, Editor)가 도구를 반복 호출하며 관찰-추론-행동 사이클을 수행한다.
3. **계층적 위임**: 상위 에이전트(SoftwareEngineer)가 전문 하위 에이전트(CodeAnalyzer, Editor)에게 작업을 위임하고 결과를 취합한다.
4. **동적 라우팅**: `SoftwareEngineer`는 매 반환 시점마다 다음 액션을 다시 결정하므로, 동일 서브 에이전트를 여러 번 반복 호출하는 것도 가능하다.
