## LangGraph 워크플로우 노드 흐름 상세 분석

### 노드 구성

| 노드 | 유형 | 역할 |
|------|------|------|
| `start` | Entry Point | 워크플로우 진입점 |
| `SoftwareEngineer` | Orchestrator Agent | 중앙 조율자, 작업 분배 및 판단 |
| `CodeAnalyzer` | Sub-Agent | 코드 분석 전담 |
| `Editor` | Sub-Agent | 코드 편집/테스트 전담 |
| `swe_tool` | Tool Node | SoftwareEngineer 전용 도구 |
| `code_analysis_tool` | Tool Node | CodeAnalyzer 전용 분석 도구 |
| `code_edit_tool` | Tool Node | Editor 전용 편집 도구 |
| `test_tool` | Tool Node | Editor 전용 테스트 도구 |
| `end` | Terminal Node | 워크플로우 종료 |

---

### 전체 흐름

```
start
  └─► SoftwareEngineer ◄────────────────────────────────┐
          │                                               │
          ├─[analyze_code]──► CodeAnalyzer               │
          │                       │◄──[continue]──┐      │
          │                       │               │      │
          │                  code_analysis_tool ──┘      │
          │                       │                      │
          │                    [done]────────────────────┤
          │                                              │
          ├─[edit_file]──────► Editor                    │
          │                      │◄──[continue]──┐       │
          │                      │               │       │
          │               code_edit_tool ────────┤       │
          │               test_tool ─────────────┘       │
          │                      │                       │
          │                   [done]─────────────────────┘
          │
          ├─────────────────► swe_tool
          │                       │
          │                  [continue]──────────────────►(SoftwareEngineer로 복귀)
          │
          └─────────────────► end
```

---

### 노드별 상세 흐름

#### 1. `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 즉시 `SoftwareEngineer` 노드로 진입
- 이 노드가 전체 작업의 **중앙 조율자(Orchestrator)** 역할 수행

---

#### 2. `SoftwareEngineer` — 분기 판단 (Conditional Edge)
4가지 경로 중 하나를 선택:

| 전환 조건 | 이동 대상 | 의미 |
|-----------|-----------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 구조/의도 분석이 필요한 경우 |
| `edit_file` | `Editor` | 파일 수정이 필요한 경우 |
| (묵시적) | `swe_tool` | SoftwareEngineer 스스로 도구 직접 사용 |
| (묵시적) | `end` | 모든 작업 완료 판단 |

---

#### 3. `CodeAnalyzer` 서브그래프 (내부 루프)

```
CodeAnalyzer
    │
    ├─[tool call, 점선]──► code_analysis_tool
    │                            │
    │                      (결과 반환)
    │                            │
    │◄───────────────────────────┘
    │
    ├─[continue] 조건: 분석 미완료 → 자기 자신으로 루프
    │
    └─[done] 조건: 분석 완료 → SoftwareEngineer로 복귀
```

- `code_analysis_tool`을 반복 호출하며 코드를 분석
- 분석이 충분하지 않으면 `continue` 엣지로 **자기 자신을 재실행**
- 분석 완료 시 `done` 엣지로 결과를 가지고 `SoftwareEngineer`에 복귀

---

#### 4. `Editor` 서브그래프 (내부 루프)

```
Editor
    │
    ├─[tool call, 점선]──► code_edit_tool   (파일 수정)
    │
    ├─[tool call, 점선]──► test_tool        (테스트 실행)
    │
    ├─[continue] 조건: 수정/테스트 미완료 → 자기 자신으로 루프
    │
    └─[done] 조건: 편집+테스트 완료 → SoftwareEngineer로 복귀
```

- `code_edit_tool`로 실제 코드를 수정하고, `test_tool`로 테스트를 실행
- 테스트 실패 또는 추가 수정 필요 시 `continue`로 **반복 루프**
- 수정 완료 및 테스트 통과 시 `done`으로 `SoftwareEngineer`에 복귀

---

#### 5. `swe_tool` — SoftwareEngineer 직속 도구
- `SoftwareEngineer`가 하위 에이전트에 위임하지 않고 **직접 도구를 사용**하는 경우
- 작업 완료 후 `continue` 엣지로 다시 `SoftwareEngineer`로 복귀하여 다음 판단 수행

---

#### 6. `end` — 종료
- `SoftwareEngineer`가 모든 작업이 완료되었다고 판단할 때 진입
- 워크플로우 완전 종료

---

### 핵심 설계 패턴 요약

1. **Orchestrator-Worker 패턴**: `SoftwareEngineer`가 중앙 조율자로, 전문화된 서브에이전트(`CodeAnalyzer`, `Editor`)에 작업을 위임
2. **Tool-Call 루프**: 각 서브에이전트는 자신의 전용 도구를 반복 호출하며 작업을 완료할 때까지 내부 루프를 돌음 (점선 엣지 = 도구 호출)
3. **ReAct 패턴**: 각 노드가 도구 호출 → 결과 관찰 → 다음 행동 결정의 싸이클을 반복
4. **중앙 복귀 구조**: 모든 서브에이전트와 도구는 최종적으로 `SoftwareEngineer`로 복귀하여 다음 작업을 재판단
