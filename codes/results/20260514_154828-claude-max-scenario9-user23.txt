## LangGraph Workflow 노드 흐름 상세 분석

---

### 전체 구조 개요

이 워크플로우는 **소프트웨어 엔지니어링 에이전트 시스템**으로, 코드 분석과 편집을 담당하는 서브 에이전트들을 중앙 오케스트레이터가 조율하는 구조다.

---

### 노드별 역할

| 노드 | 종류 | 역할 |
|------|------|------|
| `SoftwareEngineer` | Agent Node | 중앙 오케스트레이터. 작업을 판단하고 서브 에이전트에 위임 |
| `CodeAnalyzer` | Agent Node | 코드 분석 전담 에이전트 |
| `Editor` | Agent Node | 코드 편집 및 테스트 전담 에이전트 |
| `swe_tool` | Tool Node | SoftwareEngineer가 직접 사용하는 도구 |
| `code_analysis_tool` | Tool Node | CodeAnalyzer가 사용하는 코드 분석 도구 |
| `code_edit_tool` | Tool Node | Editor가 사용하는 코드 편집 도구 |
| `test_tool` | Tool Node | Editor가 사용하는 테스트 실행 도구 |

---

### 흐름 상세 서술

#### 1. 진입점: `start` → `SoftwareEngineer`
- 워크플로우가 시작되면 **항상** `SoftwareEngineer` 노드로 진입한다 (단방향 고정 엣지).
- `SoftwareEngineer`는 전달받은 작업을 분석하고, 다음 4가지 중 하나를 선택한다 (조건부 분기).

---

#### 2. 분기 1: `SoftwareEngineer` → `CodeAnalyzer` (`analyze_code`)
- **조건:** 코드 분석이 필요하다고 판단될 때 `analyze_code` 엣지로 라우팅.
- `CodeAnalyzer` 내부 루프:
  1. `CodeAnalyzer`는 `code_analysis_tool`을 호출해 실제 분석 수행.
  2. 분석 결과를 받아 추가 분석이 필요하면 → **`continue`** 엣지로 자기 자신(`CodeAnalyzer`)에게 루프백.
  3. 분석이 완료되면 → **`done`** 엣지로 `SoftwareEngineer`에게 결과 반환.

```
SoftwareEngineer
    ↓ analyze_code
CodeAnalyzer ⇄ code_analysis_tool
    ↓ continue (반복)
CodeAnalyzer
    ↓ done
SoftwareEngineer
```

---

#### 3. 분기 2: `SoftwareEngineer` → `Editor` (`edit_file`)
- **조건:** 코드 편집이 필요하다고 판단될 때 `edit_file` 엣지로 라우팅.
- `Editor` 내부 루프:
  1. `Editor`는 `code_edit_tool`로 파일 편집 또는 `test_tool`로 테스트 실행.
  2. 두 도구 모두 결과를 `Editor`로 반환하며, 추가 작업이 필요하면 → **`continue`** 엣지로 자기 자신에게 루프백.
  3. 편집/테스트가 완료되면 → **`done`** 엣지로 `SoftwareEngineer`에게 결과 반환.

```
SoftwareEngineer
    ↓ edit_file
Editor ⇄ code_edit_tool
      ⇄ test_tool
    ↓ continue (반복)
Editor
    ↓ done
SoftwareEngineer
```

---

#### 4. 분기 3: `SoftwareEngineer` → `swe_tool`
- **조건:** `SoftwareEngineer`가 외부 도구를 직접 사용해야 할 때.
- `swe_tool` 실행 후 → **`continue`** 엣지로 `SoftwareEngineer`에게 결과 반환.
- 결과를 바탕으로 `SoftwareEngineer`가 다시 다음 행동을 결정한다.

```
SoftwareEngineer
    ↓
swe_tool
    ↓ continue
SoftwareEngineer
```

---

#### 5. 분기 4: `SoftwareEngineer` → `end`
- **조건:** 작업이 완전히 완료됐다고 판단될 때.
- 워크플로우가 종료된다.

---

### 핵심 설계 패턴

1. **Hub-and-Spoke 구조:** `SoftwareEngineer`가 중앙 허브 역할을 하며, 모든 서브 에이전트의 결과가 다시 `SoftwareEngineer`로 귀환한다.

2. **서브 에이전트 내부 자율 루프:** `CodeAnalyzer`와 `Editor`는 `continue` 엣지를 통해 완료 전까지 자율적으로 반복 실행할 수 있다. `SoftwareEngineer`의 개입 없이 독립적으로 작업을 심화할 수 있다.

3. **점선 엣지 = 조건부 분기:** 도표의 모든 점선 화살표는 LLM이 런타임에 결정하는 조건부 엣지(Conditional Edge)를 나타낸다.

4. **도구 노드의 단방향성:** `code_analysis_tool`, `code_edit_tool`, `test_tool`, `swe_tool`은 모두 단순 실행 후 즉시 부모 에이전트로 결과를 반환하는 역할만 한다.
