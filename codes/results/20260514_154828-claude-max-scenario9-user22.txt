## LangGraph Workflow 노드 흐름 상세 설명

### 전체 구조 개요

이 그래프는 **SoftwareEngineer를 중심 오케스트레이터(Orchestrator)** 로 두고, 전문화된 두 에이전트(CodeAnalyzer, Editor)와 여러 도구(Tool) 노드들이 협력하는 **멀티 에이전트 워크플로우**다.

---

### 노드 분류

| 노드 | 역할 | 분류 |
|------|------|------|
| `start` | 진입점 | 시스템 |
| `SoftwareEngineer` | 중앙 라우터 / 오케스트레이터 | 에이전트 |
| `CodeAnalyzer` | 코드 분석 전문 에이전트 | 에이전트 |
| `Editor` | 파일 편집 전문 에이전트 | 에이전트 |
| `swe_tool` | SoftwareEngineer 전용 도구 | 도구 |
| `code_analysis_tool` | 코드 분석 도구 | 도구 |
| `code_edit_tool` | 코드 편집 도구 | 도구 |
| `test_tool` | 테스트 실행 도구 | 도구 |
| `end` | 종료점 | 시스템 |

---

### 엣지 흐름 상세

#### 1. 진입 흐름
```
start → SoftwareEngineer
```
- 워크플로우가 시작되면 가장 먼저 `SoftwareEngineer` 노드로 진입한다.
- 이 노드가 전체 태스크를 받아 어떤 액션을 취할지 **라우팅 결정**을 한다.

---

#### 2. SoftwareEngineer → CodeAnalyzer (analyze_code)
```
SoftwareEngineer --[analyze_code]--> CodeAnalyzer
```
- SoftwareEngineer가 코드 분석이 필요하다고 판단하면 `analyze_code` 조건으로 `CodeAnalyzer`에 위임한다.

**CodeAnalyzer 내부 루프:**
```
CodeAnalyzer ↔ code_analysis_tool  (continue)
CodeAnalyzer ↔ code_edit_tool      (continue)
```
- `code_analysis_tool`: 정적 분석, 코드 구조 파악 등을 수행하고 결과를 `CodeAnalyzer`에 반환(`continue`)
- `code_edit_tool`: 분석 결과 기반으로 편집이 필요하면 호출하고 결과를 `CodeAnalyzer`에 반환(`continue`)
- 도구 결과를 받은 후 추가 도구 호출이 필요하면 루프가 반복된다.

**완료 시:**
```
CodeAnalyzer --[done]--> SoftwareEngineer
```
- 분석 완료 후 `done` 신호와 함께 결과를 SoftwareEngineer에 반환한다.

---

#### 3. SoftwareEngineer → Editor (edit_file)
```
SoftwareEngineer --[edit_file]--> Editor
```
- SoftwareEngineer가 파일 편집이 필요하다고 판단하면 `edit_file` 조건으로 `Editor`에 위임한다.

**Editor 내부 루프:**
```
Editor ↔ code_edit_tool  (continue)
Editor ↔ test_tool        (continue)
```
- `code_edit_tool`: 실제 파일 수정을 수행하고 결과를 `Editor`에 반환(`continue`)
- `test_tool`: 편집 후 테스트를 실행하고 결과를 `Editor`에 반환(`continue`)
- 테스트 실패 시 다시 `code_edit_tool`을 호출하는 **수정-테스트 반복 루프**가 가능하다.

**완료 시:**
```
Editor --[done]--> SoftwareEngineer
```
- 편집 및 테스트 완료 후 `done` 신호와 함께 결과를 SoftwareEngineer에 반환한다.

---

#### 4. SoftwareEngineer → swe_tool (직접 도구 호출)
```
SoftwareEngineer → swe_tool --[continue]--> SoftwareEngineer
```
- SoftwareEngineer가 하위 에이전트 없이 **직접 도구를 사용**해야 할 때 `swe_tool`을 호출한다.
- 도구 실행 후 `continue` 신호로 SoftwareEngineer에게 결과를 반환하고, 오케스트레이터가 다음 행동을 다시 결정한다.

---

#### 5. SoftwareEngineer → end (종료)
```
SoftwareEngineer → end
```
- 모든 태스크가 완료되었다고 판단되면 `end` 노드로 라우팅하여 워크플로우를 종료한다.

---

### 전체 실행 흐름 예시

```
start
  └─→ SoftwareEngineer (태스크 수신 및 계획)
        ├─[analyze_code]→ CodeAnalyzer
        │                   ├─→ code_analysis_tool → (continue) → CodeAnalyzer
        │                   ├─→ code_edit_tool     → (continue) → CodeAnalyzer
        │                   └─[done]→ SoftwareEngineer
        │
        ├─[edit_file]→ Editor
        │               ├─→ code_edit_tool → (continue) → Editor
        │               ├─→ test_tool      → (continue) → Editor
        │               └─[done]→ SoftwareEngineer
        │
        ├─→ swe_tool → (continue) → SoftwareEngineer
        │
        └─→ end
```

---

### 핵심 설계 패턴

1. **Supervisor 패턴**: `SoftwareEngineer`가 모든 라우팅 결정을 내리는 중앙 오케스트레이터 역할
2. **ReAct 루프**: 각 에이전트(CodeAnalyzer, Editor)가 도구를 반복 호출하며 결과를 누적
3. **공유 도구**: `code_edit_tool`은 `CodeAnalyzer`와 `Editor` **양쪽에서 공유**됨
4. **조건부 엣지(Conditional Edge)**: 점선(dashed) 화살표가 조건에 따른 동적 라우팅을 나타냄
