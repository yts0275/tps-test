## LangGraph 워크플로우 상세 흐름

---

### 노드 구성 개요

**에이전트 노드 (보라색 테두리)**
| 노드 | 역할 |
|------|------|
| `SoftwareEngineer` | 중앙 오케스트레이터 — 전체 작업을 조율하고 하위 에이전트에 위임 |
| `CodeAnalyzer` | 코드 분석 전담 에이전트 |
| `Editor` | 코드 편집 및 테스트 전담 에이전트 |

**도구 노드 (연한 보라색)**
| 노드 | 역할 |
|------|------|
| `code_analysis_tool` | 정적 분석, 코드 구조 파악 |
| `code_edit_tool` | 파일 읽기/쓰기 등 실제 편집 |
| `test_tool` | 테스트 실행 및 결과 수집 |
| `swe_tool` | SoftwareEngineer가 직접 사용하는 범용 도구 |

---

### 전체 흐름

```
start
  └─► SoftwareEngineer ──────────────────────────────────► end
         │         ▲                      ▲
         │(analyze_code)  (done)    (done/continue)
         │         │                      │
         ▼         │            ┌─────────┘
      CodeAnalyzer─┘            │
         │   ▲                  │
         │   │(continue)    Editor
         │   │                  │   ▲
         ▼   │               ▼   │(continue)
   code_analysis_tool   code_edit_tool / test_tool
   (+ code_edit_tool?)
         
SoftwareEngineer ──► swe_tool ──(continue)──► SoftwareEngineer
```

---

### 단계별 상세 흐름

#### 1. `start` → `SoftwareEngineer`
워크플로우가 시작되면 **SoftwareEngineer** 노드가 최초 실행된다. 이 노드는 사용자 요청을 받아 작업 성격을 파악하고, **Conditional Edge**를 통해 다음 중 하나로 라우팅한다.

---

#### 2. `SoftwareEngineer`의 분기 (Conditional Edge)

| 조건 | 다음 노드 | 설명 |
|------|-----------|------|
| `analyze_code` | `CodeAnalyzer` | 코드 이해, 구조 파악, 버그 탐색이 필요할 때 |
| `edit_file` | `Editor` | 실제 파일 수정 또는 테스트 실행이 필요할 때 |
| _(직접 도구 호출)_ | `swe_tool` | 분석/편집 없이 범용 도구를 직접 쓸 때 |
| _(작업 완료)_ | `end` | 모든 작업이 끝났다고 판단할 때 |

---

#### 3. `CodeAnalyzer` 루프

```
CodeAnalyzer
  ├──► code_analysis_tool  ──(continue)──► CodeAnalyzer  (반복)
  ├──► code_edit_tool       ──(continue)──► CodeAnalyzer  (필요 시)
  └──(done)──► SoftwareEngineer
```

- **`code_analysis_tool`** 을 호출해 코드를 분석한다.
- 결과를 받으면 `continue` 엣지로 **자기 자신(CodeAnalyzer)으로 루프백**하여 추가 분석을 이어간다.
- 필요하다면 `code_edit_tool`도 호출 가능하다(분석 중 간단한 수정).
- 분석이 충분히 완료되면 `done` 엣지로 **SoftwareEngineer에게 결과를 반환**한다.

---

#### 4. `Editor` 루프

```
Editor
  ├──► code_edit_tool  ──(continue)──► Editor  (반복)
  ├──► test_tool       ──(continue)──► Editor  (반복)
  └──(done)──► SoftwareEngineer
```

- **`code_edit_tool`** 로 파일을 수정하고, **`test_tool`** 로 테스트를 실행한다.
- 도구 결과가 돌아오면 `continue` 엣지로 **Editor가 루프**하며 수정 → 테스트 → 재수정 사이클을 반복한다.
- 편집 및 테스트가 완료되면 `done` 엣지로 **SoftwareEngineer에게 결과를 반환**한다.

---

#### 5. `swe_tool` → `continue` → `SoftwareEngineer`

- **SoftwareEngineer**가 `CodeAnalyzer`나 `Editor`를 거치지 않고 **직접 도구(`swe_tool`)를 호출**하는 경로다.
- 도구 실행 후 `continue` 엣지로 **SoftwareEngineer로 돌아와** 결과를 바탕으로 다음 판단을 이어간다.

---

#### 6. 종료

**SoftwareEngineer**가 작업이 완전히 완료됐다고 판단하면 `end` 노드로 라우팅하여 워크플로우가 종료된다.

---

### 핵심 패턴 요약

| 패턴 | 설명 |
|------|------|
| **Hub-and-Spoke** | `SoftwareEngineer`가 허브 역할. 모든 하위 에이전트가 완료 후 다시 허브로 복귀 |
| **ReAct 루프** | `CodeAnalyzer`, `Editor` 모두 도구 호출 → 결과 수신 → 재실행의 ReAct 패턴 |
| **계층적 위임** | 최상위 오케스트레이터가 전문 에이전트에 위임하고, 전문 에이전트가 도구를 직접 운용 |
| **조건부 종료** | 각 에이전트는 `continue`(반복) vs `done`(반환) 분기로 루프 종료 시점을 자율 결정 |
