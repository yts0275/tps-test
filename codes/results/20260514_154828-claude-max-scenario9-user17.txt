## LangGraph Workflow 상세 흐름 분석

### 노드 구성

| 노드 | 역할 | 타입 |
|------|------|------|
| `start` | 워크플로우 진입점 | Entry |
| `SoftwareEngineer` | 중앙 오케스트레이터 | Agent |
| `CodeAnalyzer` | 코드 분석 전담 | Agent |
| `Editor` | 파일 편집 전담 | Agent |
| `swe_tool` | 범용 SWE 도구 | Tool Node |
| `code_analysis_tool` | 코드 분석 도구 | Tool Node |
| `code_edit_tool` | 코드 편집 도구 | Tool Node |
| `test_tool` | 테스트 실행 도구 | Tool Node |
| `end` | 워크플로우 종료 | Terminal |

---

### 엣지 표기 규칙

- **실선 화살표**: 에이전트 간 직접 전환 (조건부 라우팅 포함)
- **점선 화살표**: 에이전트 ↔ 도구 간 호출/응답 (Tool Call 사이클)

---

### 전체 흐름

#### 1. 진입 (start → SoftwareEngineer)

```
start ──► SoftwareEngineer
```

워크플로우가 시작되면 무조건 `SoftwareEngineer`로 진입한다. 이 노드가 전체 작업의 **중앙 오케스트레이터** 역할을 한다.

---

#### 2. SoftwareEngineer의 라우팅 결정

`SoftwareEngineer`는 현재 상태(State)를 분석하여 4가지 경로 중 하나로 분기한다.

```
SoftwareEngineer
  ├──(analyze_code)──► CodeAnalyzer   # 코드 분석이 필요한 경우
  ├──(edit_file)─────► Editor         # 파일 수정이 필요한 경우
  ├──────────────────► swe_tool       # 직접 도구 사용이 필요한 경우
  └──────────────────► end            # 작업 완료 시
```

- `analyze_code` : 현재 코드를 이해하거나 파악할 필요가 있을 때
- `edit_file` : 파일을 직접 편집해야 할 때
- `swe_tool` : 분석/편집 외의 SWE 작업이 필요할 때 (예: repo 탐색 등)
- `end` : 모든 작업이 완료된 것으로 판단될 때

---

#### 3. CodeAnalyzer 서브루프

```
CodeAnalyzer ◄──(점선)──► code_analysis_tool
     │
     ├──(done)──────────► SoftwareEngineer   # 분석 완료, 결과 반환
     └──(continue)──────► Editor             # 분석 후 바로 편집 필요
```

- `CodeAnalyzer`는 분석 수행 중 `code_analysis_tool`을 반복 호출할 수 있다 (점선 루프).
- 분석이 완료되면 (`done`) 결과를 `SoftwareEngineer`에게 반환한다.
- 분석 결과를 바탕으로 즉시 편집이 필요한 경우 (`continue`) `Editor`로 직접 전환한다.

---

#### 4. Editor 서브루프

```
Editor ◄──(점선)──► code_edit_tool
Editor ◄──(점선)──► test_tool
  │
  ├──(done)──────────► SoftwareEngineer   # 편집 완료, 결과 반환
  └──(continue)──────► CodeAnalyzer       # 편집 후 재검증 필요
```

- `Editor`는 편집 작업 중 `code_edit_tool` 또는 `test_tool`을 반복 호출할 수 있다.
- `test_tool` 실행 결과에 따라 수정 → 테스트 사이클을 반복할 수 있다.
- 편집이 완료되면 (`done`) `SoftwareEngineer`에게 반환한다.
- 편집 후 코드를 다시 분석해야 하면 (`continue`) `CodeAnalyzer`로 직접 전환한다.

---

#### 5. swe_tool 처리

```
swe_tool ──(continue)──► SoftwareEngineer
```

- `swe_tool` 실행 후에는 반드시 `SoftwareEngineer`로 복귀한다.
- `SoftwareEngineer`가 결과를 보고 다음 행동을 재결정한다.

---

### 핵심 루프 패턴 요약

```
SoftwareEngineer
    │
    ▼
CodeAnalyzer ──(continue)──► Editor ──(continue)──► CodeAnalyzer
    │                            │
  (done)                       (done)
    └──────────────┬────────────┘
                   ▼
           SoftwareEngineer
                   │
             (작업 완료 시)
                   ▼
                 end
```

**CodeAnalyzer ↔ Editor** 간의 `continue` 양방향 루프가 핵심으로, 분석 → 편집 → 재분석 → 재편집 사이클을 `SoftwareEngineer`를 거치지 않고 직접 수행할 수 있어 반복 작업의 효율성을 높인다.

---

### 전체 실행 시나리오 예시

1. `start` → `SoftwareEngineer` : 작업 지시 수신
2. `SoftwareEngineer` → `CodeAnalyzer` : 기존 코드 파악 지시
3. `CodeAnalyzer` ↔ `code_analysis_tool` : 코드 분석 수행 (반복 가능)
4. `CodeAnalyzer` → `Editor` : 분석 완료, 편집 필요 판단 (`continue`)
5. `Editor` ↔ `code_edit_tool` : 코드 수정
6. `Editor` ↔ `test_tool` : 테스트 실행
7. `Editor` → `CodeAnalyzer` : 테스트 실패, 재분석 필요 (`continue`)
8. `CodeAnalyzer` → `Editor` : 재분석 완료 (`continue`)
9. `Editor` → `SoftwareEngineer` : 모든 편집/테스트 완료 (`done`)
10. `SoftwareEngineer` → `end` : 전체 작업 완료
