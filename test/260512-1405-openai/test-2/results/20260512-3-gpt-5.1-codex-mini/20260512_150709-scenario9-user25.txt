이 Workflow는 전체적으로 SoftwareEngineer를 중심으로 여러 도구 노드와 상호작용하는 흐름으로 구성되어 있습니다. 각 노드 간 연결을 순차적으로 살펴보면 다음과 같습니다.

1. **start → SoftwareEngineer**  
   흐름은 `start` 노드에서 시작하여 곧바로 `SoftwareEngineer` 노드로 진입합니다. 즉, 작업은 소프트웨어 엔지니어가 중심 역할을 맡는 상태에서 시작됩니다.

2. **SoftwareEngineer → CodeAnalyzer (레이블: analyze_code)**  
   엔지니어는 코드 분석을 위해 `CodeAnalyzer` 노드로 흐름을 넘깁니다. 이 과정을 통해 어떤 분석 작업이 수행됨을 나타냅니다.

3. **CodeAnalyzer → code_analysis_tool**  
   `CodeAnalyzer` 내부에서는 실제 분석을 수행하는 `code_analysis_tool`로 작업이 전달됩니다. 이는 분석기 노드가 실제 도구를 통해 작업을 처리한다는 의미입니다.

4. **CodeAnalyzer → SoftwareEngineer (레이블: done)**  
   분석이 완료되면 `done` 레이블과 함께 `SoftwareEngineer`로 다시 돌아갑니다. 즉, 분석 완료를 엔지니어에게 보고하는 흐름입니다.

5. **SoftwareEngineer → Editor (레이블: edit_file)**  
   수정 작업이 필요할 경우 엔지니어는 `edit_file` 흐름을 타고 에디터 노드로 이동합니다.

6. **Editor → code_edit_tool**  
   에디터에서는 실제 편집을 수행하기 위해 `code_edit_tool` 도구를 호출합니다. 이 부분은 편집기 노드 내부 프로세스가 도구를 사용하는 구조입니다.

7. **Editor → test_tool**  
   편집 과정 이후에는 `test_tool`을 이용해 테스트를 수행하는 흐름도 그려져 있습니다. 즉, 에디터는 편집된 코드를 테스트하는 도구로 연계됩니다.

8. **Editor → SoftwareEngineer (레이블: done)**  
   에디터 작업이 끝나면 `done` 레이블로 다시 `SoftwareEngineer`에게 돌아옵니다. 편집 완료 상태를 알리는 흐름입니다.

9. **SoftwareEngineer → swe_tool (레이블: continue)**  
   작업이 지속될 경우 엔지니어는 `swe_tool`로 흐름을 이어갑니다. 이는 추가적인 소프트웨어 엔지니어링 도구 사용을 나타냅니다.

10. **swe_tool → end**  
    `swe_tool`을 다 사용한 후에는 `end` 노드로 흐름이 연결되어 작업이 종료됩니다. 이 흐름은 `continue`와 이어지며 전체 프로세스의 마무리를 표현합니다.

요약하면, 엔지니어는 시작점부터 코드 분석 → 편집 → 테스트 → 추가 도구 사용의 순서로 다양한 도구와 상호작용하며, 각 작업이 완료될 때마다 다시 엔지니어 노드로 돌아와 다음 단계를 결정하는 방식입니다. 각 도구 노드는 실제 처리(analysis, edit, test)에 해당하는 하위 도구(code_analysis_tool, code_edit_tool, test_tool)를 호출하고, 완료 시 `done` 흐름을 통해 엔지니어에게 상태를 반환합니다. 이러한 반복적인 루프를 통해 작업이 진행되고, 최종적으로 `swe_tool` 사용 이후 `end`로 종료됩니다.
