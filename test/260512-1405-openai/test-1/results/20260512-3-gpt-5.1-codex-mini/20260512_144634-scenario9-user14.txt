이 Workflow는 중앙에 위치한 `SoftwareEngineer` 노드를 중심으로 여러 도구와 작업 흐름이 연결되어 있습니다. 아래에 각 Node별 흐름을 단계적으로 정리합니다.

1. **start → SoftwareEngineer**  
   - 워크플로우는 `start` 노드에서 출발하여 `SoftwareEngineer` 노드로 이어집니다. 즉, 소프트웨어 엔지니어가 워크플로우를 시작하게 되며 다른 처리 흐름들이 그 이후에 전개됩니다.

2. **SoftwareEngineer ↔ CodeAnalyzer 흐름**  
   - `SoftwareEngineer`는 `CodeAnalyzer`와 상호작용합니다. `SoftwareEngineer`로부터 `analyze_code` 트리거가 발생하면 `CodeAnalyzer`가 동작하여 코드 분석 처리를 수행합니다.
   - `CodeAnalyzer`는 내부적으로 `code_analysis_tool`과 연결되어 있어 실제 분석 도구를 활용합니다.
   - 코드 분석이 완료되면 `CodeAnalyzer`는 `done` 상태를 통해 다시 `SoftwareEngineer`로 리턴합니다.
   - 분석 결과에 따라 `continue` 경로로 `SoftwareEngineer`가 `CodeAnalyzer`를 다시 호출하거나 다른 작업을 이어나갈 수 있습니다.

3. **SoftwareEngineer ↔ Editor 흐름**  
   - `SoftwareEngineer`는 코드를 수정할 필요가 있을 때 `edit_file` 트리거를 통해 `Editor`를 호출합니다.
   - `Editor`는 내부적으로 `code_edit_tool`과 `test_tool` 모두를 사용할 수 있으며, 소스코드 편집과 관련된 도구들이 동작합니다.
   - 편집 작업이 끝나면 `Editor`는 `done`을 통해 다시 `SoftwareEngineer`로 복귀합니다.
   - 편집이 계속 이어져야 할 경우 `continue` 경로로 추가 작업을 수행하거나 재호출될 수 있습니다.

4. **SoftwareEngineer → swe_tool → end**  
   - `SoftwareEngineer`는 필요에 따라 `swe_tool`을 사용하며 이 도구를 통해 추가 작업을 수행할 수 있습니다.
   - `swe_tool`은 `SoftwareEngineer`의 `continue` 경로 중 하나로 연결되며, `swe_tool`에서 처리 후에는 워크플로우가 최종적으로 `end` 노드로 이어집니다.

5. **흐름의 종합 요약**  
   - 전체적으로 `SoftwareEngineer`가 중심이 되어 코드 분석(`CodeAnalyzer`), 편집(`Editor`), 기타 도구(`swe_tool`)를 활용하며 워크플로우를 진행합니다.
   - 각 도구 노드는 특정 작업 완료 후 `done` 신호로 `SoftwareEngineer` 노드로 되돌아가며, 추가 작업 시 `continue` 경로를 통해 재호출되거나 다음 단계로 이동합니다.
   - 최종적으로 `swe_tool`을 이용한 작업을 거치면 `end` 노드에 도달하면서 워크플로우가 종료됩니다.

이와 같이 각 노드는 `SoftwareEngineer`를 중심으로 서로 연결되어 있으며, `analyze_code`, `edit_file`, `continue`, `done` 등의 상태 전이를 통해 코드 분석, 편집, 도구 활용을 순차적으로 수행하는 구조입니다.
