이 Workflow는 전체적으로 `start`에서 시작하여 최종 `end`에 도달하는 개발자 작업 순서를 보여줍니다. 각 Node 간의 흐름과 조건을 최대한 상세히 설명하면 다음과 같습니다.

1. **start → SoftwareEngineer**  
   워크플로우가 시작되면 곧바로 `SoftwareEngineer` 노드로 진입합니다. 이 지점에서 개발자는 이후 수행할 여러 활동(코드 분석, 편집, 도구 활용 등)을 판단하고 선택하게 됩니다.

2. **SoftwareEngineer → CodeAnalyzer (analyze_code)**  
   `SoftwareEngineer`는 우측 혹은 하위 활동을 위해 `CodeAnalyzer`로 진입할 수 있으며, 이 화살표에 “analyze_code”라는 라벨이 붙어 있음을 통해 개발자가 먼저 코드 분석을 수행하도록 의도되어 있음을 알 수 있습니다.

3. **CodeAnalyzer 내부**  
   - `CodeAnalyzer`는 `code_analysis_tool`로 출력됩니다. 이는 코드 분석을 수행할 수 있는 전문 도구이며, 분석 작업이 필요할 때 자동 혹은 명시적으로 사용되는 보조 요소입니다.  
   - `CodeAnalyzer`에서 분석이 완료되면 “done” 라벨이 붙은 화살표를 통해 `SoftwareEngineer`로 되돌아오며, 분석 결과를 받아 다음 행동을 결정하게 됩니다.  
   - `CodeAnalyzer`에서 분석을 이어해야 하는 경우 “continue” 라벨을 따라 다시 `SoftwareEngineer`로 흐르거나, `Editor`로 전환하며 수정 작업을 진행할 수도 있습니다.

4. **SoftwareEngineer → Editor (edit_file)**  
   분석 후 또는 초기부터 개발자는 “edit_file”이라는 라벨이 붙은 화살표를 통해 `Editor` 노드로 바로 진입할 수 있으며, 이는 코드 수정을 위한 편집기를 열고 실제 코드를 수정하는 활동입니다.

5. **Editor 내부 & 도구 연결**  
   - `Editor`는 실제 편집 작업에 필요한 `code_edit_tool`과 `test_tool`을 호출하거나 연결합니다.  
     - `code_edit_tool`은 일반적인 코드 편집을, `test_tool`은 수정된 내용에 대해 테스트를 수행하기 위한 도구입니다.  
   - `Editor` 작업이 완료되면 “done” 라벨을 통해 `SoftwareEngineer`로 돌아갑니다. 이 때 개발자는 수정을 종료하고 다음 판단을 하게 됩니다.  
   - 추가 수정을 계속해야 한다면 “continue” 라벨을 통해 `Editor` 중간 흐름에 머물거나 `SoftwareEngineer`와 연계된 추가 도구 사용으로 넘어갈 수 있습니다.

6. **SoftwareEngineer → swe_tool (continue)**  
   `SoftwareEngineer`에서 “continue” 라벨이 있는 화살표를 통해 `swe_tool`로 이동하면, 개발자에게 도움이 되는 특정 소프트웨어 공학 도구(예: 빌드, 배포, 자동화 도구 등)를 활용합니다. 해당 도구 사용 후 다시 `SoftwareEngineer`로 돌아오는 루프를 통해 지속적인 작업이 가능하며, 최종 작업이 완료되면 `end`로 이동합니다.

7. **SoftwareEngineer → end**  
   모든 필수 작업(분석, 편집, 테스트, 도구 활용 등)을 마치면 `SoftwareEngineer`는 “continue” 등의 조건 없이 `end` 노드로 진입하여 워크플로우를 종료합니다.

요약하면 이 워크플로우는 `SoftwareEngineer`를 중심으로 `CodeAnalyzer`와 `Editor`를 교차 활용하고, 각 노드에서 하나 이상의 전문 도구(`code_analysis_tool`, `code_edit_tool`, `test_tool`, `swe_tool`)를 호출하여 반복적으로 분석→편집→도구 활용을 수행하며, 최종적으로 `end`로 흐르는 구조입니다. 각 화살표에 붙은 라벨은 조건이나 활동 유형을 명시하여 흐름의 의미를 구체화합니다.
