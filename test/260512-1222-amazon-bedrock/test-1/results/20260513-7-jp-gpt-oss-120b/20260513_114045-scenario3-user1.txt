아래는 **Python** 으로 구현한 퀵소트(Quick Sort) 예제입니다.  
각 줄마다 한글 주석을 달아 어떤 작업을 하는지 자세히 설명했으니, 코드를 따라가며 이해하면 됩니다.

```python
# 퀵소트 함수 정의
def quick_sort(arr):
    """
    재귀적으로 배열을 정렬하는 퀵소트 함수
    - arr : 정렬하고자 하는 리스트(또는 배열)
    - 반환값 : 정렬된 새로운 리스트
    """
    # 1. 정렬할 요소가 0개 또는 1개이면 이미 정렬된 상태이므로 그대로 반환
    if len(arr) <= 1:
        return arr

    # 2. 피벗(pivot) 선택
    #    여기서는 리스트의 가운데 요소를 피벗으로 잡는다.
    #    (다른 선택 방법: 첫 번째/마지막 요소, 랜덤 선택 등)
    pivot = arr[len(arr) // 2]

    # 3. 피벗을 기준으로 왼쪽(작은 값), 가운데(피벗과 같은 값), 오른쪽(큰 값) 리스트로 분리
    left = []   # 피벗보다 작은 값들을 담는 리스트
    middle = [] # 피벗과 같은 값들을 담는 리스트 (피벗 자체도 여기 포함)
    right = []  # 피벗보다 큰 값들을 담는 리스트

    # 4. 입력 리스트 전체를 순회하면서 각각을 적절한 리스트에 넣는다.
    for x in arr:
        if x < pivot:           # 피벗보다 작으면 left에
            left.append(x)
        elif x > pivot:         # 피벗보다 크면 right에
            right.append(x)
        else:                   # 피벗과 같으면 middle에
            middle.append(x)

    # 5. left와 right에 대해 각각 재귀적으로 quick_sort 를 호출해 정렬한다.
    #    middle는 이미 피벗과 같은 값들로 정렬이 필요 없으므로 그대로 사용한다.
    sorted_left = quick_sort(left)     # 왼쪽 부분 정렬
    sorted_right = quick_sort(right)   # 오른쪽 부분 정렬

    # 6. 정렬된 left, middle, right 를 차례대로 합쳐 하나의 리스트로 만든다.
    #    이것이 최종적으로 정렬된 결과가 된다.
    return sorted_left + middle + sorted_right


# ----------------------------------------------------------------------
# 사용 예시
if __name__ == "__main__":
    # 정렬되지 않은 리스트 선언
    unsorted = [33, 10, 55, 71, 29, 3, 18, 90, 42]

    # 퀵소트 함수에 리스트를 넘겨 정렬 수행
    sorted_arr = quick_sort(unsorted)

    # 결과 출력
    print("원본 리스트 :", unsorted)
    print("정렬된 리스트:", sorted_arr)
```

### 코드 흐름 요약
1. **베이스 케이스** – 요소가 0개 또는 1개이면 그대로 반환.  
2. **피벗 선정** – 여기서는 중앙값을 피벗으로 사용. (다른 전략으로 교체 가능)  
3. **분할(partition)** – 리스트를 `< 피벗`, `= 피벗`, `> 피벗` 세 그룹으로 나눈다.  
4. **재귀 호출** – `left`와 `right`에 대해 다시 `quick_sort`를 호출해 각각 정렬한다.  
5. **합치기(concatenation)** – 정렬된 `left`, `middle`, `right`를 순서대로 이어서 최종 결과를 만든다.

### 주요 포인트
- **시간 복잡도**  
  - 평균·최선 : `O(N log N)` (피벗이 균등하게 나눠질 때)  
  - 최악 : `O(N²)` (이미 정렬된 배열에 대해 첫/마지막 요소를 피벗으로 선택할 경우)  
- **공간 복잡도**  
  - 재귀 호출 깊이와 각각의 `left/right/middle` 리스트 때문에 `O(N)` 정도의 추가 메모리가 필요합니다.  
- **피벗 선택**을 바꾸면 최악 상황을 완화할 수 있습니다. 예를 들어 `random.choice(arr)` 로 무작위 피벗을 고르면 기대 시간 복잡도가 평균적으로 유지됩니다.

필요에 따라 피벗 선택 방법을 바꾸거나, **in‑place**(제자리) 퀵소트 구현으로 메모리 사용량을 줄일 수도 있습니다. 궁금한 부분이 있으면 언제든 질문해 주세요! 🚀
